Запуск ярлыком, без консоли и браузера

Приложение открывается стартовым экраном: недавние репозитории и открытие папки системным диалогом. Выбранная папка может быть любой внутри репозитория — корень openspec/ ищется вверх по дереву, как у CLI.

Каждый репозиторий открывается в своём окне. Повторное открытие того же репозитория переводит фокус на уже открытое окно. Запуск ярлыком при работающем приложении не создаёт второй экземпляр.

Потребители считаются по зависимостям из карты модулей, а не по коду. Если спеки потребителя описывают поведение, которое меняется, добавьте в change дельту в его модуле — change станет сквозным.

Кого заденет change в библиотеке

Граф строится по зависимостям из карты модулей. Change в km/core подсвечивает прямых потребителей и тех, кто зависит от них, — с глубиной, чтобы было видно, откуда пришла зависимость.

Выбор модуля на графе показывает его зависимости, потребителей, активные changes и число спеков. Цикл в карте не ломает граф и показывается ошибкой карты.

Одна спека на сервис — и читается как документ

Разделы берутся из имени требования: Счета / Нумерация счетов. Такой формат CLI принимает, включая дельты и архивацию. А вот заголовки ## внутри требований CLI молча обрывает. IDE находит их и называет, какие требования потерялись.

В обзоре — назначение модуля, счётчики и покрытие. На карточке требования — сценарии по шагам, изменение в активном change, покрытие и связи. Фильтр «без покрытия» оставляет в спеке только то, что не реализовано и не проверено.

Где требование живёт в коде и кто на него опирается

Метка // @spec km/core: Кэш ответов в любом комментарии на любом языке связывает место с требованием. Метка в тесте — это тест требования. Тест, названный по сценарию, засчитывается как «по имени» — отдельно, чтобы не завышать покрытие. Фрагмент кода виден прямо здесь, а кнопками место открывается в IntelliJ IDEA или VS Code на нужной строке.

Ссылки между требованиями — обычные markdown-ссылки, их понимает и GitHub. Обратные ссылки точнее показывают, что заденет change. Расхождения со связями из карты модулей видны сразу.
