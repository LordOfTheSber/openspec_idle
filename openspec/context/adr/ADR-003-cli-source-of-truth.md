# ADR-003: Источник истины — файлы и CLI OpenSpec

## Решение

IDE не хранит своего состояния проекта: читает `openspec/` и спрашивает CLI
`openspec <команда> --json` через единственную обёртку в сервере. Собственный
разбор markdown — только там, где CLI молчит: пункты `tasks.md`, строки
требований для диагностики, frontmatter контекста.

## Почему

CLI — исполняемая спецификация формата. Свой разбор дельт разошёлся бы с ним
при обновлении OpenSpec, и IDE показывала бы не то, что увидит `validate`.

## Последствия

- Цена — запуск процесса на вызов; снимается кэшем и объединением событий
  наблюдателя.
- Всё, что делает IDE, можно повторить из терминала.
- Исключение — журнал метрик в каталоге `.openspec-ide`: это история, а не
  состояние проекта.
