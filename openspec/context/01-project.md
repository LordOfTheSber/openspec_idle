# OpenSpec IDE — общий контекст

Расширение VS Code для работы по методологии OpenSpec: дерево changes и спеков,
замечания валидации в панели «Проблемы», доска фаз, дельты спеков, метрики по
пунктам плана, конструктор собственного процесса, проверка структуры папок,
карта и контроль контекста модулей. Для CI — команда `openspec-ide-check` с
теми же проверками.

## Источник истины

Файлы `openspec/` на диске и CLI `@fission-ai/openspec` 1.13.x. Своей базы
состояния у IDE нет: всё, что она создаёт или меняет, остаётся обычным
OpenSpec-проектом. Исключение — журнал метрик в каталоге `.openspec-ide` (в
`.gitignore`). IDE не вызывает LLM и не запускает агентов: она готовит для них
контекст в `openspec/context/`.

## Устройство

Монорепозиторий npm workspaces, TypeScript strict, Node.js 22+, ESM.

```
core ──► server ──► vscode (бэкенд в процессе расширения)
  │         └─────► check  (openspec-ide-check)
  └────► web ─────► vscode (панель webview)
```

- `core` — чистая модель и правила без Node API: её собирают и сервер, и страница.
- `server` — Fastify-приложение: читает файлы, зовёт CLI и git, отдаёт `/api/*`.
  В расширении маршруты вызываются через `inject()`, без порта; в разработке —
  по HTTP с токеном сессии.
- `web` — React-разделы панели; запросы идут через сменяемый транспорт.
- `vscode` — нативные дерево, диагностика, команды и редакторная помощь; панель
  разделов — webview с интерфейсом `web`.
- `check` — консольная команда поверх встроенного бэкенда для CI и pre-commit.

Требования — основные спеки в [specs](../specs/); незаархивированные changes в
[changes](../changes/) дополняют их (карта контекста, трассировка, пересечения,
помощь в редакторе, проверка в CI). Решения — в [adr](adr/).

## Термины

- **change** — каталог `openspec/changes/<имя>/` с proposal, дельтами спеков,
  design и tasks; **дельта** — секции ADDED/MODIFIED/REMOVED/RENAMED Requirements.
- **capability** (домен) — основной спек `openspec/specs/<путь>/spec.md`.
- **схема** — описание процесса (артефакты и их зависимости), встроенная
  `spec-driven` или собственная в каталоге `openspec/schemas`.
- **модуль контекста** — `openspec/context/modules/<папка>/` с `index.md` и
  `context.md`; связь модуль ↔ домен — многие-ко-многим.
