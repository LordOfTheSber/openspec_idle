# Spec Delta: vscode-extension

## MODIFIED Requirements

### Requirement: Панель разделов

Доска, дельты, метрики, процессы, поиск, структура и контекст ДОЛЖНЫ (SHALL)
открываться в одной панели webview внутри VS Code — командой палитры или из
контекстного меню change в дереве. Панель ДОЛЖНА переиспользоваться: повторный
вызов переключает раздел и выбранный change в уже открытой панели, а не создаёт
новую. Поведение разделов ДОЛЖНО совпадать с прежней web-IDE.

#### Scenario: Метрики из контекстного меню

- **WHEN** пользователь выбирает «Метрики» в контекстном меню change
- **THEN** открывается панель с разделом «Метрики» этого change

#### Scenario: Повторный вызов

- **WHEN** панель уже открыта и пользователь вызывает команду «Доска»
- **THEN** та же панель переключается на доску, вторая панель не появляется

#### Scenario: Карта контекста из палитры

- **WHEN** пользователь вызывает команду «Карта контекста»
- **THEN** открывается панель с разделом «Контекст»

#### Scenario: Изменения на диске

- **WHEN** пользователь или внешний инструмент меняет файлы change, пока открыта панель
- **THEN** открытый раздел перечитывает данные без действий пользователя

## ADDED Requirements

### Requirement: Бэкенд без порта в процессе расширения

Бэкенд IDE ДОЛЖЕН (SHALL) работать в процессе расширения и обслуживать запросы
без сетевого сокета. Расширение НЕ ДОЛЖНО открывать ни одного порта. Все
операции над OpenSpec ДОЛЖНЫ идти через ту же обёртку над CLI, что и раньше, а
при деактивации расширения ДОЛЖНО останавливаться наблюдение за файлами.

#### Scenario: Работа без порта

- **WHEN** расширение активировано в проекте с OpenSpec
- **THEN** запросы разделов обслуживаются бэкендом без открытия TCP-порта

#### Scenario: Закрытие окна VS Code

- **WHEN** окно VS Code закрывается
- **THEN** наблюдатель за файлами останавливается

### Requirement: Канал сообщений панели и событий файлов

Панель ДОЛЖНА (SHALL) общаться с бэкендом только сообщениями webview: запрос с
идентификатором, методом, путём API и телом, и ответ с тем же идентификатором,
кодом и телом. Коды и тела ответов ДОЛЖНЫ совпадать с HTTP-режимом бэкенда,
чтобы разделы не различали транспорт. События бэкенда об изменении файлов
ДОЛЖНЫ доставляться в панель сообщениями того же канала. Сообщение
неизвестного вида ДОЛЖНО отклоняться, а запрос к пути вне `/api/` — получать
отказ.

#### Scenario: Конфликт записи

- **WHEN** панель сохраняет файл, изменившийся на диске после чтения
- **THEN** ответ приходит с кодом 409 и версией с диска, как в HTTP-режиме

#### Scenario: Изменение файлов

- **WHEN** файл в `openspec/` меняется, пока панель открыта
- **THEN** событие об изменении приходит в панель без опроса

#### Scenario: Запрос вне API

- **WHEN** панель присылает запрос к пути `/` или `/etc/passwd`
- **THEN** бэкенд не вызывается, панель получает отказ

### Requirement: Замечания карты контекста в панели «Проблемы»

Расширение ДОЛЖНО (SHALL) показывать замечания карты контекста в панели
«Проблемы»: ошибки — ошибками, предупреждения — предупреждениями, на строке
поля в `index.md` модуля или в ADR, а без строки — на первой строке файла.
Замечания ДОЛЖНЫ обновляться при активации и при изменении файлов.

#### Scenario: Неописанный модуль в зависимостях

- **WHEN** `index.md` модуля перечисляет в `depends_on` неописанный модуль `sds-router`
- **THEN** в панели «Проблемы» ошибка на строке поля `depends_on` этого `index.md`

#### Scenario: Исправление

- **WHEN** пользователь описывает модуль `sds-router` и сохраняет файлы
- **THEN** ошибка исчезает из панели «Проблемы» без команды пользователя

## REMOVED Requirements

### Requirement: Бэкенд внутри процесса расширения

**Reason**: Процессов агента больше нет; требование заменено «Бэкенд без порта в процессе расширения».
**Migration**: Не требуется.

### Requirement: Канал сообщений панели

**Reason**: Событий хода запуска агента больше нет; требование заменено «Канал сообщений панели и событий файлов».
**Migration**: Не требуется.
