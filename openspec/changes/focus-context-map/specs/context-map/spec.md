# Spec Delta: context-map

## Purpose

Описывает контекст проекта для людей и агентов: модули, их связи с доменами
(спеками OpenSpec) и между собой, решения ADR — и показывает эти связи
графически, проверяя, что ссылки указывают на существующее.

## ADDED Requirements

### Requirement: Модель контекста модулей

Система ДОЛЖНА (SHALL) читать контекст проекта из `openspec/context/`: общие
файлы `openspec/context/*.md`, модули — папки `openspec/context/modules/<папка>/`
с файлами `index.md` и `context.md`, ADR — файлы `openspec/context/adr/**/*.md`.
Frontmatter `index.md` ДОЛЖЕН поддерживать поля `module` (идентификатор, по
умолчанию имя папки), `description`, `domains`, `code_paths` и `depends_on`.
Домен ДОЛЖЕН соответствовать спеке `openspec/specs/<путь>/spec.md`. Связь модуля
с доменами ДОЛЖНА быть многие-ко-многим: у модуля несколько доменов, домен
относится к нескольким модулям.

#### Scenario: Домен у нескольких модулей

- **WHEN** модули `sds-master` и `sds-impl` оба перечисляют домен `replication` в `domains`
- **THEN** у домена `replication` на карте два модуля
- **AND** у модуля `sds-master` все его домены

#### Scenario: Идентификатор модуля отличается от папки

- **WHEN** в `openspec/context/modules/master/index.md` задано `module: sds-master`
- **THEN** модуль на карте называется `sds-master`
- **AND** ссылки `depends_on` других модулей на `sds-master` считаются описанными

#### Scenario: ADR связан с модулями и доменами

- **WHEN** ADR в `openspec/context/adr/` перечисляет в frontmatter `modules: [sds-master]` и `domains: [replication]`
- **THEN** на карте ADR связан с модулем `sds-master` и доменом `replication`
- **AND** заголовок ADR берётся из поля `title`, иначе из заголовка `#` файла

### Requirement: Проверка связей контекста

Система ДОЛЖНА (SHALL) сообщать замечания к контексту с файлом и строкой поля:
ошибки — неизвестный домен, неописанный модуль в `depends_on` или в ADR,
зависимость модуля от себя, цикл зависимостей, дубль идентификатора модуля,
модуль без `index.md`, frontmatter, который не разбирается или не содержит
полей, поле неверного типа; предупреждения — модуль без `context.md`,
отсутствующий путь кода, домен, не относящийся ни к одному модулю. Проверка НЕ
ДОЛЖНА менять файлы проекта.

#### Scenario: Опечатка в имени домена

- **WHEN** модуль перечисляет в `domains` значение `sesion-lifecycle`, а спеки `openspec/specs/sesion-lifecycle/spec.md` нет
- **THEN** сообщается ошибка «домен не найден» со строкой поля `domains` в `index.md`
- **AND** домен показан на карте с отметкой «не найден»

#### Scenario: Неописанный модуль в зависимостях

- **WHEN** модуль перечисляет в `depends_on` модуль `sds-router`, которого нет среди модулей
- **THEN** сообщается ошибка со строкой поля `depends_on`

#### Scenario: Цикл зависимостей

- **WHEN** модуль `a` зависит от `b`, `b` от `c`, а `c` от `a`
- **THEN** каждый из трёх модулей получает замечание о цикле
- **AND** рёбра цикла выделены на графе

#### Scenario: Домен без модуля

- **WHEN** модули описаны, а спеку `cm-cluster-api` не перечисляет ни один из них
- **THEN** сообщается предупреждение о домене, не относящемся ни к одному модулю

#### Scenario: Путь кода по шаблону

- **WHEN** в `code_paths` указан `sds-master/src/**/*.java`, а папка `sds-master/src` существует
- **THEN** замечания о пути кода нет

### Requirement: Набор контекста модуля

Система ДОЛЖНА (SHALL) собирать для модуля упорядоченный список файлов
контекста: общий контекст, `context.md` модуля и транзитивно всех модулей из
его `depends_on`, спеки их доменов и ADR, ссылающиеся на эти модули. Каждый
файл ДОЛЖЕН входить в список один раз, цикл зависимостей НЕ ДОЛЖЕН мешать
сборке.

#### Scenario: Зависимости попадают в контекст

- **WHEN** модуль `sds-master` зависит от `sds-impl`
- **THEN** в наборе контекста `sds-master` есть `context.md` обоих модулей и спеки доменов обоих модулей

#### Scenario: Копирование путей

- **WHEN** пользователь нажимает «Копировать пути» в карточке модуля
- **THEN** в буфер обмена попадают пути набора по одному в строке с префиксом `@`

### Requirement: Раздел «Контекст»

Панель ДОЛЖНА (SHALL) иметь раздел «Контекст» с двумя видами: граф — колонки
ADR, модулей и доменов со связями между ними и дугами `depends_on`, и матрица
модули × домены. Выбор узла ДОЛЖЕН подсвечивать его связи и показывать
карточку: описание, файлы, домены, зависимости, зависимые модули, ADR, пути
кода и набор контекста. Раздел ДОЛЖЕН показывать замечания с переходом к узлу
на карте и к строке файла и перечитывать карту при изменении файлов. Если
модулей и ADR нет, раздел ДОЛЖЕН показывать пример `index.md`.

#### Scenario: Связи выбранного домена

- **WHEN** пользователь выбирает на графе домен `replication`
- **THEN** подсвечиваются связи домена с модулями `sds-master` и `sds-impl`
- **AND** карточка перечисляет оба модуля и ADR домена

#### Scenario: Матрица

- **WHEN** пользователь переключается на матрицу
- **THEN** на пересечении модуля и домена стоит отметка, если модуль перечисляет домен
- **AND** под матрицей для каждого домена показано число модулей

#### Scenario: Правка index.md

- **WHEN** в `index.md` модуля добавлен домен, пока раздел открыт
- **THEN** новая связь появляется на графе и в матрице без действий пользователя
