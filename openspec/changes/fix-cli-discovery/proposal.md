# Change: поиск CLI OpenSpec вне PATH редактора

## Why

На Windows расширение сообщало «Не найден CLI OpenSpec», хотя `openspec`
работал в терминале Git Bash. VS Code берёт PATH при запуске: CLI,
установленный глобально после запуска редактора, или путь, который добавляет
`.bashrc` Git Bash либо менеджер версий Node, процессу редактора не виден. Ни
указать путь к CLI, ни понять из сообщения, что делать, было нельзя, а кнопка
«Обновить» CLI заново не искала.

## What Changes

- Поиск CLI дополнен каталогами глобальной установки npm: префикс npm,
  `%APPDATA%\npm`, nvm-windows, Volta, fnm; на POSIX — `~/.npm-global/bin`,
  `/usr/local/bin` и подобные.
- Явный путь к CLI: настройка VS Code `openspec.cliPath` и переменная
  окружения `OPENSPEC_CLI`. Принимаются файл, каталог, путь в кавычках, `~`,
  путь Git Bash вида `/c/Users/…` и имя без расширения — к нему подставляются
  расширения из PATHEXT. Неверный явный путь не подменяется найденным в другом
  месте.
- Уведомление «нет CLI» объясняет, почему CLI из терминала может быть не виден,
  и называет настройку; в VS Code — кнопка «Указать путь к CLI», подсказка в
  дереве и строке состояния, в панели — список просмотренных путей.
- Изменение настройки перезапускает бэкенд; «Обновить» при отсутствии CLI ищет
  его заново.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `ide-runtime` — порядок поиска CLI и явный путь к нему.
- `vscode-extension` — настройка `openspec.cliPath` и повторный поиск CLI.

## Impact

- **Код**: `packages/server/src/openspec/locate.ts`, опция `cliPath` сервера и
  встроенного бэкенда; `packages/vscode` — настройка, сообщения, перезапуск;
  `packages/web` — уведомление «нет CLI».
- **CLI OpenSpec**: не затрагивается.
