## ADDED Requirements

### Requirement: Навигация по разделам

Панель ДОЛЖНА (SHALL) показывать разделы вкладками в шапке: у каждой вкладки
иконка и подпись, у активной — выделение и `aria-current`. Когда ширина панели
меньше 720 px, подпись ДОЛЖНА оставаться только у активной вкладки, у остальных —
иконка с подсказкой и доступным именем. В шапке ДОЛЖНЫ быть кнопка «Поиск и
команды» с сочетанием Ctrl+K и индикатор связи с бэкендом. Раздел «Обозреватель»
со встроенным редактором ДОЛЖЕН показываться только вне VS Code.

#### Scenario: Переход между разделами

- **WHEN** пользователь щёлкает вкладку «Метрики» в шапке
- **THEN** открывается раздел «Метрики»
- **AND** вкладка «Метрики» отмечена как текущая

#### Scenario: Узкая панель

- **WHEN** панель уже 720 px
- **THEN** у неактивных вкладок видны только иконки
- **AND** у каждой вкладки есть доступное имя с названием раздела

#### Scenario: Потеря связи

- **WHEN** поток событий бэкенда разорван
- **THEN** индикатор в шапке показывает «Нет связи» цветом ошибки
- **AND** после восстановления показывает «Синхронизировано»

### Requirement: Палитра поиска и команд

Панель ДОЛЖНА (SHALL) открывать по Ctrl+K (Cmd+K на macOS) и по кнопке в шапке
модальную палитру, которая ищет по названиям changes, capability и схем, текстам
требований и сценариев и по командам панели. Выдача ДОЛЖНА быть сгруппирована
по типу, с числом найденного в каждом фильтре, подсветкой совпадения и местом в
файле. Стрелки ДОЛЖНЫ перемещать выбор, Enter — открывать результат или
выполнять команду, Esc — закрывать палитру и возвращать фокус.

#### Scenario: Поиск требования

- **WHEN** пользователь открывает палитру и вводит фрагмент названия требования
- **THEN** в группе «Требования» показано требование со спеком и строкой
- **AND** Enter открывает файл спека на строке требования

#### Scenario: Команда из палитры

- **WHEN** пользователь вводит «архив» при выбранном change
- **THEN** в группе «Команды» есть «Архивировать change…»
- **AND** её выполнение открывает подтверждение архивации этого change на доске

#### Scenario: Фильтр по типу

- **WHEN** пользователь выбирает фильтр «Сценарии»
- **THEN** в выдаче остаются только сценарии
- **AND** у каждого фильтра показано число найденного

#### Scenario: Ничего не найдено

- **WHEN** запрос не совпал ни с одним элементом
- **THEN** палитра показывает запрос и предлагает снять фильтр, если он задан

### Requirement: Выбор change в разделах

Разделы «Дельты» и «Метрики» ДОЛЖНЫ (SHALL) выбирать change переключателем в
шапке раздела, показывающим имя change и его фазу, вместо дерева рабочего
пространства. Выбор ДОЛЖЕН быть общим для разделов и меняться при переходе с
доски, из дерева VS Code и из палитры.

#### Scenario: Смена change

- **WHEN** пользователь выбирает другой change в переключателе раздела «Метрики»
- **THEN** раздел показывает метрики выбранного change
- **AND** при переходе в «Дельты» выбран тот же change

#### Scenario: Change не выбран

- **WHEN** пользователь открывает «Метрики», не выбрав change
- **THEN** раздел предлагает выбрать change из списка активных

### Requirement: Нить change

Панель ДОЛЖНА (SHALL) показывать путь change одной линией — «нитью»: узлы
артефактов схемы change в порядке зависимостей и завершающий узел «Архив».
Узел ДОЛЖЕН различать состояния «есть», «следующий шаг», «пропущен», «не
начат» и «готов к архивации» формой, а не только цветом. Отрезок между
последним артефактом и архивом ДОЛЖЕН заполняться долей выполненных пунктов
плана. Каждый узел ДОЛЖЕН иметь подсказку с названием артефакта и состоянием.

#### Scenario: Пропущенный артефакт

- **WHEN** у change есть proposal, specs и tasks, но нет design, а карточка в колонке design
- **THEN** узел design показан как следующий шаг

#### Scenario: Работа идёт

- **WHEN** все артефакты созданы и выполнено 2 пункта плана из 3
- **THEN** отрезок перед узлом «Архив» заполнен на две трети

#### Scenario: Готов к архивации

- **WHEN** change в колонке «Готово к архивации»
- **THEN** узел «Архив» показан как готовый

### Requirement: Визуальная система панели

Панель ДОЛЖНА (SHALL) использовать токены цвета со смысловыми ролями — акцент,
успех, внимание, ошибка, информация — и в VS Code брать их значения из
переменных текущей темы. Статус ДОЛЖЕН передаваться одновременно иконкой,
цветом и текстом. Текст интерфейса НЕ ДОЛЖЕН быть мельче 12 px; моноширинный
шрифт ДОЛЖЕН использоваться только для идентификаторов, путей и кода. Иконки
ДОЛЖНЫ быть встроенным SVG, наследующим цвет текста.

#### Scenario: Статус проверки

- **WHEN** последняя проверка change нашла две ошибки
- **THEN** рядом с change показаны иконка ошибки, цвет ошибки и текст «2 ошибки»

#### Scenario: Смена темы VS Code

- **WHEN** пользователь переключает тему VS Code при открытой панели
- **THEN** цвета акцента, успеха, внимания и ошибки меняются вместе с темой

### Requirement: Состояния загрузки, пустые и ошибки

Раздел, ожидающий данные, ДОЛЖЕН (SHALL) показывать скелетон своей раскладки,
а не строку «Загрузка…». Пустой раздел ДОЛЖЕН объяснять, откуда берутся данные,
и предлагать действие. Ошибка ДОЛЖНА называть причину и действие для её
устранения. Итог операции — архивации, проверки, создания — ДОЛЖЕН
показываться всплывающим уведомлением с переходом к результату.

#### Scenario: Контекст без модулей

- **WHEN** в `openspec/context/modules/` нет ни одного модуля
- **THEN** раздел «Контекст» показывает формат `index.md` с примером и кнопку «Создать модуль…»
- **AND** оформление не использует цвет ошибки

#### Scenario: Создание модуля

- **WHEN** пользователь вводит имя `web` в «Создать модуль…»
- **THEN** создаются `openspec/context/modules/web/index.md` с полями frontmatter и пустой `context.md`
- **AND** модуль появляется на карте без перезагрузки

#### Scenario: Модуль уже существует

- **WHEN** папка модуля с введённым именем уже есть
- **THEN** файлы не создаются и показывается причина

#### Scenario: Уведомление об архивации

- **WHEN** архивация change завершилась успешно
- **THEN** показывается уведомление с именем change
- **AND** уведомление исчезает само через несколько секунд
