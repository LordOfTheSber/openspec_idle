## ADDED Requirements

### Requirement: Ссылка пункта плана на сценарий

Система ДОЛЖНА (SHALL) распознавать в отслеживаемом артефакте change ссылку
пункта плана на сценарий или требование дельты: строку под пунктом, которая
после отступа начинается с `↳` или `->` и содержит `<capability> / <название>`.
Ссылка на требование ДОЛЖНА покрывать все его сценарии. Если у пункта нет ни
одной явной ссылки, связь ДОЛЖНА предполагаться, когда название сценария или
требования длиной от 12 символов встречается в тексте пункта без учёта регистра,
и ДОЛЖНА помечаться как предполагаемая.

#### Scenario: Явная ссылка на сценарий

- **WHEN** под пунктом `2.2` стоит строка `↳ vscode-extension / Команда без CLI`
- **THEN** сценарий «Команда без CLI» спека `vscode-extension` связан с пунктом `2.2`
- **AND** связь помечена как явная

#### Scenario: Ссылка на требование

- **WHEN** под пунктом стоит `-> ide-runtime / Поиск CLI OpenSpec`, а у требования три сценария
- **THEN** все три сценария связаны с пунктом

#### Scenario: Предполагаемая связь

- **WHEN** у пункта нет строк-ссылок, а его текст содержит название сценария «Путь скопирован из Git Bash»
- **THEN** сценарий связан с пунктом
- **AND** связь помечена как предполагаемая

#### Scenario: Ссылка на неизвестный сценарий

- **WHEN** строка-ссылка называет сценарий, которого нет в дельтах change
- **THEN** ссылка показывается как висячая у пункта плана
- **AND** не увеличивает покрытие

### Requirement: Покрытие сценариев change

Система ДОЛЖНА (SHALL) считать покрытыми сценарии требований ADDED и MODIFIED
дельт change, связанные хотя бы с одним пунктом плана, и показывать долю
покрытых. Для каждого пункта ДОЛЖНЫ показываться его связанные сценарии,
состояние проверки приёмки из метрик и затронутые файлы.

#### Scenario: Покрыты не все сценарии

- **WHEN** в дельтах change пять сценариев, а пункты плана связаны с четырьмя
- **THEN** покрытие показано как «4 из 5»
- **AND** непокрытый сценарий отмечен как пробел

#### Scenario: Удалённое требование

- **WHEN** дельта содержит требование в секции REMOVED со сценарием
- **THEN** этот сценарий не входит в число сценариев для покрытия

#### Scenario: Приёмка пункта

- **WHEN** проверка приёмки связанного пункта последний раз прошла успешно
- **THEN** у пункта показано «Приёмка пройдена»

### Requirement: Раздел «Трассировка»

Раздел «Дельты» ДОЛЖЕН (SHALL) иметь вкладку «Трассировка», которая показывает
сценарии дельт по capability и требованиям, пункты плана и их проверки приёмки,
связанные линиями, и сводку: покрытие сценариев, число пунктов с пройденной
приёмкой и число затронутых файлов. Вкладку ДОЛЖНО быть можно отфильтровать до
непокрытых сценариев. Выбор сценария ДОЛЖЕН показывать его шаги «когда / тогда»
и связанные пункты.

#### Scenario: Только пробелы

- **WHEN** пользователь включает «Только пробелы»
- **THEN** на вкладке остаются только непокрытые сценарии

#### Scenario: Живое обновление

- **WHEN** в плане появляется строка ссылки на непокрытый сценарий
- **THEN** вкладка показывает сценарий покрытым без действий пользователя

### Requirement: Действия для непокрытого сценария

Для непокрытого сценария система ДОЛЖНА (SHALL) предлагать «Добавить пункт в
план» и «Копировать задачу для агента». Добавление ДОЛЖНО дописывать в конец
последней группы отслеживаемого артефакта пункт
`- [ ] <группа>.<следующий номер> <название сценария>` и строку ссылки на
сценарий, не меняя остальных байтов файла. Задача для агента ДОЛЖНА содержать
change, capability, требование, шаги сценария и пути файлов спека и плана в
виде `@путь`.

#### Scenario: Пункт добавлен в план

- **WHEN** в последней группе `## 2.` плана два пункта и пользователь добавляет пункт для сценария «Команда без CLI»
- **THEN** в конец группы дописаны строки `- [ ] 2.3 Команда без CLI` и `  ↳ vscode-extension / Команда без CLI`
- **AND** остальные строки файла не изменились
- **AND** сценарий становится покрытым

#### Scenario: У change нет отслеживаемого артефакта

- **WHEN** схема change не объявила отслеживаемый артефакт
- **THEN** действие «Добавить пункт в план» недоступно и объяснено

#### Scenario: Задача для агента

- **WHEN** пользователь копирует задачу для агента по сценарию
- **THEN** в буфере обмена текст со сценарием, шагами и путями `@openspec/changes/<change>/specs/<capability>/spec.md` и файла плана
