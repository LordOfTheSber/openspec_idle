# Design: новый интерфейс панели, нить change и трассировка

## Context

Панель разделов — одна сборка React, которая открывается в webview VS Code и
в браузере (режим разработки и e2e). В VS Code цвета берутся из переменных
`--vscode-*`, скрипты — только из файлов расширения, сеть и внешние шрифты
запрещены политикой безопасности. Состояние проекта — файлы `openspec/` и CLI;
своей базы у IDE нет, метрики — в `.openspec-ide/`.

Макеты: `docs/mockups/panel-redesign.html`.

## Goals / Non-Goals

**Goals:**

- Узнаваемая навигация без обучения, один способ найти что угодно (Ctrl+K).
- Доска, по которой за секунду видно, где каждый change и что делать дальше.
- Видимая связь «сценарий контракта → пункт плана → проверка приёмки».
- Одинаковый язык статусов во всех разделах, читаемый в любой теме VS Code.

**Non-Goals:**

- Собственная тема оформления поверх темы VS Code.
- Новый формат метаданных связей (отдельный файл, frontmatter): связь живёт в
  самом плане, как всё остальное в OpenSpec.
- Перетаскивание карточек: фаза по-прежнему выводится из файлов.

## Decisions

### 1. Вкладки разделов в шапке вместо вертикальной рельсы

Разделы — горизонтальные вкладки с иконкой и подписью; в узкой панели (уже
720 px) подпись остаётся только у активной вкладки, у остальных — иконка с
подсказкой и `aria-label`.

*Альтернатива:* рельса слева с иконками. Отклонена: у VS Code уже есть
вертикальная панель действий слева, вторая рядом с ней путает; горизонтальные
вкладки к тому же вмещают подписи, а их в редакторе VS Code меньше, чем мест.

### 2. Переключатель change вместо дерева в «Дельтах» и «Метриках»

Дерево занимало 260 px ради одного выбора. Раздел, которому нужен change,
показывает в шапке кнопку-список с именем change и его фазой. Без выбранного
change «Дельты» показывают карту связей, «Метрики» — первый change из
«В работе» или список для выбора. В браузере дерево остаётся в разделе
«Обозреватель» со встроенным редактором.

*Альтернатива:* оставить дерево сворачиваемым. Отклонена: в VS Code оно
дублирует нативное дерево, а свёрнутое — лишний шаг до того же выбора.

### 3. Палитра по Ctrl+K заменяет раздел «Поиск»

Палитра — модальный диалог поверх раздела: поле, фильтры-чипы с числом
найденного, группы результатов, навигация стрелками, Enter открывает. Команды
ищутся тем же полем: переход в раздел, «Создать change…», «Проверить»,
«Архивировать…» и «Трассировка» для выбранного change. Поиск по артефактам —
прежний маршрут `/api/search`, команды фильтруются на клиенте.

В VS Code Ctrl+K занят аккордами редактора, но внутри webview с фокусом клавиши
получает страница; команда палитры VS Code «Поиск по требованиям» открывает ту
же палитру сообщением `navigate` с разделом `search`.

*Альтернатива:* оставить раздел «Поиск» и добавить палитру команд отдельно.
Отклонена: два поля поиска с разной выдачей.

### 4. Нить change — одна линия этапов

Узлы — артефакты схемы change в порядке зависимостей и завершающий узел
«Архив». Состояния узла: есть, следующий шаг (первый отсутствующий артефакт
колонки карточки), пропущен (артефакт отсутствует, а карточка уже дальше —
так бывает, когда схема не требует его для следующих), не начат, готов к
архивации. Отрезок между последним артефактом и «Архивом» заполняется долей
выполненных пунктов плана: зелёным при 100 %, акцентом раньше.

Нить строится на клиенте из `BoardCard` (артефакты, колонка, прогресс) —
нового маршрута не нужно. На карточке нить без подписей, узлы с подсказкой;
в панели деталей — с подписями.

*Альтернатива:* сегментная полоска артефактов плюс отдельная полоса плана.
Отклонена: две полоски на карточке читаются как одна и не показывают порядок.

### 5. Полоса фаз вместо свёрнутых полос

Над колонками — ряд чипов всех фаз со счётчиками (группы «Артефакты» и
«Реализация»); пустые приглушены. Колонки показываются только для непустых
фаз, если не включены «Пустые фазы»; щелчок по пустой фазе в полосе
разворачивает её колонку. Узкая раскладка («Список») — секции непустых фаз и
строка «Пустые фазы: …».

*Альтернатива:* оставить полосы и повернуть текст обратно. Отклонена: семь
полос шириной 36 px съедают столько же места, сколько колонка.

### 6. Трассировка: явная ссылка `↳` и предполагаемая по названию

Пункт плана ссылается на сценарий строкой под ним:

```markdown
- [ ] 2.2 Предупреждение при команде без CLI
  ↳ vscode-extension / Команда без CLI
```

Разбор (`core/trace.ts`): строки, начинающиеся с `↳` или `->` после отступа,
относятся к ближайшему пункту выше; справа — `<capability> / <сценарий>` или
`<capability> / <требование>` (тогда покрыты все сценарии требования);
несколько ссылок — несколько строк. Если у пункта нет ни одной явной ссылки,
связь предполагается, когда название сценария или требования (без регистра и
кавычек, от 12 символов) встречается в тексте пункта. Предполагаемые связи
показываются пунктиром с подписью.

Покрываются сценарии требований ADDED и MODIFIED; сценарии REMOVED и
требований без сценариев в покрытие не входят. Проверка приёмки и файлы
пункта — из метрик (`ItemMetrics.acceptance`, `files`).

«Добавить пункт в план» дописывает в отслеживаемый артефакт в конец последней
группы пункт `- [ ] <группа>.<следующий номер> <название сценария>` и строку
ссылки; остальные байты файла не меняются. Если групп нет, пункт дописывается
в конец файла без номера.

*Альтернативы:* (а) ссылки во frontmatter плана — отклонено: разъезжаются с
пунктами при правке; (б) только сопоставление по названию — отклонено: даёт
ложные связи и не позволяет сказать «этот пункт реализует тот сценарий»;
(в) HTML-комментарий `<!-- covers: … -->` — отклонено: невидим при чтении
плана, а ссылка — часть договорённости команды.

### 7. Готовность к архивации — пять условий

Артефакты схемы созданы; план выполнен; последняя валидация без ошибок (или
не запускалась — тогда условие «не проверено»); все сценарии покрыты;
предпросмотр архивации — «пройдёт» (строится по запросу во вкладке
«Проверка», до этого — «не проверено»). Кольцо показывает число выполненных
условий. Архивация по-прежнему доступна только через подтверждение с
предпросмотром — готовность ничего не блокирует, она подсказывает.

*Альтернатива:* один процент «здоровья» change. Отклонена: число без
расшифровки не говорит, что делать.

### 8. Визуальная система

Токены: `--bg`, `--panel`, `--card`, `--border`, `--text`, `--text-2`,
`--muted`, `--primary`, `--accent`, `--success`, `--warning`, `--danger`,
`--info`, `--purple` и их `-soft` варианты. Старые имена (`--surface`,
`--added`, `--modified`, `--removed`) остаются псевдонимами, чтобы не трогать
разметку разделов, которую редизайн не меняет. В VS Code токены берутся из
`--vscode-*` (кнопки, поля, списки, декорации git, `editorWarning`,
`editorError`). Статус всегда тройкой «иконка + цвет + текст». Иконки —
компонент `Icon` со встроенным SVG, stroke `currentColor`.

*Альтернатива:* шрифт codicons. Отклонена: политика панели разрешает шрифты
только из файлов расширения, а тянуть пакет codicons ради двух десятков
иконок и держать его версию в синхроне с VS Code дороже встроенного SVG.

### 9. Создание модуля контекста

`POST /api/context/module { id }` создаёт
`openspec/context/modules/<id>/index.md` (frontmatter с `module`,
`description`, `domains: []`, `code_paths: []`, `depends_on: []`) и пустой
`context.md`; имя — kebab-case, существующая папка — отказ.

*Альтернатива:* только показывать пример frontmatter. Отклонена: пример уже
есть, а пользователю всё равно приходится вручную создавать две папки и два
файла с правильными именами.

## Risks / Trade-offs

- [E2E опираются на разметку] → действия сохраняют прежние `data-testid`;
  тесты, проверявшие удалённые элементы (свёрнутые полосы, раздел «Поиск»),
  переписаны под новые.
- [Предполагаемые связи ошибаются] → они помечены, не считаются явными, а
  порог длины названия отсекает совпадения коротких слов.
- [Ctrl+K в VS Code] → в webview с фокусом клавиши получает страница; вне
  фокуса палитру открывает команда VS Code.

## Migration Plan

Формат файлов проекта не меняется; строка `↳` необязательна и игнорируется
CLI OpenSpec как обычный текст списка. Откат — возврат сборки панели.
