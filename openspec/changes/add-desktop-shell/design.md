# Design: десктопное приложение

## Context

IDE уже состоит из Node-сервера (`packages/server`, Fastify на loopback с
токеном сессии) и React-страницы (`packages/web`). Сервер умеет стартовать из
чужого кода: функция `startServer` не зависит от CLI-обёртки. Значит,
приложению нужно дать окно, стартовый экран и управление жизненным циклом —
логика IDE не меняется.

Ограничения:

- Основная платформа команды — Windows, установка без прав администратора.
- Корпоративная сеть: двоичный Electron при установке зависимостей может быть
  недоступен с GitHub и берётся с внутреннего зеркала.
- CLI OpenSpec запускается как Node-скрипт. В приложении Electron отдельного
  Node нет, но сам Electron умеет работать как Node (`ELECTRON_RUN_AS_NODE`).

## Goals / Non-Goals

### Goals

- Обычное приложение: установщик, ярлык, окно, недавние репозитории.
- Тот же интерфейс и те же гарантии безопасности, что в режиме браузера.
- Ни Node.js, ни CLI OpenSpec не нужно ставить отдельно.

### Non-Goals

- Автообновление. В корпоративной сети оно требует своей инфраструктуры
  раздачи; версия ставится установщиком.
- Подпись установщика сертификатом организации — делается на стороне
  выпуска, вне этого change.
- Отказ от режима браузера: команда `openspec-ide` остаётся.

## Decisions

### 1. Electron, а не Tauri

**Решение.** Оболочка — Electron. Главный процесс запускает `startServer` из
`packages/server` прямо у себя, окно загружает страницу с этого сервера.

**Почему.** Весь бэкенд IDE — Node: CLI OpenSpec, наблюдение за файлами,
запуск агента. В Electron он работает без изменений. Tauri дал бы установщик
около 10 МБ вместо примерно 100 МБ, но Node-сервер пришлось бы возить
отдельным процессом или переписывать на Rust. Выигрыш в размере не стоит
второй реализации бэкенда.

### 2. Страница по-прежнему ходит на loopback-сервер, а не через IPC

**Решение.** Окно загружает `http://127.0.0.1:<порт>` своего сервера, токен
сессии встраивается в страницу, как и сейчас. IPC используется только для
оконных действий: системный диалог, меню, недавние, подтверждение закрытия.

**Альтернатива** — перевести API на IPC Electron. Тогда у интерфейса было бы
два транспорта, режим браузера и приложение разошлись бы, а e2e-тесты
пришлось бы вести дважды. Loopback с токеном уже защищён (решение 7 основного
проекта), и одинаковый транспорт важнее.

### 3. Один сервер на окно

**Решение.** Каждое окно репозитория поднимает свой экземпляр сервера на своём
порте. Закрытие окна останавливает его сервер и наблюдатель за файлами.

**Альтернатива** — один сервер со многими корнями. Это потребовало бы
передавать корень в каждом запросе и изолировать состояние (метрики, запуски
агента, кэш CLI) внутри сервера. Отдельные экземпляры дают изоляцию бесплатно,
а накладные расходы — один порт и один наблюдатель на окно.

### 4. Один экземпляр приложения

**Решение.** `app.requestSingleInstanceLock()`. Второй запуск передаёт свои
аргументы (путь к репозиторию) работающему экземпляру и завершается.

**Почему.** Иначе два экземпляра открывают один репозиторий и одновременно
пишут журнал метрик и запусков агента.

### 5. CLI OpenSpec: из репозитория, иначе встроенный

**Решение.** Поиск остаётся прежним: `node_modules/.bin` вверх по дереву, затем
PATH. Если ничего не найдено, используется встроенный `@fission-ai/openspec` из
ресурсов приложения. Он запускается исполняемым файлом Electron с
`ELECTRON_RUN_AS_NODE=1`: отдельный Node не нужен.

**Почему приоритет у репозитория.** Команда фиксирует версию OpenSpec в своих
зависимостях. Встроенная версия приложения может с ней разойтись, и IDE начнёт
видеть проект иначе, чем `npx openspec` в терминале.

### 6. Недавние репозитории и положение окон — в профиле пользователя

**Решение.** JSON в `app.getPath('userData')`: недавние (путь и время
открытия) и геометрия окна по пути репозитория. В репозиторий ничего не
пишется.

### 7. Сборка: electron-builder, NSIS в режиме «для пользователя»

**Решение.** Установщик NSIS с `perMachine: false` — установка в профиль без
прав администратора — и переносимая сборка (`portable`). Для macOS — `dmg`,
для Linux — `AppImage`. `@fission-ai/openspec` кладётся в
`extraResources`.

**Альтернатива** — Squirrel.Windows. Он ставит в профиль всегда, но работает
только в паре с автообновлением, которое здесь не нужно, а удаление через
«Приложения» у него ведёт себя хуже.

## Risks / Trade-offs

- **Размер установщика ~100 МБ.** Цена Chromium внутри. Приемлемо для
  внутреннего инструмента.
- **Двоичный Electron в закрытой сети.** `npm ci` скачивает его при установке
  пакета. Решение — `ELECTRON_MIRROR` на внутреннее зеркало; описывается в
  README. Пакет `desktop` не входит в `npm run build` основного проекта, чтобы
  режим браузера собирался и без Electron.
- **Неподписанный установщик.** SmartScreen предупредит при первом запуске до
  подписи сертификатом организации.

## Migration Plan

Режим браузера остаётся без изменений. Приложение ставится рядом; данные
репозитория (`.openspec-ide/`) у обоих режимов общие.
