# Spec Delta: task-metrics

## ADDED Requirements

### Requirement: Отчёт о запуске агента

Система ДОЛЖНА (SHALL) принимать отчёт о запуске агента — файл JSON версии
`openspec-run/1` с идентификатором и временем запуска, исходом, токенами по
видам, вызовами инструментов, прочитанными и изменёнными файлами и
необязательной привязкой к change и пункту плана (состав полей — в
design.md). Отчёт другой версии или без `runId`, `startedAt` или
`finishedAt` ДОЛЖЕН (SHALL) считаться неверным; числовое поле отчёта без
значения ДОЛЖНО храниться как «нет данных», а не как ноль.

#### Scenario: Полный отчёт

- **WHEN** в отчёте есть все поля, `tokens.input` равно 1200, `tokens.cacheRead` — 48000, `tokens.output` — 900
- **THEN** запуск записывается в журнал событием `run-finished` с этими значениями токенов и списками файлов

#### Scenario: Отчёт без расхода токенов

- **WHEN** в отчёте нет поля `tokens`
- **THEN** запуск записывается, а его токены показаны как «нет данных»
- **AND** сводный расход change не уменьшается и не подменяется нулём

#### Scenario: Отчёт неизвестной версии

- **WHEN** в отчёте поле `schema` равно `openspec-run/2`
- **THEN** отчёт не записывается в журнал и остаётся в inbox
- **AND** проверка `metrics` даёт предупреждение с именем файла отчёта

#### Scenario: Отчёт без обязательного поля

- **WHEN** в отчёте нет поля `runId`, `startedAt` или `finishedAt`
- **THEN** отчёт не записывается в журнал и остаётся в inbox с предупреждением

### Requirement: Приём отчётов о запусках

Система ДОЛЖНА (SHALL) переносить отчёты из каталога `.openspec-ide/inbox` в
журнал метрик при запуске бэкенда, при появлении файла в inbox и при проверке
`metrics` команды `openspec-ide-check`. Отчёт с уже записанным `runId` НЕ
ДОЛЖЕН (SHALL NOT) записываться повторно. Записанный отчёт ДОЛЖЕН удаляться из
inbox, неверный — оставаться в нём с предупреждением. Приём НЕ ДОЛЖЕН
изменять файлы `openspec/`.

#### Scenario: Появление файла в inbox при открытой IDE

- **WHEN** IDE открыта, и хук агента пишет отчёт в inbox
- **THEN** раздел «Метрики» показывает новый запуск без действий пользователя
- **AND** файл отчёта удалён из inbox

#### Scenario: Отчёт записан при закрытой IDE

- **WHEN** отчёт лёг в inbox, пока IDE не была запущена, и затем бэкенд запускается
- **THEN** запуск записывается в журнал при запуске бэкенда

#### Scenario: Повторный отчёт

- **WHEN** в inbox лежит отчёт с `runId`, который уже есть в журнале
- **THEN** журнал не меняется, а отчёт удаляется из inbox

#### Scenario: Приём при проверке metrics в CI

- **WHEN** запускается `openspec-ide-check --only metrics`, и в inbox два верных отчёта
- **THEN** оба запуска записываются в журнал, а проверка завершается с кодом 0

### Requirement: Привязка запуска к задаче

Система ДОЛЖНА (SHALL) привязывать запуск к change и пункту плана по первому
сработавшему правилу: поля `change` и `item` отчёта; единственный пункт
change, взятый в работу и не завершённый на момент начала запуска;
единственный пункт, отмеченный выполненным во время запуска;
change, файлы которого запуск изменил, — без пункта. Запуск, к которому не
подошло ни одно правило, ДОЛЖЕН учитываться как «вне change» и показываться
только в сводке рабочего пространства.

#### Scenario: Явная привязка

- **WHEN** в отчёте `change: add-limits` и `item: "2.1"`
- **THEN** запуск засчитывается пункту 2.1 change `add-limits`

#### Scenario: Пункт взят в работу

- **WHEN** в отчёте нет `change` и `item`, а пункт 1.2 change `add-limits` взят в работу с доски до начала запуска и не завершён
- **THEN** запуск засчитывается пункту 1.2

#### Scenario: Пункт отмечен во время запуска

- **WHEN** правила выше не сработали, и во время запуска агент отметил выполненным пункт 3.1
- **THEN** запуск засчитывается пункту 3.1

#### Scenario: Несколько пунктов отмечены во время запуска

- **WHEN** правила выше не сработали, и во время запуска отмечены выполненными пункты 3.1 и 3.2 одного change
- **THEN** запуск засчитывается change без пункта
- **AND** в карточке запуска перечислены оба пункта как кандидаты

#### Scenario: Запуск вне change

- **WHEN** ни одно правило не сработало
- **THEN** запуск показан в сводке рабочего пространства как «вне change»
- **AND** не входит в сводку ни одного change

### Requirement: Метрики контекста запуска

Система ДОЛЖНА (SHALL) показывать для запуска и суммой для задачи и change:
долю разведки — `callsBeforeFirstEdit` от `toolCalls`, число поисков, число
файлов, прочитанных без правки, и число прочитанных файлов из
`openspec/context/` и `openspec/specs/`. Запуск без изменённых файлов ДОЛЖЕН
иметь долю разведки «нет данных», а не 100 %.

#### Scenario: Запуск с правкой

- **WHEN** запуск сделал 40 вызовов инструментов, из них 12 — до первой правки файла
- **THEN** его доля разведки — 30 %

#### Scenario: Запуск без правок

- **WHEN** запуск только читал файлы и ничего не изменил
- **THEN** его доля разведки показана как «нет данных»
- **AND** не входит в среднюю долю разведки задачи

### Requirement: Сводки по сценариям и модулям контекста

Система ДОЛЖНА (SHALL) сводить расход токенов и долю разведки по сценариям —
через строки `↳ <capability> / <сценарий>` пунктов плана — и по модулям
контекста — по `code_paths` модулей, под которыми лежат изменённые запуском
файлы. Запуск, изменивший файлы нескольких модулей, ДОЛЖЕН засчитываться
каждому из них, а сумма по модулям — сопровождаться пометкой о пересечении.
Модуль со средней долей разведки выше 50 % не меньше чем по 5 запускам
ДОЛЖЕН отмечаться как кандидат на аудит контекста.

#### Scenario: Расход на сценарий

- **WHEN** пункт 2.1 ссылается на два сценария и израсходовал 30 000 токенов
- **THEN** в сводке по сценариям каждому из двух сценариев засчитано по 15 000 токенов

#### Scenario: Запуск в двух модулях

- **WHEN** запуск изменил `packages/core/src/metrics.ts` и `packages/server/src/metrics.ts`
- **THEN** запуск засчитан модулям `core` и `server`
- **AND** итог по модулям помечен как сумма с пересечением

#### Scenario: Модуль с высокой долей разведки

- **WHEN** средняя доля разведки запусков модуля выше 50 % не меньше чем по 5 запускам
- **THEN** в сводке по модулям модуль отмечен как кандидат на аудит контекста

### Requirement: Признак задачи «с первого раза»

Система ДОЛЖНА (SHALL) отмечать задачу признаком «с первого раза», если задача
выполнена, ни разу не возвращалась в работу и её последняя проверка приёмки
прошла, и показывать долю таких задач в сводке change.

#### Scenario: Задача с первого раза

- **WHEN** задача отмечена выполненной, ни разу не возвращалась в работу и её последняя проверка приёмки завершилась с кодом 0
- **THEN** у задачи стоит признак «с первого раза»
- **AND** доля таких задач учтена в сводке change

#### Scenario: Задача возвращалась в работу

- **WHEN** задача выполнена и приёмка прошла, но до этого задача один раз возвращалась в работу
- **THEN** признака «с первого раза» у задачи нет

### Requirement: Отчёт из транскрипта Claude Code

Команда `openspec-ide-check report-run` ДОЛЖНА (SHALL) читать из стандартного
ввода данные хука Claude Code (`session_id`, `transcript_path`, `cwd`),
считать по транскрипту токены, вызовы инструментов, прочитанные и изменённые
файлы с прошлого отчёта этой сессии и писать отчёт в inbox. Команда ДОЛЖНА
завершаться с кодом 0 и без вывода в стандартный поток ошибок, если
транскрипт не найден или не разбирается, — хук не должен мешать работе
агента.

#### Scenario: Два отчёта одной сессии

- **WHEN** хук `Stop` дважды передаёт команде один и тот же `session_id` и `cwd`
- **THEN** второй отчёт содержит только токены и вызовы после первого
- **AND** у отчётов разные `runId`

#### Scenario: Транскрипт не найден или не разбирается

- **WHEN** файл `transcript_path` не существует или не разбирается как JSON Lines
- **THEN** команда завершается с кодом 0, отчёт не пишется
