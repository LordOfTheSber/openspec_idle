# Change: метрики запусков агента по задачам OpenSpec

## Why

Спека `task-metrics` уже требует хранить по каждому пункту плана расход
токенов, число запусков агента, вызовы инструментов и затронутые файлы, а
журнал метрик умеет событие `run-finished` (`packages/core/src/metrics.ts`).
Но после ADR-006 IDE не запускает агентов, и событие больше никто не пишет:
столбцы расхода в «Метриках» всегда «нет данных». Команда не видит, сколько
стоит задача, change и сценарий, какие задачи агент делает с первого раза и в
каких модулях он тратит токены на поиск вместо работы — то есть где контекст
модуля не помогает.

## What Changes

- **Отчёт о запуске агента** — файл JSON версии `openspec-run/1` в каталоге
  `.openspec-ide/inbox`: агент, модель, время, исход, токены по видам
  (новые входные, чтение кэша, запись кэша, выходные), вызовы инструментов,
  прочитанные и изменённые файлы, поиски, change и пункт плана, если они
  известны. Формат не зависит от агента.
- **Приём отчётов**: IDE и `openspec-ide-check` переносят отчёты из inbox в
  журнал событием `run-finished` — один раз на `runId`, повреждённый отчёт
  остаётся в inbox с замечанием. IDE при этом не запускает агента и не
  подключается к нему: решение ADR-006 не меняется.
- **Привязка запуска к задаче**: явная (поля отчёта или переменные
  `OPENSPEC_CHANGE`, `OPENSPEC_TASK`), затем по пункту, взятому в работу
  («Взять в работу» на доске), затем по пункту, отмеченному выполненным во
  время запуска, затем по change, чьи файлы запуск менял; иначе запуск
  считается «вне change».
- **Адаптер Claude Code**: команда `openspec-ide-check report-run` для хука
  `Stop` — читает транскрипт сессии, считает токены и инструменты с прошлого
  отчёта этой сессии и пишет отчёт в inbox. Для других агентов — тот же
  формат отчёта.
- **Метрики контекста запуска**: доля разведки — вызовы инструментов до
  первой правки файла, поиски, файлы, прочитанные без правки, чтение файлов
  `openspec/context/`. Сводка по модулям контекста (по `code_paths`
  изменённых файлов) показывает, в каких модулях агент дольше ищет — это
  кандидаты на аудит контекста (навык `context-audit`).
- **Сводки**: на задачу, на change, на сценарий (по строкам `↳` плана), на
  модуль; показатели «с первого раза» (задача выполнена без возврата и с
  пройденной приёмкой) и стоимость задачи в токенах.

### New Capabilities

### Modified Capabilities

- `task-metrics` — приём отчётов о запусках извне, привязка запуска к задаче,
  токены по видам, метрики контекста запуска, сводки по сценариям и модулям.

## Impact

- `packages/core`: формат отчёта и его проверка, привязка запуска, новые поля
  `run-finished` (версия журнала остаётся 1: новые поля необязательны),
  свёртка сводок.
- `packages/server`: приём inbox при запуске и по событию наблюдателя,
  маршрут `/api/metrics` — новые поля, `API_REVISION`.
- `packages/check`: команда `report-run` и приём inbox в проверке `metrics`.
- `packages/web`: столбцы и сводки раздела «Метрики».
- Документация: README — раздел о подключении хука; навык `context-audit`
  ссылается на сводку по модулям.
