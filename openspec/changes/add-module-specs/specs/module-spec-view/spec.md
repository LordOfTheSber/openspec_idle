# Spec Delta: module-spec-view

## Purpose

Делает большую спеку модуля — одну на сервис, UI или библиотеку, с десятками
требований — удобной для чтения: разделы, оглавление, поиск, карточка
требования с его статусом и историей, проверка формата, при котором CLI не
теряет требования.

## ADDED Requirements

### Requirement: Разделы спеки

Система ДОЛЖНА (SHALL) группировать требования спеки в разделы по имени требования:
часть имени до первого разделителя ` / ` — раздел, остаток — имя требования
внутри раздела. Несколько разделителей ДОЛЖНЫ давать вложенные разделы.
Требования без разделителя ДОЛЖНЫ попадать в раздел «Общее». Порядок разделов
и требований внутри них ДОЛЖЕН совпадать с порядком в файле.

#### Scenario: Требования с разделами

- **WHEN** спека содержит требования `Счета / Выставление счёта`, `Счета / Нумерация счетов` и `Возвраты / Возврат оплаты`
- **THEN** показаны разделы «Счета» с двумя требованиями и «Возвраты» с одним

#### Scenario: Вложенный раздел

- **WHEN** имя требования `Счета / НДС / Округление`
- **THEN** требование «Округление» показано в подразделе «НДС» раздела «Счета»

#### Scenario: Требование без раздела

- **WHEN** имя требования не содержит разделителя
- **THEN** требование показано в разделе «Общее»

### Requirement: Навигация по спеке

Система ДОЛЖНА (SHALL) показывать для спеки модуля оглавление разделов с числом
требований и сценариев, поиск по тексту требований и сценариев внутри спеки и
адрес, открывающий конкретное требование.

#### Scenario: Оглавление

- **WHEN** пользователь выбирает раздел в оглавлении
- **THEN** спека прокручивается к разделу, раздел выделен в оглавлении

#### Scenario: Поиск внутри спеки

- **WHEN** пользователь вводит текст, встречающийся в сценарии одного из требований
- **THEN** остаются показанными только требования с совпадениями, совпадение выделено
- **AND** в оглавлении у разделов указано число совпадений

#### Scenario: Прямой адрес требования

- **WHEN** пользователь копирует адрес требования и открывает его в другом окне или после перезапуска
- **THEN** открывается спека модуля с развёрнутым и выделенным требованием

### Requirement: Обзор модуля

Система ДОЛЖНА (SHALL) показывать в начале спеки модуля его обзор: назначение из
раздела Purpose, вид и каталог кода модуля, число разделов, требований и
сценариев, активные changes модуля, покрытие кодом и тестами и число связей с
другими модулями.

#### Scenario: Открытие спеки модуля

- **WHEN** пользователь открывает спеку модуля `billing`
- **THEN** обзор показывает назначение, вид «сервис», каталог `services/billing` и счётчики
- **AND** из обзора можно перейти к активным changes модуля и к требованиям без покрытия

### Requirement: Карточка требования

Система ДОЛЖНА (SHALL) показывать требование карточкой: текст, сценарии с выделенными
шагами WHEN, THEN и AND, и признаки — изменяется ли требование в активных
changes, покрыто ли кодом и тестами, сколько у него исходящих и входящих ссылок
на требования других модулей.

#### Scenario: Требование меняется в активном change

- **WHEN** активный change содержит дельту MODIFIED или REMOVED для этого требования
- **THEN** на карточке показан признак с именем change и видом изменения
- **AND** из признака открывается сравнение текущего текста с предлагаемым

#### Scenario: Требование добавляется в активном change

- **WHEN** активный change содержит дельту ADDED с требованием для этой спеки
- **THEN** требование показано в своём разделе как предлагаемое, с именем change

### Requirement: История требования

Система ДОЛЖНА (SHALL) показывать историю требования по архиву changes: какие changes
его добавили, изменили или переименовали, с датой архивации и текстом до и
после.

#### Scenario: Требование менялось дважды

- **WHEN** требование добавлено одним архивным change и изменено другим
- **THEN** история показывает оба change от новых к старым с датами
- **AND** выбор записи показывает различия текста и сценариев

#### Scenario: Переименованное требование

- **WHEN** требование было переименовано дельтой RENAMED
- **THEN** история продолжается через переименование и показывает прежнее имя

### Requirement: Проверка формата спеки модуля

Система ДОЛЖНА (SHALL) предупреждать о конструкциях, которые CLI OpenSpec обрабатывает
не так, как их видит человек: заголовок уровня `##` после раздела
Requirements, повтор имени требования, разделы, различающиеся только регистром
или пробелами.

#### Scenario: Заголовок раздела внутри требований

- **WHEN** в спеке после `## Requirements` встречается другой заголовок `##`
- **THEN** показано предупреждение со строкой заголовка и числом требований после него, которые CLI не увидит
- **AND** предлагается перенести раздел в имена требований в формате `Раздел / Требование`

#### Scenario: Похожие разделы

- **WHEN** в спеке есть разделы `Счета` и `счета `
- **THEN** показано предупреждение с предложением свести их к одному написанию
