# Spec Delta: spec-cross-links

## Purpose

Связывает требования спек разных модулей: требование сервиса ссылается на
требование библиотеки КМ, UI — на требование сервиса. IDE разрешает такие
ссылки, показывает обратные, находит битые и сопоставляет связи требований с
зависимостями модулей из карты.

## ADDED Requirements

### Requirement: Ссылка на требование другого модуля

Система ДОЛЖНА (SHALL) распознавать в тексте требования и сценариев markdown-ссылку
на спеку другой capability с якорем требования и разрешать её до требования.
Якорь ДОЛЖЕН строиться по правилам GitHub для заголовка
`### Requirement: <имя>`, чтобы та же ссылка работала при просмотре репозитория
в браузере. Ссылка без якоря ДОЛЖНА разрешаться до спеки целиком.

#### Scenario: Разрешение ссылки

- **WHEN** требование `billing` содержит ссылку `[km/core: Кэш ответов](../km/core/spec.md#requirement-кэш-ответов)`
- **THEN** ссылка показана как переход к требованию «Кэш ответов» модуля `km/core`
- **AND** при наведении видны текст и сценарии целевого требования

#### Scenario: Ссылка на спеку целиком

- **WHEN** ссылка ведёт на `spec.md` другой capability без якоря
- **THEN** она разрешается до спеки модуля и открывает её обзор

### Requirement: Вставка ссылки

Система ДОЛЖНА (SHALL) предоставлять в редакторе артефактов вставку ссылки на
требование: поиск требования по всем модулям и вставку markdown-ссылки с
относительным путём от редактируемого файла и якорем.

#### Scenario: Вставка из редактора

- **WHEN** пользователь в редакторе спеки `billing` вызывает вставку ссылки и выбирает требование «Кэш ответов» модуля `km/core`
- **THEN** в текст вставляется ссылка с относительным путём до `specs/km/core/spec.md` и якорем требования

#### Scenario: Вставка в дельту change

- **WHEN** ссылка вставляется в дельту спеки внутри change
- **THEN** относительный путь строится так, чтобы ссылка оставалась верной после архивации change

### Requirement: Обратные ссылки

Система ДОЛЖНА (SHALL) показывать у требования, какие требования других модулей на
него ссылаются. Для change, изменяющего требование, ДОЛЖНЫ показываться
требования, которые на него ссылаются, как затронутые.

#### Scenario: Кто ссылается на требование

- **WHEN** пользователь открывает требование «Кэш ответов» модуля `km/core`
- **THEN** показан список ссылающихся требований с модулем и разделом, например `billing: Счета / Выставление счёта`

#### Scenario: Change меняет требование, на которое ссылаются

- **WHEN** активный change содержит дельту MODIFIED для требования «Кэш ответов»
- **THEN** в деталях change показаны ссылающиеся требования других модулей как затронутые
- **AND** этот перечень точнее списка затронутых модулей по зависимостям карты

### Requirement: Битые ссылки

Система ДОЛЖНА (SHALL) находить ссылки, которые не разрешаются: несуществующая спека,
несуществующее требование, требование, удаляемое или переименовываемое в
активном change. Для переименованного требования ДОЛЖНА предлагаться
замена ссылки.

#### Scenario: Требование переименовано

- **WHEN** требование, на которое ссылаются, переименовано в архивном change
- **THEN** ссылка помечена битой с указанием файла и строки
- **AND** предлагается заменить якорь на новое имя требования

#### Scenario: Требование удаляется в активном change

- **WHEN** активный change удаляет требование, на которое ссылаются из других модулей
- **THEN** в деталях change показано предупреждение с перечнем ссылающихся требований

### Requirement: Связи требований на графе модулей

Система ДОЛЖНА (SHALL) показывать на графе модулей связи, выведенные из ссылок между
требованиями, с числом ссылок, и сопоставлять их с зависимостями из карты
модулей.

#### Scenario: Ссылка без зависимости в карте

- **WHEN** требование `web-ui` ссылается на требование `billing`, а в карте модулей `web-ui` не зависит от `billing`
- **THEN** связь показана на графе как расхождение
- **AND** предлагается добавить зависимость в карту модулей

#### Scenario: Зависимость без ссылок

- **WHEN** модуль зависит от другого по карте, но ни одно его требование не ссылается на требования этого модуля
- **THEN** зависимость отмечена как неописанная в спеках — контракт между модулями не зафиксирован
