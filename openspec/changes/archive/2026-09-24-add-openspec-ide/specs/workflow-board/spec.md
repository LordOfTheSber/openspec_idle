# Spec Delta: workflow-board

## Purpose

Даёт обзор всех активных changes на доске фаз их процесса и позволяет выполнять
над change операции — валидацию, переход к работе и архивацию — не покидая
интерфейс. Фазы доски выводятся из схемы workflow, по которой заведён change,
поэтому доска одинаково работает и для встроенной схемы, и для собственного
процесса команды.

## ADDED Requirements

### Requirement: Доска фаз процесса

Система ДОЛЖНА (SHALL) размещать каждый активный change в одной колонке доски по его
текущей фазе. Фаза ДОЛЖНА вычисляться из состояния артефактов и прогресса
отслеживаемого артефакта, полученных командой
`openspec status --change <name> --json`, а не задаваться пользователем вручную.
Состав колонок ДОЛЖЕН строиться из артефактов схемы change в порядке их
зависимостей, с добавлением завершающих колонок работы и готовности к архивации;
жёстко заданного списка фаз быть не должно.

#### Scenario: Change без артефактов

- **WHEN** у change создан только каталог и файл настроек
- **THEN** карточка находится в колонке первого артефакта схемы

#### Scenario: Планирование завершено, работа не начата

- **WHEN** у change заполнены все артефакты планирования, а в отслеживаемом артефакте нет отмеченных пунктов
- **THEN** карточка находится в колонке «Готово к работе»

#### Scenario: Работа идёт

- **WHEN** часть пунктов change отмечена выполненными, но не все
- **THEN** карточка находится в колонке «В работе»
- **AND** на карточке виден прогресс в виде отношения выполненных пунктов к общему числу

#### Scenario: Все пункты выполнены

- **WHEN** все пункты отслеживаемого артефакта отмечены выполненными
- **THEN** карточка находится в колонке «Готово к архивации»

#### Scenario: Изменение файлов меняет фазу

- **WHEN** пользователь отмечает последний невыполненный пункт
- **THEN** карточка перемещается в колонку «Готово к архивации» без перезагрузки страницы

#### Scenario: Собственная схема с дополнительным этапом

- **WHEN** change заведён по схеме, где перед предложением идёт артефакт исследования
- **THEN** на доске присутствует колонка этого артефакта перед колонкой предложения
- **AND** порядок колонок соответствует порядку зависимостей артефактов схемы

#### Scenario: Changes на разных схемах

- **WHEN** активные changes заведены по разным схемам
- **THEN** доска показывает объединённый набор колонок
- **AND** карточка каждого change попадает в колонку своей схемы
- **AND** на карточке указано имя схемы, по которой заведён change

### Requirement: Содержимое карточки change

Карточка change ДОЛЖНА (SHALL) показывать имя change, имя его схемы, статус
артефактов планирования, прогресс по отслеживаемому артефакту, результат последней
валидации и время последнего изменения файлов change.

#### Scenario: Карточка с ошибками валидации

- **WHEN** последняя валидация change завершилась с ошибками
- **THEN** карточка показывает признак ошибки и их количество
- **AND** переход с карточки открывает панель проверок этого change

#### Scenario: Карточка нового change

- **WHEN** change создан только что и ни разу не валидировался
- **THEN** карточка показывает состояние проверки «не выполнялась»
- **AND** доступно действие запуска валидации

### Requirement: Операции над change с доски

Система ДОЛЖНА (SHALL) предоставлять с карточки change операции создания change,
валидации и архивации. Операции, изменяющие файлы, ДОЛЖНЫ выполняться
соответствующими командами CLI OpenSpec, а не собственной реализацией IDE.

#### Scenario: Создание нового change

- **WHEN** пользователь создаёт change с корректным именем
- **THEN** выполняется `openspec new change <name>` со схемой, выбранной пользователем
- **AND** созданный change появляется на доске в колонке первого артефакта своей схемы

#### Scenario: Выбор схемы при создании change

- **WHEN** в проекте доступна более чем одна схема
- **THEN** при создании change предлагается выбрать схему
- **AND** схемой по умолчанию предлагается заданная в настройках проекта

#### Scenario: Недопустимое имя change

- **WHEN** введённое имя не соответствует требованиям CLI к имени change
- **THEN** создание не выполняется
- **AND** сообщение об ошибке от CLI показывается рядом с полем ввода

#### Scenario: Архивация завершённого change

- **WHEN** пользователь подтверждает архивацию change, все пункты которого выполнены
- **THEN** выполняется `openspec archive <name>`
- **AND** после успешного завершения change исчезает с доски и появляется в разделе архива
- **AND** затронутые основные спеки обновляются в дереве

#### Scenario: Архивация невыполненного change

- **WHEN** пользователь запускает архивацию change с невыполненными пунктами
- **THEN** показывается предупреждение с числом невыполненных пунктов
- **AND** операция выполняется только после явного подтверждения

#### Scenario: Операция CLI завершилась ошибкой

- **WHEN** запущенная с доски команда CLI возвращает ненулевой код
- **THEN** состояние доски не меняется
- **AND** пользователю показывается вывод команды целиком

### Requirement: Отметка выполнения пунктов с доски

Система ДОЛЖНА (SHALL) позволять отмечать и снимать отметку выполнения пункта
change, записывая изменение в артефакт, объявленный схемой отслеживаемым, без
изменения остального содержимого файла, включая формулировки пунктов, заголовки
групп и порядок строк.

#### Scenario: Отметка пункта выполненным

- **WHEN** пользователь отмечает пункт в списке работ change
- **THEN** в соответствующей строке отслеживаемого артефакта скобки чекбокса содержат символ `x`
- **AND** остальные строки файла остаются побайтово неизменными

#### Scenario: Схема отслеживает артефакт с другим именем

- **WHEN** схема change объявляет отслеживаемым артефакт с именем, отличным от `tasks.md`
- **THEN** отметка записывается именно в этот файл

#### Scenario: Снятие отметки

- **WHEN** пользователь снимает отметку с выполненного пункта
- **THEN** скобки чекбокса в строке становятся пустыми
- **AND** прогресс change пересчитывается
