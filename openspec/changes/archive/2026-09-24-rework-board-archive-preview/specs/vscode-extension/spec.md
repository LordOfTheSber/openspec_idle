# Spec Delta: vscode-extension

## MODIFIED Requirements

### Requirement: Команды и строка состояния

Расширение ДОЛЖНО (SHALL) предоставлять команды палитры: обновить дерево,
создать change (с выбором схемы), проверить change, построить предпросмотр
архивации change, архивировать change и открыть каждый раздел панели. Команды,
которым нужен change, ДОЛЖНЫ брать его из узла дерева, а при вызове из палитры —
предлагать выбор. Подтверждение архивации ДОЛЖНО показывать сводку изменений
основных спеков по предпросмотру и НЕ ДОЛЖНО предлагать архивацию, которую CLI
по предпросмотру отклонит. Строка состояния ДОЛЖНА показывать число активных
changes и спеков и открывать доску по щелчку.

#### Scenario: Архивация из палитры

- **WHEN** пользователь вызывает «Архивировать change» из палитры
- **THEN** расширение предлагает выбрать один из активных changes
- **AND** после подтверждения change архивируется через CLI OpenSpec и исчезает из раздела «Изменения»

#### Scenario: Сводка в подтверждении архивации

- **WHEN** пользователь архивирует change, который добавляет capability `data-export`
- **THEN** окно подтверждения перечисляет `data-export` как новую capability с числом добавленных требований
- **AND** предлагает, кроме архивации, открыть сравнение спеков

#### Scenario: Архивация, которую CLI отклонит

- **WHEN** предпросмотр сообщает, что CLI отклонит архивацию change
- **THEN** расширение показывает сообщение CLI и не предлагает архивировать

#### Scenario: Создание change с выбором схемы

- **WHEN** пользователь создаёт change и выбирает собственную схему с нарушением SDD уровня «ошибка»
- **THEN** создание отклоняется с текстом нарушения, как и в прежней IDE

#### Scenario: Строка состояния

- **WHEN** в проекте 2 активных change и 5 спеков
- **THEN** строка состояния показывает оба числа
- **AND** щелчок по ней открывает доску

## ADDED Requirements

### Requirement: Предпросмотр архивации в редакторе сравнения

Расширение ДОЛЖНО (SHALL) открывать предпросмотр архивации capability во
встроенном редакторе сравнения VS Code: слева — текущий файл спека или пустой
документ для новой capability, справа — спек после архивации в документе только
для чтения. Содержимое правой стороны ДОЛЖНО браться из запроса расширения к
бэкенду, а не из сообщения панели: панель ДОЛЖНА передавать только имя change и
путь capability.

#### Scenario: Сравнение из панели

- **WHEN** пользователь в предпросмотре архивации на доске нажимает «Открыть сравнение» у capability
- **THEN** в VS Code открывается редактор сравнения текущего спека и спека после архивации

#### Scenario: Новая capability

- **WHEN** capability создаётся архивацией и её файла ещё нет
- **THEN** левая сторона сравнения пуста

#### Scenario: Команда для нескольких capability

- **WHEN** пользователь вызывает «Предпросмотр архивации» для change с дельтами трёх capability
- **THEN** расширение предлагает выбрать одну capability или все

#### Scenario: Правая сторона только для чтения

- **WHEN** пользователь пытается изменить спек в правой стороне сравнения
- **THEN** правка не принимается, файлы проекта не меняются
