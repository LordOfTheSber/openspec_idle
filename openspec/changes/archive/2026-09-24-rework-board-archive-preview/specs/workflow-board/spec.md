# Spec Delta: workflow-board

## MODIFIED Requirements

### Requirement: Содержимое карточки change

Карточка change ДОЛЖНА (SHALL) показывать имя change, имя его схемы, статус
артефактов планирования, прогресс по отслеживаемому артефакту, результат последней
валидации и время последнего изменения файлов change. Метка созданного
артефакта на карточке ДОЛЖНА открывать его файл: в VS Code — в редакторе
VS Code, в браузере — во встроенном редакторе.

#### Scenario: Карточка с ошибками валидации

- **WHEN** последняя валидация change завершилась с ошибками
- **THEN** карточка показывает признак ошибки и их количество
- **AND** переход с карточки открывает панель проверок этого change

#### Scenario: Карточка нового change

- **WHEN** change создан только что и ни разу не валидировался
- **THEN** карточка показывает состояние проверки «не выполнялась»
- **AND** доступно действие запуска валидации

#### Scenario: Время изменения

- **WHEN** файлы change последний раз менялись пять минут назад
- **THEN** карточка показывает «изменён 5 мин назад»

#### Scenario: Переход к артефакту с карточки

- **WHEN** пользователь в панели VS Code щёлкает метку `design` на карточке
- **THEN** `design.md` этого change открывается в редакторе VS Code

### Requirement: Операции над change с доски

Система ДОЛЖНА (SHALL) предоставлять с карточки change операции создания change,
валидации и архивации. Операции, изменяющие файлы, ДОЛЖНЫ выполняться
соответствующими командами CLI OpenSpec, а не собственной реализацией IDE.
Подтверждение архивации ДОЛЖНО показывать предпросмотр изменений основных спеков
до того, как пользователь подтвердит операцию, и НЕ ДОЛЖНО позволять запустить
архивацию, которую CLI по предпросмотру отклонит.

#### Scenario: Создание нового change

- **WHEN** пользователь создаёт change с корректным именем
- **THEN** выполняется `openspec new change <name>` со схемой, выбранной пользователем
- **AND** созданный change появляется на доске в колонке первого артефакта своей схемы

#### Scenario: Выбор схемы при создании change

- **WHEN** в проекте доступна более чем одна схема
- **THEN** при создании change предлагается выбрать схему
- **AND** схемой по умолчанию предлагается заданная в настройках проекта

#### Scenario: Недопустимое имя change

- **WHEN** введённое имя не соответствует требованиям CLI к имени change
- **THEN** создание не выполняется
- **AND** сообщение об ошибке от CLI показывается рядом с полем ввода

#### Scenario: Архивация завершённого change

- **WHEN** пользователь подтверждает архивацию change, все пункты которого выполнены
- **THEN** выполняется `openspec archive <name>`
- **AND** после успешного завершения change исчезает с доски и появляется в разделе архива
- **AND** затронутые основные спеки обновляются в дереве

#### Scenario: Архивация невыполненного change

- **WHEN** пользователь запускает архивацию change с невыполненными пунктами
- **THEN** показывается предупреждение с числом невыполненных пунктов
- **AND** операция выполняется только после явного подтверждения

#### Scenario: Подтверждение показывает изменения спеков

- **WHEN** пользователь запускает архивацию change с дельтами двух capability
- **THEN** до подтверждения показан предпросмотр по обеим capability
- **AND** кнопка подтверждения доступна, только когда предпросмотр готов

#### Scenario: Архивация, которую CLI отклонит

- **WHEN** предпросмотр сообщает, что CLI отклонит архивацию
- **THEN** кнопка подтверждения недоступна
- **AND** рядом показаны сообщение CLI и подсказка по исправлению

#### Scenario: Проверка с доски

- **WHEN** пользователь запускает проверку change с его карточки
- **THEN** выполняется `openspec validate <name> --strict`
- **AND** замечания показываются в панели деталей с переходом к файлу и строке

#### Scenario: Операция CLI завершилась ошибкой

- **WHEN** запущенная с доски команда CLI возвращает ненулевой код
- **THEN** состояние доски не меняется
- **AND** пользователю показывается вывод команды целиком

## ADDED Requirements

### Requirement: Раскладка доски в узкой панели

Доска ДОЛЖНА (SHALL) занимать всю ширину раздела без дерева рабочего
пространства. Колонки без карточек ДОЛЖНЫ сворачиваться в узкие полосы с
названием и счётчиком, если пользователь не выбрал показ пустых колонок. Доска
ДОЛЖНА иметь режим «Список», в котором фазы идут секциями сверху вниз, и в
автоматическом режиме переключаться в него, когда ширина доски меньше 640 px.
Выбор режима ДОЛЖЕН сохраняться между открытиями доски.

#### Scenario: Пустые колонки свёрнуты

- **WHEN** на доске семь колонок и карточки есть только в двух
- **THEN** пять пустых колонок показаны узкими полосами с названием и нулевым счётчиком
- **AND** щелчок по полосе разворачивает колонку

#### Scenario: Узкая панель VS Code

- **WHEN** панель разделов открыта рядом с редактором и доска уже 640 px
- **THEN** доска показана списком фаз без горизонтальной прокрутки
- **AND** в каждой секции видны карточки этой фазы

#### Scenario: Режим выбран вручную

- **WHEN** пользователь выбрал режим «Колонки» и закрыл панель
- **THEN** при следующем открытии доска показана колонками независимо от ширины

#### Scenario: Фильтр по имени

- **WHEN** пользователь вводит часть имени change в поле фильтра
- **THEN** на доске остаются только карточки, имя которых содержит введённый текст
- **AND** счётчики колонок показывают число оставшихся карточек

### Requirement: Панель деталей change

Выбор карточки ДОЛЖЕН (SHALL) открывать панель деталей change рядом с доской,
а на узкой панели — поверх доски. Панель ДОЛЖНА показывать артефакты change с
состоянием и переходом к файлу, пункты отслеживаемого артефакта по группам с
возможностью отметки, результат последней проверки, запущенной с доски, и
действия: проверить, открыть дельты, метрики и агента этого change,
архивировать. Панель ДОЛЖНА закрываться кнопкой и клавишей Esc.

#### Scenario: Переход к метрикам

- **WHEN** пользователь нажимает «Метрики» в панели деталей change
- **THEN** открывается раздел «Метрики» с этим change

#### Scenario: Пункты по группам

- **WHEN** отслеживаемый артефакт содержит группы `## 1.` и `## 2.`
- **THEN** пункты показаны под заголовками своих групп

#### Scenario: Закрытие по Esc

- **WHEN** панель деталей открыта и пользователь нажимает Esc
- **THEN** панель закрывается, а доска остаётся на месте

### Requirement: Живое обновление доски

Доска, панель деталей change и открытый предпросмотр архивации ДОЛЖНЫ (SHALL)
перечитывать данные при изменении файлов рабочего пространства, в том числе
сделанном в обход IDE, без действий пользователя.

#### Scenario: Отметка пункта в редакторе VS Code

- **WHEN** пользователь отмечает последний невыполненный пункт в `tasks.md` в редакторе VS Code и сохраняет файл
- **THEN** карточка на доске переходит в колонку «Готово к архивации»
- **AND** пункт в панели деталей отмечен выполненным
