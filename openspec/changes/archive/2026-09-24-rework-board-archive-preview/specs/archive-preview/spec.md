# Spec Delta: archive-preview

## Purpose

Показывает заранее, что станет с основными спеками после `openspec archive`
для выбранного change, и пройдёт ли архивация вообще. Предпросмотр строится тем
же CLI, что и архивация, поэтому не может с ней разойтись, и не меняет файлы
проекта.

## ADDED Requirements

### Requirement: Прогон архивации на временной копии

Система ДОЛЖНА (SHALL) строить предпросмотр архивации change, выполняя
`openspec archive <name> --yes --json` во временной копии каталога `openspec/`
проекта, содержащей конфигурацию, схемы проекта, основные спеки и сам change.
Файлы проекта при построении предпросмотра НЕ ДОЛЖНЫ меняться, а временная
копия ДОЛЖНА удаляться после прогона. Собственной реализации слияния дельт с
основными спеками у системы быть НЕ ДОЛЖНО.

#### Scenario: Предпросмотр не трогает проект

- **WHEN** пользователь строит предпросмотр архивации change
- **THEN** каталог change остаётся в `openspec/changes/`
- **AND** файлы `openspec/specs/` проекта побайтово не меняются

#### Scenario: Временная копия удаляется

- **WHEN** предпросмотр построен, в том числе с отказом CLI
- **THEN** временного каталога предпросмотра больше нет на диске

#### Scenario: Change на собственной схеме

- **WHEN** change заведён по схеме из `openspec/schemas/` проекта
- **THEN** предпросмотр строится по этой схеме так же, как её применит архивация

### Requirement: Исход предпросмотра

Предпросмотр ДОЛЖЕН (SHALL) сообщать один из исходов: архивация пройдёт;
архивация будет отклонена проверкой; архивация будет отклонена по другой
причине. При отказе ДОЛЖНЫ показываться сообщение CLI и его подсказка по
исправлению. При отказе проверкой ДОЛЖНЫ дополнительно показываться спеки,
какими они станут после исправления ошибок проверки.

#### Scenario: Архивация пройдёт

- **WHEN** CLI в копии архивирует change без ошибок
- **THEN** предпросмотр сообщает, что архивация пройдёт
- **AND** показывает число добавленных, изменённых, удалённых и переименованных требований

#### Scenario: MODIFIED теряет сценарий основного спека

- **WHEN** требование секции MODIFIED не содержит сценария, который есть у него в основном спеке
- **THEN** предпросмотр сообщает, что архивация будет отклонена
- **AND** показывает сообщение CLI с именем потерянного сценария

#### Scenario: Change не проходит проверку

- **WHEN** `openspec validate` для change завершается ошибками
- **THEN** предпросмотр сообщает, что архивация будет отклонена проверкой
- **AND** показывает спеки, какими их сделает архивация без проверки, с пометкой об этом

#### Scenario: Вывод CLI не разбирается

- **WHEN** CLI завершился, но его вывод не является ожидаемым JSON
- **THEN** предпросмотр сообщает об отказе и показывает вывод CLI целиком
- **AND** не показывает спеков после архивации

### Requirement: Изменения основных спеков

Для каждой capability, файл которой архивация создаст или изменит, предпросмотр
ДОЛЖЕН (SHALL) показывать: путь capability и признак «новая» или «изменится»;
требования спека после архивации с отметкой «добавлено», «изменено»,
«переименовано» или «без изменений»; требования, которые будут удалены; для
изменённого требования — появившиеся и пропавшие сценарии; построчное
сравнение файла спека до и после архивации с контекстом.

#### Scenario: Новая capability

- **WHEN** change добавляет дельту capability, которой нет в `openspec/specs/`
- **THEN** capability отмечена как новая
- **AND** все её требования отмечены как добавленные

#### Scenario: Переименованное требование

- **WHEN** дельта содержит RENAMED с `FROM` и `TO`
- **THEN** требование показано под новым именем с отметкой «переименовано» и прежним именем
- **AND** не показывается как пара «удалено» и «добавлено»

#### Scenario: Удалённое требование

- **WHEN** дельта удаляет требование основного спека
- **THEN** требование указано в списке удаляемых

#### Scenario: Изменённое требование

- **WHEN** MODIFIED меняет текст требования и добавляет сценарий
- **THEN** требование отмечено как изменённое
- **AND** добавленный сценарий перечислен как появившийся

#### Scenario: Построчное сравнение

- **WHEN** пользователь раскрывает сравнение файла спека
- **THEN** добавленные и удалённые строки выделены раздельно
- **AND** неизменные участки вне трёх строк контекста свёрнуты

### Requirement: Маршрут предпросмотра

Бэкенд ДОЛЖЕН (SHALL) отдавать предпросмотр по запросу
`GET /api/archive/preview?change=<name>` одинаково в HTTP-режиме и в панели
VS Code. Запрос для несуществующего change ДОЛЖЕН завершаться кодом 404.

#### Scenario: Несуществующий change

- **WHEN** запрошен предпросмотр change, которого нет среди активных
- **THEN** ответ приходит с кодом 404 и сообщением
