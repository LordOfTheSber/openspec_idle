# Change: расширение VS Code вместо отдельной web-IDE

## Why

OpenSpec IDE сейчас — отдельное приложение: команда `openspec-ide` поднимает
локальный HTTP-сервер и открывает интерфейс во вкладке браузера. На практике
разработчик работает с OpenSpec-проектом не в вакууме, а в редакторе кода, и
отдельная вкладка создаёт три неудобства:

- **Два редактора одного файла.** Артефакт можно править во встроенном в IDE
  CodeMirror и тут же в VS Code. Правки расходятся, IDE вынуждена ловить
  конфликты записи, а привычные средства редактора — горячие клавиши,
  расширения, git-аннотации, поиск по проекту — в IDE недоступны.
- **Лишняя инфраструктура.** Порт, токен сессии, открытие браузера, отдельный
  бинарь, который нужно собрать и положить в `PATH`. Всё это защищает и
  обслуживает канал, которого внутри редактора просто нет.
- **Контекст теряется при переключении.** Задача из `tasks.md`, запуск агента и
  изменённые им файлы живут в разных окнах; перейти от замечания валидации к
  строке в коде или от метрики к исходнику приходится вручную.

Логика IDE — разбор артефактов, доска, метрики, правила SDD, мост к агенту — от
браузера не зависит: она уже отделена в пакетах `core` и `server`. Меняется
только оболочка. Поэтому IDE переезжает в VS Code как расширение, а отдельная
web-IDE с бинарём `openspec-ide` упраздняется.

## What Changes

- **Новое расширение VS Code `openspec-ide`** — пакет `packages/vscode`.
  Активируется в рабочей области, где есть каталог `openspec/`, и поднимает
  бэкенд IDE внутри процесса расширения, без сетевого порта.
- **Нативный обозреватель** — дерево changes, спеков, процессов и архива в
  собственном контейнере на панели действий VS Code, с теми же индикаторами
  состояния и прогресса. Выбор артефакта или спека открывает файл в обычном
  редакторе VS Code.
- **Нативная валидация** — замечания `openspec validate --strict` показываются в
  панели «Проблемы» и подчёркиваются в тексте артефакта; проверка
  перезапускается при сохранении файла change.
- **Разделы в панели webview** — доска, дельты, метрики, агент, процессы,
  настройки и поиск открываются командами и из контекстного меню дерева в одной
  панели внутри VS Code. Это тот же React-интерфейс, но он общается с бэкендом
  сообщениями webview, а не HTTP, и открывает файлы в редакторе VS Code вместо
  встроенного.
- **Команды палитры** — обновить, создать change, проверить change,
  архивировать change, открыть каждый из разделов.
- **Строка состояния** — число changes и спеков, признак готовности CLI OpenSpec.
- **Упраздняется** бинарь `openspec-ide` (пакет `packages/cli`): запуск по
  порту, флаги `--port`, `--no-open`, открытие браузера. **BREAKING** для тех,
  кто запускал IDE из терминала.
- **Остаётся** HTTP-режим бэкенда как средство разработки интерфейса
  (`npm run dev`) и сквозных тестов — не как пользовательский продукт.

Не входит в этот change: публикация расширения в Marketplace, поддержка
VS Code for the Web (нужен Node для CLI OpenSpec и агента), несколько корней
OpenSpec в одной рабочей области одновременно, замена React-разделов на
нативные виды VS Code сверх дерева и диагностики.

## Capabilities

### New Capabilities

- `vscode-extension` — активация расширения и выбор корня OpenSpec, бэкенд
  внутри процесса расширения, нативное дерево, диагностика валидации, панель
  разделов и её канал сообщений, команды и строка состояния.

### Modified Capabilities

- `ide-runtime` — требование «Запуск IDE в каталоге проекта» (бинарь
  `openspec-ide`) снимается: точкой входа становится расширение. Требования к
  разрешению корня, обёртке над CLI, границам рабочего пространства и
  конфигурации остаются и выполняются расширением.

## Impact

- **Новый код**: `packages/vscode` — расширение (TypeScript, сборка esbuild в
  один CommonJS-файл, `vscode` — внешний модуль). В `packages/server` —
  встраиваемый бэкенд без сокета. В `packages/web` — сменяемый транспорт API и
  потока событий, связь с хостом VS Code, тема из переменных VS Code.
- **Удаляется**: `packages/cli` и его тесты. `npm run dev` и e2e переходят на
  скрипт разработки поверх `startServer`.
- **Зависимости**: `@types/vscode`, `esbuild`, `@vscode/vsce` — только для
  разработки и упаковки. Требование к VS Code — 1.90 и новее.
- **Данные**: без изменений — `.openspec-ide/` в корне проекта, схемы в
  `openspec/schemas/`.
- **Сеть**: расширение не открывает ни одного порта; исходящий трафик к LLM
  по-прежнему идёт только через процесс GigaCode CLI.
- **Проверка**: запустить настоящий VS Code в CI этого репозитория нельзя —
  загрузка VS Code недоступна. Поведение расширения проверяется модульными
  тестами и дымовым тестом собранного бандла с подменённым модулем `vscode`.
