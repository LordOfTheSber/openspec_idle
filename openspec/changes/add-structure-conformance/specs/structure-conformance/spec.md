# Spec Delta: structure-conformance

## Purpose

Фиксирует единую структуру папок проекта для контекста и спецификаций в файле
`openspec/structure.yaml` и проверяет, что рабочее пространство ей
соответствует. Жёсткость задаётся по месту: строго до файла или только до
папки, внутри которой допустима любая структура.

## ADDED Requirements

### Requirement: Описание структуры папок

Система ДОЛЖНА (SHALL) читать структуру папок из файла `openspec/structure.yaml`:
дерево от корня проекта в поле `structure`, где ключ — имя элемента, а
значение — правило. Правила ДОЛЖНЫ поддерживать: обязательный файл (`file`);
строгую папку — вложенный перечень, всё не описанное в которой считается
лишним; свободную папку (`"*"`), содержимое которой не проверяется; элемент
любого типа (`any`); необязательный элемент (`?` в конце имени); шаблон имени
со звёздочкой, которому соответствует ноль или больше элементов. Корень
проекта НЕ ДОЛЖЕН считаться строгой папкой.

#### Scenario: Жёсткая структура до файла

- **WHEN** описание задаёт папку `docs/context` с файлами `README.md` и `glossary.md`
- **THEN** проверка требует оба файла
- **AND** любой другой файл или папка в `docs/context` считается лишним

#### Scenario: Мягкая граница

- **WHEN** описание задаёт `specs: "*"` внутри строгой папки `openspec`
- **THEN** проверка требует папку `openspec/specs`
- **AND** не проверяет ничего внутри неё

#### Scenario: Шаблон имени

- **WHEN** описание задаёт в папке `adr` правило `"*.md": file`
- **THEN** любое число файлов `.md` в `adr` допустимо, в том числе ни одного
- **AND** файл `notes.txt` в `adr` считается лишним

#### Scenario: Необязательный элемент

- **WHEN** описание задаёт `schemas?: "*"`, а папки `schemas` нет
- **THEN** нарушения нет

#### Scenario: Корень проекта

- **WHEN** в корне проекта есть `src/` и `package.json`, не упомянутые в описании
- **THEN** они не считаются лишними

#### Scenario: Служебные файлы

- **WHEN** в строгой папке лежит `.gitkeep` или `.DS_Store`
- **THEN** он не считается лишним, если поле `ignore` не переопределено

### Requirement: Ошибки описания структуры

Система ДОЛЖНА (SHALL) сообщать об ошибках в самом описании с номером строки:
некорректный YAML, неизвестное правило, имя с `/`, `.` или `..`,
необязательный шаблон, отсутствие поля `structure`. При ошибках описания
проверка соответствия НЕ ДОЛЖНА выполняться.

#### Scenario: Неизвестное правило

- **WHEN** в описании встречается `README.md: required`
- **THEN** сообщается, что правило «required» неизвестно, с номером строки ключа
- **AND** нарушения структуры не показываются

#### Scenario: Путь вместо имени

- **WHEN** ключ описания — `docs/context`
- **THEN** сообщается, что имя не может содержать `/`, и предлагается вложить папки

### Requirement: Проверка соответствия

Система ДОЛЖНА (SHALL) проверять рабочее пространство по описанию и сообщать
нарушения трёх видов: нет обязательного элемента, лишний элемент в строгой
папке, не тот тип элемента. Каждое нарушение ДОЛЖНО содержать путь
относительно корня, вид, ожидаемый и фактический тип и номер строки правила в
`openspec/structure.yaml`. Проверка НЕ ДОЛЖНА менять файлы проекта.

#### Scenario: Нет обязательного файла

- **WHEN** описание требует `docs/context/README.md`, а файла нет
- **THEN** сообщается нарушение «нет обязательного файла» с путём `docs/context/README.md`
- **AND** со строкой ключа `README.md` в описании

#### Scenario: Лишний файл

- **WHEN** в строгой папке `docs/context` лежит `draft.txt`
- **THEN** сообщается нарушение «лишний файл» со строкой ключа `context`
- **AND** перечислены имена, разрешённые в этой папке

#### Scenario: Не тот тип

- **WHEN** описание требует папку `docs/context/adr`, а на этом месте файл
- **THEN** сообщается, что `docs/context/adr` должна быть папкой

#### Scenario: Структура соответствует

- **WHEN** все элементы на месте и лишних нет
- **THEN** проверка сообщает, что структура соответствует описанию

### Requirement: Раздел «Структура»

Панель ДОЛЖНА (SHALL) иметь раздел «Структура», который показывает итог
проверки, нарушения с переходом к файлу или к правилу описания, ошибки
описания и дерево описания с отметкой состояния каждого элемента. Раздел
ДОЛЖЕН перепроверять структуру при изменении файлов и по кнопке. Если описания
нет, раздел ДОЛЖЕН предлагать создать `openspec/structure.yaml` по текущей
раскладке каталога `openspec/`; созданное описание ДОЛЖНО проходить проверку
на том проекте, где его создали.

#### Scenario: Описания нет

- **WHEN** в проекте нет `openspec/structure.yaml`
- **THEN** раздел объясняет, что проверка не настроена, и предлагает создать описание
- **AND** после создания проверка проходит без нарушений

#### Scenario: Переход к правилу

- **WHEN** пользователь выбирает нарушение «нет обязательного файла»
- **THEN** открывается `openspec/structure.yaml` на строке этого правила

#### Scenario: Файл добавлен в обход IDE

- **WHEN** в строгую папку добавлен лишний файл, пока раздел открыт
- **THEN** нарушение появляется без действий пользователя
