# Change: проверка структуры папок контекста и спецификаций

## Why

В проекте должна поддерживаться одна структура папок для контекста и
спецификаций: где лежат спеки, где — контекст для агентов и людей, какие файлы
обязательны. Сейчас эта структура нигде не записана и ничем не проверяется.
Люди и агенты кладут файлы «примерно туда», появляются дубли и лишние папки,
пропадают обязательные файлы, и замечают это только на ревью или когда агент
не находит контекст.

Нужна структура, записанная в репозитории, и проверка соответствия ей. При
этом жёсткость должна задаваться по месту: в одних папках известен каждый файл,
в других зафиксирован только путь до папки, а внутри неё допустима любая
структура.

## What Changes

- **Описание структуры** — файл `openspec/structure.yaml` в репозитории. Дерево
  папок и файлов от корня проекта:
  - `имя: file` — обязательный файл;
  - `имя:` со вложенным перечнем — папка строго с перечисленным содержимым:
    всё, что в ней не описано, — нарушение;
  - `имя: "*"` — папка, внутри которой допустима любая структура (мягкая
    граница: жёстко до этой папки, дальше свободно);
  - `имя: any` — файл или папка с любым содержимым;
  - `имя?: …` — необязательный элемент;
  - ключ с `*` (`"*.md": file`, `"ADR-*": file`, `"*": "*"`) — шаблон имени:
    сколько угодно подходящих элементов, каждый проверяется по правилу.
  Корень проекта не строгий: проверяются только перечисленные на первом уровне
  элементы. Служебные файлы (`.DS_Store`, `Thumbs.db`, `.gitkeep`) не считаются
  лишними; список меняется полем `ignore`.
- **Проверка соответствия** — три вида нарушений: нет обязательного элемента,
  лишний элемент в строгой папке, не тот тип (файл вместо папки и наоборот).
  Ошибки в самом описании — неизвестное правило, путь в имени, необязательный
  шаблон — показываются с номером строки.
- **Раздел «Структура»** в панели: итог проверки, список нарушений с переходом к
  файлу или к правилу, дерево описания с отметками; если описания нет —
  создание `openspec/structure.yaml` по текущей раскладке `openspec/`.
- **VS Code**: нарушения в панели «Проблемы» — лишний файл на самом файле,
  остальное на строке правила в `structure.yaml`; команда «Проверить
  структуру папок»; проверка при активации, изменении файлов и сохранении
  описания.
- **Маршрут** `GET /api/structure` и `POST /api/structure/init`.

Не входит: автоматическое исправление структуры (перенос и создание файлов),
проверка содержимого файлов, несколько описаний структуры на проект, запуск
проверки в CI без IDE.

## Capabilities

### New Capabilities

- `structure-conformance` — описание структуры папок в `openspec/structure.yaml`,
  его разбор, проверка соответствия и раздел «Структура».

### Modified Capabilities

- `vscode-extension` — нарушения структуры в панели «Проблемы», команда
  проверки структуры, раздел «Структура» в панели.

## Impact

- **Код**: `packages/core` — разбор описания и проверка (чистые функции, без
  файловой системы); `packages/server` — чтение описания с номерами строк,
  обход файловой системы, маршруты, наблюдение за папками верхнего уровня из
  описания; `packages/web` — раздел «Структура»; `packages/vscode` —
  диагностика, команда, наблюдение за созданием и удалением файлов.
- **Файлы проекта**: новый необязательный файл `openspec/structure.yaml`. Без
  него проверка не выполняется и ничего не сообщает, кроме предложения его
  создать.
- **CLI OpenSpec**: не используется и не затрагивается.
