# Spec Delta: conformance-check

## ADDED Requirements

### Requirement: Консольная проверка проекта

Система ДОЛЖНА (SHALL) предоставлять команду `openspec-ide-check`, которая
для проекта в текущем каталоге (или в каталоге `--root`) находит корень
OpenSpec так же, как CLI, и выполняет проверки `validate`, `archived`,
`structure`, `context`, `schemas`, `authoring`, `coverage`, `drift` по тем же
правилам, что и IDE. Проверка, для которой в проекте нет исходных данных,
ДОЛЖНА пропускаться с пометкой в отчёте. Команда ДОЛЖНА принимать
`--only` и `--skip` со списком проверок через запятую.

#### Scenario: Нарушение структуры в CI

- **WHEN** в строгой папке из `openspec/structure.yaml` лежит лишний файл и выполняется `openspec-ide-check`
- **THEN** отчёт содержит ошибку проверки `structure` с путём этого файла

#### Scenario: Проверка без данных

- **WHEN** в проекте нет `openspec/structure.yaml`
- **THEN** проверка `structure` отмечена в отчёте как пропущенная, а не как пройденная с ошибкой

#### Scenario: Выбор проверок

- **WHEN** выполняется `openspec-ide-check --only structure,context`
- **THEN** выполняются только проверки `structure` и `context`

### Requirement: Формат отчёта

Команда ДОЛЖНА (SHALL) печатать отчёт в формате `--format text` (по
умолчанию: строка `путь:строка: уровень: сообщение [проверка]` на замечание,
затем итог по проверкам), `json` (замечания и итог по проверкам одним
объектом) или `github` (команды аннотаций GitHub Actions `::error`,
`::warning`, `::notice` с файлом и строкой).

#### Scenario: Аннотации GitHub

- **WHEN** выполняется `openspec-ide-check --format github`, и в дельте MODIFIED ссылается на несуществующее требование
- **THEN** печатается строка `::error file=<путь дельты>,line=<строка>,title=openspec-ide/authoring::…`

#### Scenario: JSON

- **WHEN** выполняется `openspec-ide-check --format json`
- **THEN** вывод — один JSON-объект с массивом замечаний и итогом по каждой проверке

### Requirement: Код завершения

Команда ДОЛЖНА (SHALL) завершаться с кодом 0, если нет замечаний уровня
`--fail-on` (по умолчанию `error`) и выше; с кодом 1, если есть; с кодом 2 при
ошибке запуска: неизвестная проверка или формат, нет корня OpenSpec, нет CLI
OpenSpec для выбранных проверок, которым он нужен.

#### Scenario: Только предупреждения

- **WHEN** в проекте есть непокрытый сценарий (предупреждение) и нет ошибок
- **THEN** команда завершается с кодом 0, а с `--fail-on warning` — с кодом 1

#### Scenario: Нет CLI OpenSpec

- **WHEN** CLI OpenSpec не найден и выбрана проверка `validate`
- **THEN** команда завершается с кодом 2 и называет способ установки CLI

### Requirement: Поставка одним файлом

Сборка ДОЛЖНА (SHALL) давать команду одним файлом `openspec-ide-check.mjs`,
который запускается `node openspec-ide-check.mjs` на Node 22 без установки
зависимостей; внешней зависимостью остаётся только CLI OpenSpec проекта.

#### Scenario: Запуск собранного файла

- **WHEN** собранный файл скопирован в каталог вне репозитория IDE и запущен на фикстурном проекте
- **THEN** он выполняет проверки и печатает отчёт
