# Change: проверка проекта OpenSpec для CI и pre-commit

## Why

Договорённости команды записаны в репозитории — `openspec/structure.yaml`,
карта контекста в `openspec/context/`, собственные схемы с правилами SDD,
ссылки плана на сценарии, — но проверяются только в VS Code с этим
расширением. Кто работает из терминала или другого редактора, агент в CI,
ревьюер PR — нарушений не видят, и они попадают в основную ветку.
`openspec validate` проверяет только формат спеков и changes.

## What Changes

Новая возможность `conformance-check` — консольная команда
`openspec-ide-check`, которая прогоняет те же проверки, что и IDE, и годится
для CI и pre-commit:

- **Проверки**: `validate` — `openspec validate --all --strict` (changes и
  основные спеки, со строками, как в IDE); `archived` — `openspec validate
  --archived`; `structure` — `openspec/structure.yaml`; `context` — карта
  контекста; `schemas` — правила SDD и структура собственных схем проекта;
  `authoring` — ссылки дельт на основной спек и ссылки плана; `coverage` —
  сценарии без пунктов плана; `drift` — пересечения и устаревшие дельты.
  Проверка без исходных данных (нет `structure.yaml`, нет
  `openspec/context/`, нет собственных схем) пропускается с пометкой.
- **Выбор**: `--only a,b` и `--skip a,b`.
- **Отчёт**: `--format text` (по умолчанию, `путь:строка: уровень: сообщение
  [проверка]` и итог), `json`, `github` (аннотации GitHub Actions).
- **Код завершения**: 0 — нет замечаний на уровне `--fail-on` (по умолчанию
  `error`) и выше, 1 — есть, 2 — ошибка запуска (неизвестная проверка, нет
  корня OpenSpec, нет CLI для проверок, которым он нужен).
- **Поставка**: пакет `packages/check`, сборка одним файлом
  `dist/openspec-ide-check.mjs` без зависимостей, кроме Node 22 и CLI
  OpenSpec проекта. В этом репозитории — `npm run check:openspec`.

Не входит: публикация в npm, автоматическое исправление нарушений.

## Capabilities

### New Capabilities

- `conformance-check` — консольная проверка проекта OpenSpec для CI.

### Modified Capabilities

Нет.

## Impact

- **Код**: `packages/server/src/check.ts` — сбор замечаний всех проверок через
  встроенный бэкенд (те же маршруты, что у расширения); `packages/check` —
  разбор аргументов, форматы отчёта, код завершения, сборка одним файлом;
  корневой `package.json` — скрипты сборки и `check:openspec`.
- **Тесты**: тесты сбора на фикстурах (каждая проверка находит своё
  нарушение), тесты форматов и кодов завершения, дымовой тест собранного
  файла.
