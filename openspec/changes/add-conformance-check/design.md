# Design: проверка проекта OpenSpec для CI и pre-commit

## Context

Мотивация — в `proposal.md`. Бэкенд IDE умеет работать без сокета
(`createEmbeddedBackend`): те же маршруты, что у расширения, через
`inject()`. Все проверки уже есть как маршруты: `/api/validate`,
`/api/validate/specs`, `/api/structure`, `/api/context-map`,
`/api/schema/check`, `/api/authoring`, `/api/trace`, `/api/drift`.

## Decisions

### 1. Команда — клиент встроенного бэкенда

**Решение.** `runCheck` в `packages/server/src/check.ts` поднимает встроенный
бэкенд без наблюдателя за файлами и собирает замечания из тех же маршрутов,
что показывает расширение, приводя их к одному виду
`{ check, level, file, line, message }`. Правила проверки не дублируются: CI
и IDE не могут разойтись.

**Альтернатива — вызывать сервисы напрямую.** Минует обработку ошибок и
проверки маршрутов, и каждый новый сервис пришлось бы подключать дважды.

**Альтернатива — вернуть бинарь `openspec-ide` с HTTP-сервером.** Его
упразднили вместе с web-режимом; проверке порт не нужен.

### 2. Поставка — один файл

**Решение.** esbuild собирает `packages/check/src/cli.ts` вместе с `core` и
`server` в `dist/openspec-ide-check.mjs` (ESM, Node 22). Файл можно положить в
репозиторий проекта или взять артефактом сборки; `npm install` ему не нужен.
CLI OpenSpec ищется так же, как в расширении (`OPENSPEC_CLI`,
`node_modules/.bin`, PATH, глобальные каталоги npm).

**Альтернатива — публикация пакета в npm.** Удобнее всего, но репозиторий не
публикует пакеты; добавить публикацию можно позже, не меняя команду.

### 3. Уровни и код завершения

**Решение.** Уровни — `error`, `warning`, `info`, как в панели «Проблемы».
`--fail-on error|warning|info` задаёт порог; по умолчанию `error`, чтобы
предупреждения (непокрытый сценарий, пересечение) не ломали сборку без
решения команды. Ошибка запуска — код 2, отдельно от найденных замечаний.

### 4. Формат `github`

**Решение.** Строки `::error file=…,line=…,title=openspec-ide/<проверка>::…`
— аннотации появляются на строках PR без отдельного действия. Переводы строк
в сообщении кодируются `%0A`, как требует формат.

## Risks / Trade-offs

- Проверка `drift` без истории git (клон `--depth 1` в CI) не находит базовой
  версии → работает запасной путь по архиву; в README — совет
  `fetch-depth: 0`.
- `schemas` и `validate` требуют CLI OpenSpec → без него код 2 с подсказкой,
  либо `--skip validate,archived,schemas` для проверок только по файлам.
