# Spec Delta: context-map

## ADDED Requirements

### Requirement: Коэффициент полезности контекста

Система ДОЛЖНА (SHALL) оценивать для каждого файла контекста коэффициент
полезности от 0 до 100 % как произведение плотности, множителя привязки и
множителя свежести и показывать его со знаком ≈ вместе с разбивкой.
Плотность ДОЛЖНА считаться как доля токенов файла без балласта; балластом
ДОЛЖНЫ считаться абзацы-повторы (кроме первого вхождения), заготовки
(HTML-комментарии; абзацы, которые начинаются с `TODO`, `TBD`, `FIXME`,
«заполнить», «дописать», или состоят только из `<…>` и многоточий) и абзацы
со ссылкой на путь, которого нет; каждый абзац ДОЛЖЕН учитываться один раз.
Файл без содержимого, кроме заголовков, ДОЛЖЕН иметь коэффициент 0.
Множитель привязки ДОЛЖЕН применяться только к `context.md` модулей и равняться
0,5 + 0,5 × доля токенов содержательных абзацев с `` `кодом` `` или ссылкой.
Множитель свежести ДОЛЖЕН применяться только к `context.md` модулей с данными
git и равняться 1 / (1 + N / 10), где N — коммиты в путях кода после
последнего коммита `context.md`; незакоммиченная правка — N = 0. Полезные
токены файла — коэффициент × токены — ДОЛЖНЫ суммироваться по всему контексту,
по набору модуля и по набору из нескольких узлов. Файл от 200 токенов с
коэффициентом ниже 50 %, кроме пустого, ДОЛЖЕН давать сведение с причинами.

#### Scenario: Заготовки и повтор в контексте модуля

- **WHEN** `context.md` модуля `sds-master` содержит HTML-комментарий шаблона, абзац `TODO: описать ограничения` и абзац, дословно повторяющий общий контекст
- **THEN** у файла видны токены повторов и заготовок
- **AND** коэффициент меньше 100 %

#### Scenario: Плотный файл

- **WHEN** общий контекст не содержит повторов, заготовок и ненайденных путей
- **THEN** коэффициент файла — 100 %

#### Scenario: Отставание снижает коэффициент

- **WHEN** после последнего коммита `context.md` модуля в его путях кода сделано 10 коммитов, а балласта в файле нет и каждый абзац ссылается на код
- **THEN** коэффициент файла — 50 %

#### Scenario: Низкая полезность в CI

- **WHEN** `openspec-ide-check --only context` запущен в проекте, где `context.md` модуля в 600 токенов наполовину состоит из заготовок и не ссылается на код
- **THEN** в отчёте есть сведение о низкой полезности с токенами заготовок и привязкой к коду
- **AND** код завершения при пороге по умолчанию — 0

### Requirement: Полезность в виде «Контроль»

Вид «Контроль» раздела «Контекст» ДОЛЖЕН (SHALL) показывать карточку
«Полезность»: полезные токены и их долю во всём контексте и файлы с потерями
по убыванию потерянных токенов — с коэффициентом, токенами балласта по
причинам, привязкой и свежестью. Таблица наборов модулей ДОЛЖНА показывать
полезные токены набора и их долю. Сводка раздела и карточка модуля ДОЛЖНЫ
показывать долю полезных токенов.

#### Scenario: Файл с потерями сверху

- **WHEN** пользователь открывает вид «Контроль» в проекте, где в `context.md` модуля `sds-master` есть повтор и заготовки
- **THEN** в карточке «Полезность» этот файл виден с коэффициентом и токенами повторов и заготовок
- **AND** файлы без потерь в таблицу не входят

#### Scenario: Полезные токены набора

- **WHEN** пользователь выбирает модуль `sds-master` на карте
- **THEN** в карточке модуля видны полезные токены набора рядом с его объёмом
