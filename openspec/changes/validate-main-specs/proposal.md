# Change: проверка основных спеков и точные строки замечаний

## Why

Расширение проверяет только активные changes: `openspec validate <change>
--strict`. Основные спеки в `openspec/specs/` не проверяются вовсе, хотя их
правят руками, их меняет архивация, а CLI находит в них ошибки и
предупреждения: требование без сценария, требование без SHALL/MUST, слишком
короткое назначение. Такие замечания обнаруживаются только из терминала.

Кроме того, замечания валидации change часто ложатся на начало файла: CLI
сообщает путь `data-export/spec.md`, но не строку, хотя в тексте называет
требование — `MODIFIED "Выгрузка данных" omits scenario(s)…`. Искать это
требование в файле приходится глазами.

## What Changes

- **Проверка основных спеков**: `openspec validate --specs --strict --json`,
  замечания — в панели «Проблемы» на файле спека. Путь замечания вида
  `requirements[2]` или `requirements.2.scenarios` переводится в строку
  заголовка третьего требования, `overview` и `purpose` — в строку
  `## Purpose`.
- Проверка основных спеков выполняется при активации, при изменении файлов в
  `openspec/specs/` (в том числе после архивации) и по новой команде
  «OpenSpec: Проверить основные спеки».
- **Строка по имени требования**: если замечание валидации change называет
  требование (`MODIFIED "Имя"`, `header "### Requirement: Имя"`,
  `Requirement "Имя"`), оно ложится на строку заголовка этого требования в
  файле дельты.
- Маршрут `GET /api/validate/specs`; ревизия API — 6.

Не входит: проверка архивных changes в IDE (она есть в команде проверки для
CI, change `add-conformance-check`).

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `vscode-extension` — диагностика основных спеков, команда «Проверить
  основные спеки».
- `ide-runtime` — строка замечания валидации по имени требования и по пути
  `requirements[N]`.

## Impact

- **Код**: `packages/server/src/validation.ts` — прогон по спекам, перевод
  путей замечаний в строки; `packages/server/src/server.ts` — маршрут;
  `packages/core/src/constants.ts` — ревизия API; `packages/vscode` —
  коллекция диагностик, команда, запуск по событиям.
- **Тесты**: модульные тесты перевода путей и имён в строки, тест маршрута на
  фикстуре со сломанным спеком, дымовой тест: замечание основного спека в
  «Проблемах».
