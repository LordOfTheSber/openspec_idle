# Spec Delta: artifact-editor

## Purpose

Позволяет читать и править артефакты change — proposal, спеки, design и tasks —
прямо в IDE, со структурной подсветкой формата OpenSpec, шаблонами, живой
валидацией и безопасным сохранением поверх файлов на диске.

## ADDED Requirements

### Requirement: Редактирование артефакта change

Система ДОЛЖНА (SHALL) открывать артефакт change в текстовом редакторе markdown с
подсветкой синтаксиса, сохранять изменения в тот же файл на диске и отображать
признак несохранённых правок. Сохранение ДОЛЖНО быть атомарным: файл не остаётся
в частично записанном состоянии при сбое.

#### Scenario: Правка и сохранение

- **WHEN** пользователь меняет текст `proposal.md` и выполняет сохранение
- **THEN** новое содержимое записывается в файл на диске
- **AND** признак несохранённых правок снимается
- **AND** валидация change перезапускается

#### Scenario: Попытка закрыть вкладку с несохранёнными правками

- **WHEN** пользователь закрывает артефакт с несохранёнными изменениями
- **THEN** запрашивается подтверждение с выбором сохранить или отменить правки

#### Scenario: Файл изменён на диске во время правки

- **WHEN** файл открытого артефакта изменён вне IDE, а в редакторе есть несохранённые правки
- **THEN** сохранение блокируется
- **AND** показывается сравнение версии на диске и версии в редакторе
- **AND** пользователь выбирает, какую версию оставить

#### Scenario: Сбой записи на диск

- **WHEN** запись файла завершается ошибкой, например из-за прав доступа
- **THEN** исходный файл остаётся неизменным
- **AND** правки сохраняются в редакторе
- **AND** текст системной ошибки показывается пользователю

### Requirement: Структурная подсветка формата OpenSpec

Система ДОЛЖНА (SHALL) выделять в редакторе элементы формата OpenSpec: заголовки
дельт-операций, требования, сценарии и строки WHEN/THEN, а также отмечать
структурные нарушения непосредственно в тексте.

#### Scenario: Сценарий записан тремя решётками

- **WHEN** в спеке строка сценария начинается с трёх решёток вместо четырёх
- **THEN** строка помечается как структурная ошибка прямо в редакторе
- **AND** подсказка объясняет, что сценарий требует ровно четырёх решёток

#### Scenario: Требование без сценариев

- **WHEN** блок требования не содержит ни одного сценария
- **THEN** заголовок требования помечается предупреждением
- **AND** предлагается вставка шаблона сценария

#### Scenario: Навигация по структуре документа

- **WHEN** пользователь открывает панель структуры артефакта
- **THEN** показывается список требований и вложенных сценариев
- **AND** выбор элемента прокручивает редактор к его строке

### Requirement: Создание артефакта из шаблона

Система ДОЛЖНА (SHALL) создавать отсутствующий артефакт из шаблона схемы workflow,
полученного командой `openspec templates`, и предлагать вставку типовых блоков
требования и сценария в уже существующий артефакт.

#### Scenario: Создание отсутствующего артефакта

- **WHEN** пользователь выбирает создание артефакта design у change, где его нет
- **THEN** файл создаётся с содержимым шаблона действующей схемы
- **AND** открывается в редакторе

#### Scenario: Вставка блока требования

- **WHEN** пользователь вызывает вставку требования в спеке
- **THEN** в текущую позицию вставляется заготовка требования с одним сценарием
- **AND** курсор устанавливается на название требования

#### Scenario: Создание файла дельты для capability

- **WHEN** пользователь добавляет спек для capability, указанной в proposal
- **THEN** файл создаётся по пути `specs/<capability-path>/spec.md` внутри каталога change
- **AND** путь совпадает с указанным в секции Capabilities без переименований

### Requirement: Живая валидация артефактов

Система ДОЛЖНА (SHALL) запускать `openspec validate <change> --strict --json` после
сохранения артефакта и по явному запросу, показывая ошибки и предупреждения
списком. Каждая запись списка ДОЛЖНА вести к файлу и, если он известен, к номеру
строки.

#### Scenario: Валидация нашла ошибку

- **WHEN** после сохранения валидация сообщает об ошибке в спеке
- **THEN** панель проверок показывает уровень, текст и источник ошибки
- **AND** выбор записи открывает нужный файл и позиционирует курсор

#### Scenario: Валидация прошла без замечаний

- **WHEN** валидация завершается без ошибок и предупреждений
- **THEN** панель проверок показывает успешное состояние
- **AND** индикатор change в дереве переходит в состояние «валиден»

#### Scenario: Валидация выполняется дольше ожидаемого

- **WHEN** процесс валидации не завершился за отведённое время
- **THEN** показывается индикатор выполнения
- **AND** предыдущий результат остаётся видимым и помечен как устаревший

#### Scenario: Одновременные запросы валидации

- **WHEN** сохранение происходит, пока предыдущая валидация ещё выполняется
- **THEN** предыдущий запуск отменяется
- **AND** отображается результат последнего запуска
