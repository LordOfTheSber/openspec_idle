# Spec Delta: spec-delta-viewer

## Purpose

Показывает содержимое спеков и дельт change в структурном виде — по требованиям и
сценариям — и объясняет, что именно change меняет в основном спеке, чтобы
рецензент видел эффект предложения без ручного сравнения markdown-файлов.

## ADDED Requirements

### Requirement: Структурный просмотр спека

Система ДОЛЖНА (SHALL) отображать спек как список требований с вложенными сценариями,
используя данные `openspec show <item> --type spec --json`. Требования ДОЛЖНЫ
сворачиваться и разворачиваться, а назначение capability ДОЛЖНО быть показано
над списком.

#### Scenario: Открытие основного спека

- **WHEN** пользователь выбирает capability в дереве
- **THEN** показывается назначение capability и список её требований
- **AND** каждое требование раскрывается в свои сценарии с шагами WHEN/THEN

#### Scenario: Спек с незаполненным назначением

- **WHEN** назначение capability содержит заглушку, оставленную архивацией
- **THEN** заглушка выделяется как требующая заполнения
- **AND** предлагается переход к редактированию основного спека

### Requirement: Просмотр дельт change

Система ДОЛЖНА (SHALL) группировать требования дельты по операциям ADDED, MODIFIED,
REMOVED и RENAMED, помечая каждую группу своим цветом и подписью. Для операции
REMOVED ДОЛЖНЫ отображаться поля причины и миграции, для RENAMED — прежнее и
новое имя.

#### Scenario: Дельта со всеми видами операций

- **WHEN** спек change содержит добавленные, изменённые, удалённые и переименованные требования
- **THEN** каждая группа показана отдельной секцией со своей меткой операции
- **AND** счётчик требований выводится для каждой операции

#### Scenario: Удалённое требование без причины

- **WHEN** требование в секции REMOVED не содержит поля причины или миграции
- **THEN** требование помечается как неполное
- **AND** указывается, какое из полей отсутствует

#### Scenario: Change без дельт с явным отказом от спеков

- **WHEN** у change нет файлов спеков, а его настройки объявляют отказ от спеков
- **THEN** показывается состояние «спеки не затрагиваются» с причиной из настроек
- **AND** это не отмечается как ошибка

### Requirement: Сравнение дельты с основным спеком

Система ДОЛЖНА (SHALL) показывать для изменённого требования различие между текстом в
основном спеке и текстом в дельте на уровне требования и его сценариев.

#### Scenario: Изменённое требование

- **WHEN** пользователь открывает требование из секции MODIFIED
- **THEN** показывается сравнение прежнего и нового текста требования
- **AND** добавленные и удалённые сценарии выделены раздельно

#### Scenario: Требование не найдено в основном спеке

- **WHEN** требование секции MODIFIED отсутствует в основном спеке capability
- **THEN** показывается предупреждение о несовпадении заголовка
- **AND** предлагается список похожих заголовков из основного спека

#### Scenario: Добавленное требование

- **WHEN** пользователь открывает требование из секции ADDED
- **THEN** весь текст требования показан как добавленный
- **AND** сравнение с основным спеком не запрашивается

### Requirement: Карта связей capability и changes

Система ДОЛЖНА (SHALL) показывать для выбранной capability все активные changes,
затрагивающие её, и наоборот — для выбранного change все затрагиваемые
capability. Связи ДОЛЖНЫ строиться по путям файлов дельт.

#### Scenario: Capability под несколькими changes

- **WHEN** два активных change содержат дельты одной capability
- **THEN** карта показывает обе связи
- **AND** требования, изменяемые обоими changes, помечаются как конфликтующие

#### Scenario: Capability не затронута ни одним change

- **WHEN** ни один активный change не содержит дельт для capability
- **THEN** карта показывает capability без связей
- **AND** сообщает, что активных изменений нет

#### Scenario: Дельта указывает на несуществующую capability

- **WHEN** путь дельты не соответствует ни одному спеку в `openspec/specs/`
- **THEN** связь помечается как висячая
- **AND** предлагается создать новую capability или исправить путь
