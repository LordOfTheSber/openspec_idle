# Tasks

## 1. Каркас проекта

- [ ] 1.1 Поднять npm workspaces с пакетами `core`, `server`, `web`, `cli`, общим TypeScript в строгом режиме и общей конфигурацией сборки; проверка — `npm run build` собирает все четыре пакета без ошибок типов
- [ ] 1.2 Завести команды `npm run verify` (типы + линт + модульные тесты) и `npm run dev` (сервер и Vite одной командой); проверка — `npm run verify` проходит на пустом проекте, `npm run dev` отдаёт страницу
- [ ] 1.3 Собрать фикстурные OpenSpec-проекты для тестов: пустой, с одним change без артефактов, с полным change и с архивом; проверка — тест перечисляет фикстуры и подтверждает, что `openspec validate` на каждой даёт ожидаемый исход
- [ ] 1.4 Реализовать бинарь `openspec-ide` с разбором пути, `--port`, `--no-open` и поиском ближайшего `openspec/` вверх по дереву; проверка — тесты на запуск из подкаталога, на занятый порт (ненулевой код и внятное сообщение) и на проект без `openspec/`

## 2. Обёртка над CLI OpenSpec

- [ ] 2.1 Реализовать модуль `openspecCli`: запуск процесса, таймаут, возврат кода, разобранного JSON и исходного вывода при ошибке разбора; проверка — тесты на успешный вызов, ненулевой код и невалидный JSON, где ошибка разбора не выдаётся за результат
- [ ] 2.2 Описать схемы ответов `list`, `list --specs`, `show`, `status`, `validate`, `instructions`, `templates` и разбирать вывод через них; проверка — тесты на фикстурах сверяют разобранные структуры с реальным выводом установленной версии CLI
- [ ] 2.3 Добавить кэш результатов по времени изменения файлов change и его сброс при изменениях на диске; проверка — тест подтверждает, что повторный запрос без правок не порождает нового процесса, а правка файла кэш сбрасывает
- [ ] 2.4 Проверить отсутствие CLI OpenSpec и отдавать блокирующее состояние с названием инструмента и командой установки; проверка — тест с подменённым PATH получает это состояние вместо исключения

- [ ] 3.2 Реализовать канонизацию путей с разрешением символических ссылок и отказ в операциях вне корня; проверка — тесты на переход выше корня и на символическую ссылку наружу, оба получают отказ, файл не читается и не изменяется
- [ ] 3.3 Реализовать поток SSE с переподключением и нарастающей паузой на стороне страницы; проверка — e2e-тест обрывает поток и подтверждает показ признака отключения, восстановление и полное перечитывание состояния
- [ ] 3.4 Подключить наблюдение за `openspec/` с объединением событий в одном окне; проверка — тест на пакетное изменение десятков файлов даёт одно обновление, тест на внешнюю правку файла — обновление в пределах двух секунд
- [ ] 3.5 Реализовать чтение и запись `.openspec-ide/config.json` с сохранением нераспознанных полей и отказом записывать значения секретов; проверка — тесты на отсутствующий файл, на сохранение неизвестного поля при перезаписи и на отклонение записи секрета

- [ ] 4.3 Реализовать индикаторы состояния артефактов и прогресс задач в дереве; проверка — тесты на артефакт «отсутствует», артефакт с ошибкой валидации и прогресс `4/11` на фикстуре

- [ ] 5.2 Реализовать атомарное сохранение через запись во временный файл с переименованием и определение внешнего изменения файла; проверка — тесты на сбой записи (исходный файл не изменился, правки в редакторе целы) и на расхождение с диском (сохранение блокируется, показывается сравнение)
- [ ] 5.3 Реализовать панель структуры документа с переходом к строке требования и сценария; проверка — e2e-тест выбирает элемент структуры и подтверждает позицию курсора в редакторе
- [ ] 5.4 Реализовать создание артефакта из шаблона схемы и вставку блоков требования и сценария; проверка — тест создаёт отсутствующий `design.md` и сверяет его с выводом `openspec templates`
- [ ] 5.5 Реализовать панель проверок по выводу `validate --strict --json` с отменой предыдущего запуска и переходом к источнику ошибки; проверка — тесты на отмену при двойном сохранении и на переход по записи в нужный файл и строку
