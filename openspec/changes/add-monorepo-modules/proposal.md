# Change: модули монорепозитория

## Why

Типичный репозиторий команды — монорепо: пять микросервисов, UI и КМ из
четырёх библиотек, от которых зависят сервисы и UI. Спеки ведутся в одном
корневом `openspec/`, capability сгруппированы по модулям путями
(`specs/billing/…`, `specs/ui/…`, `specs/km/core/…`).

IDE об этой структуре не знает:

- дерево спеков — плоская иерархия путей; где кончается один сервис и
  начинается другой, пользователь держит в голове;
- доска и поиск показывают всё сразу, отфильтровать работу одного сервиса
  нельзя;
- change в библиотеке КМ задевает всех её потребителей, но это нигде не видно:
  кто зависит от библиотеки, известно только из манифестов сборки;
- сквозной change, который меняет и библиотеку, и сервисы, выглядит так же,
  как change одного модуля, и нигде не показано, какие модули он затрагивает.

## What Changes

- Карта модулей `openspec/modules.yaml` в git рядом со спеками. Модуль: вид
  (сервис, UI, библиотека), каталог кода, префикс путей capability, группа,
  зависимости от других модулей.
- Обнаружение модулей по манифестам сборки (`package.json`, `pom.xml`,
  `build.gradle`, `go.mod`, `*.csproj`, `pyproject.toml`), включая зависимости
  между ними. Результат — черновик карты, который пользователь правит и
  сохраняет.
- Принадлежность модулям: capability — по префиксу пути, change — по путям
  его дельт и по явному списку модулей в `.openspec.yaml` change.
- Дерево, доска, поиск и метрики — с группировкой и фильтром по модулю.
- Граф модулей: зависимости, активные changes. Change в библиотеке
  подсвечивает всех затронутых потребителей, в том числе через цепочку
  зависимостей.
- Сквозные changes: создание change с выбором модулей, дельты по модулям,
  отметка «сквозной» на карточке и в дереве.

## Capabilities

### New Capabilities

- `monorepo-modules`: карта модулей, их обнаружение, принадлежность спеков и
  changes модулям, фильтры, граф зависимостей и сквозные changes.

### Modified Capabilities

Нет. Разделы из `add-openspec-ide` получают фильтр и группировку по модулю,
только когда карта модулей задана. Без неё поведение прежнее.

## Impact

- `packages/core`: модель карты модулей, сопоставление путей модулям, граф
  зависимостей и затронутые потребители.
- `packages/server`: чтение и запись `openspec/modules.yaml`, обнаружение по
  манифестам, модули в ответах API дерева, доски, поиска и метрик.
- `packages/web`: раздел «Модули» (карта и граф), фильтр по модулю в разделах,
  выбор модулей при создании change.
- Формат `.openspec.yaml` change дополняется необязательным ключом `modules`.
  CLI OpenSpec 1.13 его пропускает — проверено на `status`, `validate` и
  `archive`.
