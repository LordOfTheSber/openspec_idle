# Change: раздел «Качество» и исключения правил

## Why

Замечания проверки качества (`add-spec-quality`) и согласованности
(`add-spec-consistency`) видны только в «Проблемах» VS Code и в CI —
построчно, без сводки. Нельзя увидеть метрики проекта, какие спеки хуже
всех, какое правило шумит, и нельзя из интерфейса ни выключить правило, ни
исключить его там, где замечание осознанно принято: только правкой
`quality.yaml` вручную, а исключений по файлам и требованиям нет вовсе —
правило выключалось целиком. Макеты — `docs/mockups/spec-quality.html`.

## What Changes

- **Раздел «Качество»** в панели: плитки метрик с порогами, фильтр по уровню,
  «по файлам / по правилам», поиск, «только активные changes»; правила по
  группам со счётчиками; файлы по убыванию предупреждений с метриками;
  замечания файла по требованиям с переходом к строке. Команда «OpenSpec:
  Качество спеков».
- **Уровень правила из интерфейса**: карточка правила с описанием и выбором
  «по умолчанию / ошибка / предупреждение / сведение / выключено» — запись в
  `rules` файла `openspec/quality.yaml` с сохранением комментариев.
- **Исключения правил** — ключ `exclude` в `quality.yaml`: правило (или все),
  путь (файл, каталог, шаблон `*`/`**`/`?`), требование, причина. Исключённое
  не попадает в «Проблемы» и CI; файл, исключённый целиком, — в метрики.
  Исключить можно прямо из строки замечания (в требовании или во всём
  файле, с причиной); список исключений со счётчиком снятого и «Снять»;
  флажок «исключённые (N)».
- **Пороги и настройки**: плашка невыполненного порога, ошибки настроек со
  строками, «Создать quality.yaml» из заготовки, пустое состояние.
- **Подсказка «нашлось в другом модуле»** у `code-message`: файл и модуль
  карты контекста, где цитата есть.
- **Доска и дерево**: чип «качество N» на карточке, блок «Качество» в деталях
  change с переходом в раздел, ограниченный change; «⚠ N» у change и
  основных спеков в дереве VS Code.

Не входит: сравнение с ревизией git (`--baseline`) в панели — остаётся в CLI;
комментарии-исключения внутри спеков.

## Capabilities

### New Capabilities

- `quality-view` — раздел «Качество», уровни и исключения правил, отметки
  качества на доске и в дереве.

### Modified Capabilities

Нет.

## Impact

- **Код**: `packages/core/src/specQuality.ts` — `exclusions`, `applyExclusions`,
  `pathMatches`, требование у замечания, каталог `QUALITY_RULE_INFO`;
  `packages/core/src/qualityOverview.ts` — сводка раздела;
  `packages/core/src/specQualityConfig.ts` — ключ `exclude`;
  `packages/core/src/specConsistency.ts` — подсказка о другом модуле;
  `packages/server/src/quality.ts` — правка `quality.yaml`, заготовка;
  маршруты `GET /api/quality`, `POST /api/quality/init`,
  `POST /api/quality/rule`, `POST|DELETE /api/quality/exclusions`;
  `packages/web/src/components/Quality.tsx`, `Board.tsx`, `ChangeDetail.tsx`,
  `App.tsx`; `packages/vscode` — команда, раздел панели, счётчик в дереве.
- **API**: новые маршруты; ревизия API — 12.
- **Файлы проекта**: необязательный ключ `exclude` в `openspec/quality.yaml`.
