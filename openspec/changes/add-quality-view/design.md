# Design: раздел «Качество» и исключения правил

## Context

Мотивация — в `proposal.md`, требования — в дельте `specs/quality-view`,
макеты — `docs/mockups/spec-quality.html`. Строится поверх
`add-spec-quality` и `add-spec-consistency`: правила, отчёт `specQuality`,
проектные проверки по диску и настройки `openspec/quality.yaml` уже есть.

## Decisions

### 1. Сводка считается в `core`, сервер только собирает данные

**Решение.** `qualityOverview(sources, report, project)` — чистая функция:
правила с действующим уровнем и счётчиками, файлы с видом (спек, дельта,
артефакт, настройки, файл проекта) и метриками, changes, невыполненные пороги,
исключённые замечания. Маршрут `GET /api/quality` вызывает её над
`/api/authoring` и проектными проверками; каждая правка настроек отвечает
новой сводкой — интерфейс не делает второго запроса.

**Альтернатива — считать сводку в интерфейсе из `/api/authoring`.** Тогда
`web` тянул бы проверки по диску отдельным запросом и дублировал логику,
которую уже видит CI.

### 2. Исключения — в `quality.yaml`, а не комментариями в спеках

**Решение.** `exclude: [{ rule, path, requirement, reason }]`: `rule` пусто —
все правила, `path` — файл, каталог со всем содержимым или шаблон (`*` — в
пределах сегмента, `**` — любые каталоги, `?` — один символ), `requirement`
— точное имя требования. Замечание несёт имя требования (`requirement`), если
оно известно; исключение ищется первым подходящим, его номер хранится у
снятого замечания. Ошибки настроек не исключаются. Файл без `rule` и
`requirement` исключён целиком: его счётчики не входят в метрики и пороги,
иначе «старые спеки» тянули бы порог вниз. Исключение по одному правилу
метрик не меняет: метрика — свойство текста, а не замечаний.

**Альтернатива — `<!-- quality-ignore vague-wording -->` в спеке.**
Ближе к месту, но засоряет спеку служебной разметкой, которую читает агент,
и не даёт одного списка исключений с причинами для ревью.

### 3. Правка `quality.yaml` с сохранением комментариев

**Решение.** Сервер правит файл через `Document` пакета `yaml`: `setIn` /
`deleteIn` для `rules`, добавление и удаление элементов `exclude`;
комментарии и порядок ключей сохраняются. Нет файла — правка начинается с
заготовки (та же, что у «Создать quality.yaml»). Файл не разбирается — отказ
409 с просьбой исправить вручную: перезапись сломанного файла потеряла бы
правку пользователя. Строки элементов списков (`exclude`, `artifacts`) теперь
тоже известны — ошибки и переходы ведут на строку исключения.

**Альтернатива — переписывать файл целиком из модели.** Проще, но теряет
комментарии и форматирование, которые команда пишет руками.

### 4. «Нашлось в другом модуле» — по коду всех модулей карты

**Решение.** Для `code-message` сервер собирает код всех модулей карты
контекста (тот же обход `code_paths`, кэш по пути) и, если цитаты нет в
модулях домена, ищет её в остальных; находка — в тексте замечания с файлом и
модулем.

**Альтернатива — поиск по всему репозиторию.** Находит больше, но медленно
на больших проектах и смешивает продуктовый код с тестами, документацией и
сборками; модули карты — то, что команда сама назвала кодом.

### 5. Отметки на доске и в дереве — только ошибки и предупреждения

**Решение.** Чип «качество N» на карточке и «⚠ N» в дереве считают ошибки и
предупреждения; сведения видны в разделе и в панели деталей. Дерево
пересчитывается вместе с диагностикой качества (по набору), доска — после
загрузки (как отчёт о пересечениях, чтобы не задерживать карточки).
Архивацию качество не блокирует.

**Альтернатива — считать и сведения.** У этого репозитория сведений 68 —
отметка была бы почти на каждом узле и перестала бы что-то значить.

### 6. Раскладка

**Решение.** Как в макетах: шире 760 px — список правил слева, таблица
файлов справа; выбранный файл открывается справа от таблицы, а список правил
скрывается. Уже — плитки 2×2, файлы карточками, правила — в режиме «по
правилам», замечания файла — вместо списка. Исключение добавляется формой
прямо в строке замечания: «в требовании / во всём файле», причина,
«Исключить».

**Альтернатива — модальное окно исключения.** Отрывает от контекста
замечания и требует второго щелчка.

**Замер на этом репозитории.** Раздел показывает 51 предупреждение и 68
сведений в 42 файлах, плитки — 26 % ветвлений, 31 % границ, 0,08
расплывчатых слов на 100. Сводка вместе с проектными проверками строится
≈ 0,5 с. Исключений в `openspec/quality.yaml` этого репозитория нет.

## Risks / Trade-offs

- Исключение по имени требования теряет силу при переименовании требования —
  замечание вернётся, и это заметно.
- Шаблон пути без `*` — префикс каталога: `openspec/specs/legacy` исключает и
  `legacy/billing/spec.md`, но не `legacy-2/`.
- Проектные проверки (код модулей) пересчитываются при изменении файлов
  `openspec/`; правка только кода видна после следующего перечитывания.
