# Design: артефакты создаются агентом, а не пустыми

## Context

Мотивация — в `proposal.md`, требования — в дельтах `specs/`.

Исходное состояние:

- `PromptBuilder` собирает промпт запуска по артефакту из
  `openspec instructions <artifact> --change <name> --json`: описание,
  инструкция схемы, путь файла, зависимости, правила проекта, шаблон.
- Цель запуска — `{ kind: 'artifact', artifact }` или `{ kind: 'item', key }`;
  маршруты `/api/agent/prompt` и `/api/agent/run` собирают промпт заново по
  цели, запуск получает текст после правки пользователем.
- Раздел «Агент» принимает только пункт плана, с которым его открыли из
  метрик.
- Создание артефакта по шаблону: `POST /api/artifact`, в VS Code — модальное
  «Создать» из дерева.

## Decisions

### 1. Замысел — часть цели запуска по артефакту

**Решение.** Цель по артефакту получает необязательное поле
`brief` — текст автора, обрезанный по краям и ограниченный 4000 символами.
`PromptBuilder` добавляет его разделом «Замысел автора» сразу после описания
артефакта, до инструкции схемы. Так замысел одинаково попадает в промпт при
сборке для подтверждения и при запуске, и сохраняется в журнале вместе с целью.

**Альтернатива — отдельный параметр маршрутов рядом с целью.** Пришлось бы
протаскивать его через оба маршрута и запись запуска отдельно, а забытый в
одном месте параметр дал бы промпт без замысла при запуске.

**Альтернатива — дописывать замысел в текст промпта в интерфейсе.** Работает
только в веб-интерфейсе; расширение и тесты сервера о нём бы не знали.

### 2. Генерация ведёт в раздел «Агент», а не запускает агента сразу

**Решение.** «Сгенерировать агентом» открывает раздел «Агент» с выбранным
артефактом и замыслом: промпт собран, режим и бюджет видны, запуск — одной
кнопкой. Агент меняет файлы и тратит токены, а в `yolo` ещё и выполняет
команды; решение запускать остаётся за человеком, как и в остальных запусках.

**Альтернатива — запуск без подтверждения.** Быстрее на один щелчок, но в обход
существующего требования показывать промпт до запуска и согласия для `yolo`.

### 3. Режим для генерации

Если в настройках стоит `plan` или `default`, для запуска по артефакту,
открытого через «Сгенерировать агентом», в окне подтверждения предлагается
`auto-edit` с пояснением, почему: в неинтерактивном запуске `default`
отклоняет правку файлов, а `plan` её не делает вовсе. Режимы `auto-edit`,
`auto` и `yolo` из настроек сохраняются как есть. Настройки при этом не
меняются — это выбор для одного запуска.

**Альтернатива — всегда `yolo`.** Даёт агенту выполнять команды без
контроля — несоразмерно задаче «написать один файл».

### 4. Навигация к агенту из VS Code

Сообщение `navigate` получает необязательное поле `agent`:
`{ artifact, brief }`. Панель открывает раздел «Агент» для change из выбора и
сразу собирает промпт этой цели. Поле проверяется разбором протокола, как и
остальные: строка артефакта без `/` и `..`, замысел — строка до 4000 символов.

### 5. Первый артефакт при создании change

После создания change с замыслом генерация предлагается для первого артефакта
схемы в порядке зависимостей — того же, в колонке которого карточка появится
на доске. Берётся из колонки карточки на доске и из дерева в VS Code, без
отдельного запроса.

## Risks / Trade-offs

- **Агент не настроен** → раздел «Агент» уже показывает блокировку с причиной и
  ссылкой на настройки; «Сгенерировать агентом» ведёт туда же, а не прячется.
- **Длинный замысел раздувает промпт** → ограничение 4000 символов; больше —
  это уже артефакт, а не замысел.
