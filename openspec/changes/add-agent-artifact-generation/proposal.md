# Change: артефакты создаются агентом, а не пустыми

## Why

Сейчас отсутствующий артефакт — proposal, спек, design, tasks — создаётся только
из шаблона схемы: в файле оказываются заголовки и заглушки, а содержание
пользователь пишет сам. При этом в IDE уже есть мост к агенту на GigaCode CLI,
который умеет писать артефакт по инструкции схемы (`openspec instructions`), но
добраться до него можно только из раздела «Агент»: выбрать change, выбрать
артефакт, поменять режим подтверждения. От места, где артефакт создают, —
дерева VS Code, доски, встроенного редактора — к агенту пути нет.

Вторая проблема — у агента нет исходных данных. Для proposal инструкция схемы
говорит «опиши мотивацию и изменения», но о чём change, знает только автор;
промпт этого не содержит. А режим подтверждения по умолчанию (`default`) в
неинтерактивном запуске отклоняет правку файлов — агент отработает, но файла не
будет.

## What Changes

- **Замысел автора в промпте.** Запуск по артефакту принимает необязательный
  текст «что должно получиться»; он попадает в промпт отдельным разделом рядом с
  инструкцией схемы.
- **Выбор способа создания артефакта.** Везде, где создаётся отсутствующий
  артефакт — дерево VS Code, панель деталей change на доске, встроенный
  редактор, — предлагается «Сгенерировать агентом» наравне с «Пустой по
  шаблону». Генерация открывает раздел «Агент» с уже выбранным артефактом и
  замыслом: пользователь видит промпт, режим и бюджет и запускает.
- **Режим, позволяющий писать файлы.** Если настроенный режим — `plan` или
  `default`, для генерации артефакта предлагается `auto-edit` с пояснением;
  `yolo` по-прежнему только с явным согласием.
- **Замысел при создании change.** Форма создания change на доске и команда
  «Создать change» в VS Code принимают описание замысла и предлагают сразу
  сгенерировать первый артефакт схемы агентом.

Не входит: автоматический запуск без подтверждения, генерация нескольких
артефактов подряд одной кнопкой, собственный LLM-клиент в IDE — агент
по-прежнему только GigaCode CLI.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `agent-bridge` — замысел автора в промпте запуска по артефакту; режим
  подтверждения для генерации артефакта.
- `artifact-editor` — выбор способа создания отсутствующего артефакта: шаблон
  или агент.
- `workflow-board` — замысел при создании change и генерация артефакта из
  панели деталей change.
- `vscode-extension` — генерация артефакта агентом из дерева и из команды
  создания change; навигация панели к разделу «Агент» с выбранным артефактом.

## Impact

- **Код**: `packages/server` — необязательный замысел в цели запуска и в
  сборке промпта; `packages/core` — поле навигации к агенту в протоколе панели;
  `packages/web` — раздел «Агент» принимает артефакт и замысел, доска и
  редактор получают «Сгенерировать агентом»; `packages/vscode` — выбор способа
  создания артефакта, замысел в команде создания change.
- **Агент**: тот же запуск GigaCode CLI с теми же бюджетами, журналом и
  метриками; меняется только промпт и выбор режима по умолчанию для генерации.
- **Данные**: замысел хранится в журнале запуска вместе с промптом, в файлы
  проекта отдельно не пишется.
