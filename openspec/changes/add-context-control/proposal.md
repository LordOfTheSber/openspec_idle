# Change: контроль контекста — объём, лишнее и связь с реальностью

## Why

Карта контекста проверяет, что ссылки между модулями, доменами и ADR
указывают на существующее. Но агенту вредит не только битая ссылка:

- **Объём.** Набор контекста модуля легко разрастается: общий контекст,
  зависимости по `depends_on`, спеки их доменов, ADR. Сколько это токенов,
  сейчас не видно ни в карточке модуля, ни в наборе, — переполнение окна
  обнаруживается, когда агент уже начал забывать начало.
- **Лишнее.** Один и тот же абзац, скопированный в общий контекст и в
  `context.md` модуля, попадает в набор дважды и со временем расходится;
  пустой `context.md` ничего не даёт, но выглядит как описанный модуль; файлы
  рядом с `index.md`, которые не входят ни в один набор, создают ложное
  ощущение, что агент их видит; отменённый ADR попадает в набор наравне с
  действующими и уводит агента к старому решению.
- **Связь с реальностью.** Контекст описывает код словами и путями. Пути
  устаревают при переименованиях, а сам `context.md` — когда код модуля
  меняется, а описание нет. Сейчас это видно только при чтении.

## What Changes

- **Объём**: оценка токенов (≈) и строк каждого файла контекста — общего
  контекста, `context.md`, спек доменов, ADR; сумма по набору модуля и по
  набору из нескольких узлов. Поле `max_tokens` в `index.md` задаёт бюджет
  набора модуля; превышение — предупреждение на строке поля. Файл тяжелее
  8000 токенов — предупреждение.
- **Лишнее**: предупреждения о повторяющихся абзацах в общем контексте,
  `context.md` и ADR (с местом первого вхождения), о пустом `context.md`, о
  файлах в `openspec/context/`, которые не входят ни в один набор. ADR со
  статусом `superseded`, `deprecated`, `rejected` (и русскими аналогами) по
  умолчанию не входит в набор; флажок в панели набора возвращает их.
- **Связь с реальностью**: ссылки `[текст](путь)` и пути в `` `коде` `` в
  общем контексте, `context.md` и ADR проверяются на существование — от
  файла, от корня проекта и от путей кода модуля; ненайденный путь —
  предупреждение со строкой. По git: сколько коммитов в путях кода модуля
  сделано после последней правки его `context.md` — сведение «контекст
  отстаёт от кода». Модуль без `code_paths` — сведение «не привязан к коду».
- **Раздел «Контекст»**: третий вид «Контроль» — объём по файлам и наборам
  модулей с бюджетом, лишнее, связь с реальностью; оценка токенов в карточке
  модуля, в наборе и в сводке раздела.
- Новые замечания — в панели «Проблемы» VS Code (сведения — уровнем
  Information) и в проверке `context` команды `openspec-ide-check`.
- Контекст самого репозитория в `openspec/context/`: общий контекст, модули
  `core`, `server`, `web`, `vscode`, `check` с бюджетами, ADR ключевых решений;
  правило для папки в `openspec/structure.yaml`.
- Макеты — `docs/mockups/context-control.html`.
- Навык `context-fill` для агентов (`.claude/skills/`, `.agents/skills/`):
  правила и промпты заполнения, обновления и сжатия контекста.

Не входит: точный подсчёт токенов токенизатором конкретной модели, проверка
идентификаторов кода (классов, функций), упомянутых в тексте, автоматическое
исправление.

### Modified Capabilities

- `context-map` — контроль объёма, лишнего и связи контекста с кодом;
  отменённые ADR по умолчанию вне набора.

## Impact

- **Код**: `packages/core/src/contextControl.ts` — оценка токенов, ссылки,
  дубли (чистые функции); `packages/core/src/contextMap.ts` — размеры,
  замечания, бюджет, ADR вне набора; `packages/server/src/contextMap.ts` —
  чтение текстов, проверка ссылок, свежесть по git, `git.ts` — новые
  запросы истории; `packages/web` — вид «Контроль», токены в наборе и
  карточке; `packages/vscode` — уровень Information.
- **API**: `GET /api/context-map` отдаёт новые поля (`files`, `duplicates`,
  `references`, у модулей `maxTokens` и `freshness`, у ADR `active`);
  прежние поля не меняются; ревизия API — 9.
- **Файлы проекта**: необязательное поле `max_tokens` в `index.md` модуля.
