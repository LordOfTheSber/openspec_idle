# Design: контроль контекста

## Context

Мотивация — в `proposal.md`, требования — в дельте `specs/context-map`.
Макеты: `docs/mockups/context-control.html` — вид «Контроль» на контексте
этого репозитория и на примере с находками, карточка модуля, набор, узкая
панель.
Карта контекста строится чистой функцией `buildContextMap` в `core` по тому,
что прочитал сервер; новые проверки встраиваются в тот же путь, чтобы
замечания сами доходили до раздела, панели «Проблемы» и `openspec-ide-check`.

## Decisions

### 1. Оценка токенов эвристикой

**Решение.** Токены оцениваются по символам: латиница, цифры, пробелы и
знаки — 4 символа на токен, остальные (кириллица и прочее) — 2,5 символа на
токен; сумма округляется вверх. В интерфейсе оценка всегда со знаком ≈.

**Альтернатива — токенизатор модели** (tiktoken, словарь Claude). Точнее, но
это десятки мегабайт словаря в расширении, привязка к одной модели и
расхождение с той, которой реально пользуется команда. Для решения «влезает /
не влезает, что тяжелее всего» точности ±25 % хватает.

### 2. Новые проверки — замечания карты

**Решение.** Объём, лишнее и связь с реальностью — новые виды `ContextIssue`
(`large-file`, `over-budget`, `duplicate-text`, `empty-context`,
`unused-file`, `broken-reference`, `stale-context`, `no-code-paths`) и новые
поля карты (`files`, `duplicates`, `references`, `freshness` модуля). У
`ContextIssue` появляется уровень `info` — для того, что не ошибка, но
стоит знать (отставание от кода, модуль без кода).

**Альтернатива — отдельный маршрут `/api/context-health`.** Разделил бы
дорогие запросы git и дешёвую карту, но тогда VS Code и CI должны были бы
собирать замечания из двух мест, а вид «Контроль» — сопоставлять два ответа.

### 3. Где ищется путь из текста

**Решение.** Ссылка считается найденной, если путь существует относительно
файла (как в markdown), относительно корня проекта или относительно одного
из путей кода модуля (для `context.md`). Из `` `кода` `` берутся только
строки с `/`, без пробелов и шаблонов (`*`, `<…>`, `{…}`), оканчивающиеся
расширением или `/`, и не абсолютные: `I/O`, `/api/context-map`,
`openspec/context/modules/<папка>/` путями не считаются. Блоки кода
пропускаются: там чаще пример, чем ссылка.

**Альтернатива — проверять любой `` `код` `` со слешем.** Больше находок,
но маршруты API, дроби и шаблоны дали бы шум, который приучит игнорировать
замечания.

### 4. Свежесть по git, а не по времени файлов

**Решение.** Последний коммит `context.md` → `git rev-list --count
<коммит>..HEAD -- <пути кода>`. Число коммитов, а не дни: модуль, который не
трогали год, не устаревает сам по себе. Незакоммиченная правка `context.md`
— свежий контекст. Отставание — сведение, а не предупреждение: любой коммит в
код формально делает описание «старше», решать, нужна ли правка, человеку.
Без git — нет данных и нет замечаний.

**Альтернатива — время изменения файлов.** Работает без git, но после
`git clone` или переключения веток у всех файлов одно время, и сравнение
теряет смысл.

### 5. Повторы — по абзацам

**Решение.** Абзац — блок между пустыми строками без заголовков и блоков
кода; сравнение после схлопывания пробелов и приведения к нижнему регистру;
учитываются абзацы от 80 символов. Ищется в общем контексте, `context.md` и
ADR — то, что пишут люди; в спеках повторяющиеся формулировки сценариев —
норма OpenSpec. Замечание ставится на каждый повтор, кроме первого вхождения в
порядке набора (общий контекст, модули, ADR).

**Альтернатива — поиск похожих фрагментов (шинглы, расстояние).** Ловил бы
слегка изменённые копии, но порог похожести придётся подбирать, а ложные
совпадения в коротких документах неизбежны.

### 6. Недействующие ADR вне набора по умолчанию

**Решение.** `contextBundle` по умолчанию пропускает ADR со статусом
`superseded`, `deprecated`, `rejected`, `obsolete` (и русскими аналогами) и
возвращает их списком `skippedAdrs`; параметр `inactiveAdrs` включает их.

**Альтернатива — только предупреждать.** Тогда каждый набор нужно чистить
вручную, а агент, получив старое и новое решения, не всегда выберет новое.

## Risks / Trade-offs

- Запросы git добавляют время сборке карты: по три вызова на модуль с
  `context.md` и путями кода, параллельно. При сотнях модулей это заметно;
  кэш по `HEAD` можно добавить отдельно.
- Порог «тяжёлого файла» (8000 токенов) и длина абзаца для повторов —
  константы. Настройка — отдельное решение, когда появится запрос.
