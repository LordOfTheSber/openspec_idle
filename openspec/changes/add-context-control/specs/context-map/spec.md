# Spec Delta: context-map

## ADDED Requirements

### Requirement: Объём контекста

Система ДОЛЖНА (SHALL) оценивать объём каждого файла контекста — общего
контекста, `context.md` модулей, спек доменов и ADR — в строках и токенах
(оценка помечается знаком ≈) и показывать сумму по набору контекста модуля и по
набору из нескольких узлов. Поле `max_tokens` в frontmatter `index.md` ДОЛЖНО
задавать бюджет набора модуля: набор больше бюджета ДОЛЖЕН давать
предупреждение на строке поля. Файл контекста больше 8000 токенов ДОЛЖЕН давать
предупреждение. Значение `max_tokens`, не являющееся положительным целым,
ДОЛЖНО давать ошибку поля.

#### Scenario: Сумма набора модуля

- **WHEN** пользователь выбирает модуль `sds-master` на карте
- **THEN** в карточке у каждого файла набора видна оценка токенов
- **AND** видна сумма по набору

#### Scenario: Набор больше бюджета

- **WHEN** в `index.md` модуля задано `max_tokens: 100`, а его набор оценивается в 1500 токенов
- **THEN** сообщается предупреждение на строке поля `max_tokens` с оценкой и бюджетом

#### Scenario: Бюджет не число

- **WHEN** в `index.md` задано `max_tokens: много`
- **THEN** сообщается ошибка поля на строке `max_tokens`

### Requirement: Лишнее в контексте

Система ДОЛЖНА (SHALL) сообщать предупреждения о том, что занимает место в
контексте без пользы: абзац длиной от 80 символов, повторяющийся в общем
контексте, `context.md` модулей и ADR (на каждом повторе, со ссылкой на первое
вхождение); `context.md` без содержимого, кроме заголовков; файл в
`openspec/context/`, который не входит ни в один набор (не общий `*.md`, не
`index.md` или `context.md` модуля, не ADR). Блоки кода и заголовки в поиске
повторов НЕ ДОЛЖНЫ учитываться.

#### Scenario: Абзац скопирован в модуль

- **WHEN** абзац общего контекста `openspec/context/1.md` дословно (с точностью до пробелов и регистра) повторён в `context.md` модуля
- **THEN** сообщается предупреждение на строке повтора в `context.md` со ссылкой на `openspec/context/1.md` и строку первого вхождения

#### Scenario: Пустой контекст модуля

- **WHEN** `context.md` модуля содержит только заголовок `# Контекст sds-impl`
- **THEN** сообщается предупреждение о пустом контексте модуля

#### Scenario: Файл вне наборов

- **WHEN** в папке модуля рядом с `index.md` и `context.md` лежит `notes.md`
- **THEN** сообщается предупреждение, что файл не входит ни в один набор

### Requirement: Отменённые ADR вне набора

ADR со статусом `superseded`, `deprecated`, `rejected`, `obsolete` или их
русскими аналогами («заменён», «отменён», «отклонён», «устарел») ДОЛЖЕН
(SHALL) считаться недействующим: по умолчанию он НЕ ДОЛЖЕН входить в набор
контекста, а панель набора ДОЛЖНА называть пропущенные ADR и давать флажок,
который включает их в набор. Явно выбранный в набор ADR ДОЛЖЕН входить в
него независимо от статуса. На карте недействующий ADR ДОЛЖЕН оставаться
видимым.

#### Scenario: Заменённое решение

- **WHEN** ADR модуля `sds-master` имеет `status: superseded`
- **THEN** в наборе модуля `sds-master` этого ADR нет
- **AND** панель набора называет его среди пропущенных

#### Scenario: Флажок возвращает ADR

- **WHEN** пользователь включает флажок «недействующие ADR» в панели набора
- **THEN** недействующий ADR входит в набор

### Requirement: Связь контекста с реальностью

Система ДОЛЖНА (SHALL) проверять пути, на которые ссылаются общий контекст,
`context.md` и ADR: цели ссылок `[текст](путь)` (кроме внешних адресов и
якорей) и пути в `` `коде` ``, содержащие `/` и оканчивающиеся расширением
файла или `/`. Путь ДОЛЖЕН считаться найденным, если он существует
относительно файла, корня проекта или одного из путей кода модуля; иначе
ДОЛЖНО сообщаться предупреждение со строкой ссылки. Блоки кода НЕ ДОЛЖНЫ
проверяться. Если проект в git, система ДОЛЖНА считать коммиты в путях кода
модуля после последнего коммита его `context.md` и при ненулевом числе
сообщать сведение «контекст отстаёт от кода»; незакоммиченная правка
`context.md` ДОЛЖНА считаться свежей. Модуль без `code_paths` ДОЛЖЕН давать
сведение «модуль не привязан к коду». Без git проверка свежести НЕ ДОЛЖНА
выполняться и НЕ ДОЛЖНА давать замечаний.

#### Scenario: Файл переименован

- **WHEN** `context.md` модуля упоминает `` `src/Session.java` ``, а такого файла нет ни от корня, ни от путей кода модуля
- **THEN** сообщается предупреждение «путь не найден» на строке упоминания

#### Scenario: Путь от кода модуля

- **WHEN** `context.md` модуля с `code_paths: [svc/src]` упоминает `` `main/App.java` ``, а файл `svc/src/main/App.java` существует
- **THEN** замечания нет

#### Scenario: Код изменился после контекста

- **WHEN** после последнего коммита `context.md` модуля в его путях кода сделано 3 коммита
- **THEN** сообщается сведение, что контекст модуля отстаёт от кода на 3 коммита
- **AND** в карточке модуля видна дата последней правки контекста

#### Scenario: Проект без git

- **WHEN** каталог проекта не в git
- **THEN** замечаний о свежести контекста нет

### Requirement: Вид «Контроль» раздела «Контекст»

Раздел «Контекст» ДОЛЖЕН (SHALL) иметь вид «Контроль» рядом с графом и
матрицей: объём — файлы контекста по убыванию оценки токенов и наборы модулей
с бюджетом; лишнее — повторы, пустые контексты, файлы вне наборов,
недействующие ADR; связь с реальностью — ненайденные пути, отставание
контекста от кода и модули без путей кода. Сводка раздела ДОЛЖНА показывать
общую оценку токенов контекста. Новые замечания ДОЛЖНЫ попадать в панель
«Проблемы» VS Code (сведения — уровнем Information) и в проверку `context`
команды `openspec-ide-check`.

#### Scenario: Самый тяжёлый файл сверху

- **WHEN** пользователь открывает вид «Контроль»
- **THEN** файлы контекста перечислены по убыванию оценки токенов с долей от общего объёма

#### Scenario: Сведение в CI

- **WHEN** `openspec-ide-check --only context` запущен в проекте, где контекст модуля отстаёт от кода
- **THEN** в отчёте есть сведение об отставании, а код завершения при пороге по умолчанию — 0
