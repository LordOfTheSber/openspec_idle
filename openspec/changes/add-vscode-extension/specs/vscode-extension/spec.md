# Spec Delta: vscode-extension

## Purpose

Определяет, как OpenSpec IDE работает внутри VS Code: когда расширение
активируется и какой корень OpenSpec выбирает, где работает бэкенд, какие части
интерфейса нативные, как панель разделов общается с бэкендом и какие гарантии
при этом действуют.

## ADDED Requirements

### Requirement: Активация и выбор корня OpenSpec

Расширение ДОЛЖНО (SHALL) активироваться, когда в рабочей области есть файл
`openspec/config.yaml` или когда пользователь вызывает любую его команду. Корнем
рабочего пространства ДОЛЖНА становиться первая по порядку папка рабочей
области, в которой или выше которой по дереву находится каталог `openspec/`;
поиск вверх ДОЛЖЕН совпадать с тем, как корень ищет CLI OpenSpec.

#### Scenario: Папка проекта с OpenSpec

- **WHEN** пользователь открывает в VS Code папку, содержащую `openspec/`
- **THEN** расширение активируется без дополнительных действий
- **AND** корнем рабочего пространства становится эта папка

#### Scenario: Открыт подкаталог проекта

- **WHEN** открыта папка, вложенная в проект, а `openspec/` находится выше по дереву
- **THEN** корнем становится каталог, содержащий `openspec/`

#### Scenario: В рабочей области нет OpenSpec

- **WHEN** ни в одной папке рабочей области и выше по дереву нет `openspec/`
- **THEN** дерево показывает приглашение с командой `openspec init`
- **AND** команды, которым нужен проект, сообщают, что проект не инициализирован, и не падают

#### Scenario: Нет CLI OpenSpec

- **WHEN** корень найден, но исполняемый файл `openspec` не найден ни в проекте, ни в PATH
- **THEN** дерево показывает сообщение с названием инструмента и командой установки
- **AND** строка состояния отмечает, что CLI недоступен

### Requirement: Бэкенд внутри процесса расширения

Бэкенд IDE ДОЛЖЕН (SHALL) работать в процессе расширения и обслуживать запросы
без сетевого сокета. Расширение НЕ ДОЛЖНО открывать ни одного порта. Все
операции над OpenSpec ДОЛЖНЫ идти через ту же обёртку над CLI, что и раньше, а
при деактивации расширения ДОЛЖНЫ останавливаться наблюдение за файлами и
запущенные процессы агента.

#### Scenario: Работа без порта

- **WHEN** расширение активировано в проекте с OpenSpec
- **THEN** запросы разделов обслуживаются бэкендом без открытия TCP-порта

#### Scenario: Закрытие окна VS Code во время запуска агента

- **WHEN** окно закрывается, пока идёт запуск агента
- **THEN** процесс агента получает сигнал остановки
- **AND** наблюдатель за файлами останавливается

### Requirement: Дерево рабочего пространства в VS Code

Расширение ДОЛЖНО (SHALL) показывать в собственном контейнере панели действий
дерево с разделами «Изменения», «Спеки», «Процессы» и «Архив», построенное по
той же модели, что и прежний обозреватель: артефакты change по его схеме,
вложенные пути capability, источник схемы. У change ДОЛЖНЫ быть видны схема,
прогресс по отслеживаемому артефакту и число ошибок, у артефакта — состояние.

#### Scenario: Change на собственной схеме

- **WHEN** change заведён по схеме с составом артефактов, отличным от встроенной
- **THEN** в дереве под ним показаны именно артефакты этой схемы

#### Scenario: Прогресс и ошибки

- **WHEN** в отслеживаемом артефакте выполнено 4 пункта из 11, а у change нет ошибок валидации
- **THEN** узел change показывает `4/11`
- **AND** при ошибках валидации вместо прогресса показывается их число

#### Scenario: Внешняя правка файла

- **WHEN** файл в `openspec/` меняется в обход расширения, например агентом или git
- **THEN** дерево обновляется без действий пользователя

### Requirement: Артефакты открываются в редакторе VS Code

Выбор артефакта, спека или проектной схемы в дереве, а также выбор артефакта,
результата поиска или затронутого файла в панели разделов ДОЛЖЕН (SHALL)
открывать соответствующий файл в обычном текстовом редакторе VS Code.
Отсутствующий артефакт ДОЛЖЕН создаваться по шаблону его схемы только по явному
действию пользователя. Путь, выходящий за пределы корня рабочего пространства,
НЕ ДОЛЖЕН открываться.

#### Scenario: Выбор существующего артефакта

- **WHEN** пользователь выбирает в дереве `proposal` change
- **THEN** в редакторе VS Code открывается `openspec/changes/<change>/proposal.md`

#### Scenario: Переход к строке из панели разделов

- **WHEN** в панели разделов выбран результат поиска по сценарию
- **THEN** файл открывается в редакторе VS Code с курсором на строке сценария

#### Scenario: Отсутствующий артефакт

- **WHEN** пользователь выбирает в дереве артефакт в состоянии «отсутствует»
- **THEN** расширение предлагает создать его по шаблону схемы
- **AND** после согласия файл создаётся через CLI OpenSpec и открывается в редакторе

#### Scenario: Путь за пределами корня

- **WHEN** панель разделов просит открыть путь `../../etc/passwd`
- **THEN** файл не открывается

### Requirement: Диагностика валидации

Замечания `openspec validate <change> --strict` ДОЛЖНЫ (SHALL) показываться в
панели «Проблемы» VS Code с уровнем, соответствующим уровню замечания, и
привязываться к файлу и строке, когда CLI их сообщает. Проверка change ДОЛЖНА
перезапускаться при изменении на диске любого его файла — в том числе при
сохранении из редактора — и по команде. Исправленные
замечания ДОЛЖНЫ исчезать после следующей проверки.

#### Scenario: Сохранение артефакта с ошибкой

- **WHEN** пользователь сохраняет спек change, где у требования нет сценария
- **THEN** в панели «Проблемы» появляется ошибка, относящаяся к этому файлу

#### Scenario: Замечание без файла

- **WHEN** CLI сообщает замечание без пути к файлу
- **THEN** оно привязывается к каталогу change и всё равно видно в панели «Проблемы»

#### Scenario: Ошибка исправлена

- **WHEN** после исправления файл сохранён и проверка прошла без ошибок
- **THEN** замечания этого change исчезают из панели «Проблемы»

### Requirement: Панель разделов

Доска, дельты, метрики, агент, процессы, настройки и поиск ДОЛЖНЫ (SHALL)
открываться в одной панели webview внутри VS Code — командой палитры или из
контекстного меню change в дереве. Панель ДОЛЖНА переиспользоваться: повторный
вызов переключает раздел и выбранный change в уже открытой панели, а не создаёт
новую. Поведение разделов ДОЛЖНО совпадать с прежней web-IDE.

#### Scenario: Метрики из контекстного меню

- **WHEN** пользователь выбирает «Метрики» в контекстном меню change
- **THEN** открывается панель с разделом «Метрики» этого change

#### Scenario: Повторный вызов

- **WHEN** панель уже открыта и пользователь вызывает команду «Доска»
- **THEN** та же панель переключается на доску, вторая панель не появляется

#### Scenario: Изменения на диске

- **WHEN** агент или пользователь меняет файлы change, пока открыта панель
- **THEN** открытый раздел перечитывает данные без действий пользователя

### Requirement: Канал сообщений панели

Панель ДОЛЖНА (SHALL) общаться с бэкендом только сообщениями webview: запрос с
идентификатором, методом, путём API и телом, и ответ с тем же идентификатором,
кодом и телом. Коды и тела ответов ДОЛЖНЫ совпадать с HTTP-режимом бэкенда,
чтобы разделы не различали транспорт. События бэкенда — изменения файлов, ход
запуска агента — ДОЛЖНЫ доставляться в панель сообщениями того же канала.
Сообщение неизвестного вида ДОЛЖНО отклоняться, а запрос к пути вне `/api/` —
получать отказ.

#### Scenario: Конфликт записи

- **WHEN** панель сохраняет файл, изменившийся на диске после чтения
- **THEN** ответ приходит с кодом 409 и версией с диска, как в HTTP-режиме

#### Scenario: Ход запуска агента

- **WHEN** в панели запущен агент
- **THEN** события его хода приходят в панель по мере появления, без опроса

#### Scenario: Запрос вне API

- **WHEN** панель присылает запрос к пути `/` или `/etc/passwd`
- **THEN** бэкенд не вызывается, панель получает отказ

### Requirement: Безопасность панели

Панель ДОЛЖНА (SHALL) загружать скрипты и стили только из каталога собранного
интерфейса внутри расширения, по политике Content-Security-Policy с одноразовым
nonce для скриптов и без доступа к сети. Ключи и значения секретов НЕ ДОЛЖНЫ
передаваться в панель.

#### Scenario: Сторонний скрипт

- **WHEN** в разметку панели попадает `<script src="https://example.com/x.js">`
- **THEN** политика безопасности не даёт ему выполниться

### Requirement: Команды и строка состояния

Расширение ДОЛЖНО (SHALL) предоставлять команды палитры: обновить дерево,
создать change (с выбором схемы), проверить change, архивировать change и
открыть каждый раздел панели. Команды, которым нужен change, ДОЛЖНЫ брать его из
узла дерева, а при вызове из палитры — предлагать выбор. Строка состояния ДОЛЖНА
показывать число активных changes и спеков и открывать доску по щелчку.

#### Scenario: Архивация из палитры

- **WHEN** пользователь вызывает «Архивировать change» из палитры
- **THEN** расширение предлагает выбрать один из активных changes
- **AND** после подтверждения change архивируется через CLI OpenSpec и исчезает из раздела «Изменения»

#### Scenario: Создание change с выбором схемы

- **WHEN** пользователь создаёт change и выбирает собственную схему с нарушением SDD уровня «ошибка»
- **THEN** создание отклоняется с текстом нарушения, как и в прежней IDE

#### Scenario: Строка состояния

- **WHEN** в проекте 2 активных change и 5 спеков
- **THEN** строка состояния показывает оба числа
- **AND** щелчок по ней открывает доску

### Requirement: Оформление по теме VS Code

Панель разделов ДОЛЖНА (SHALL) брать цвета и шрифты из текущей темы VS Code и менять их вместе со сменой темы, сохраняя смысловые цвета дельт
ADDED / MODIFIED / REMOVED различимыми.

#### Scenario: Смена темы

- **WHEN** пользователь переключает VS Code со светлой темы на тёмную при открытой панели
- **THEN** панель перекрашивается без перезагрузки
