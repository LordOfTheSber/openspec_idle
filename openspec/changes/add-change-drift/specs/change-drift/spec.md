# Spec Delta: change-drift

## ADDED Requirements

### Requirement: Пересечения активных changes по требованиям

IDE ДОЛЖНА (SHALL) находить требования, которые затрагивают два и более
активных change: одна capability и одно имя требования (без учёта регистра и
лишних пробелов) в секциях MODIFIED, REMOVED, RENAMED (прежнее имя) или
ADDED. Пересечение ДОЛЖНО показываться на карточке change на доске, в панели
деталей change — с именем требования, операциями и другими changes и с
переходом к строке дельты — и в панели «Проблемы» VS Code предупреждением на
строке заголовка требования в каждой из дельт.

#### Scenario: Два change изменяют одно требование

- **WHEN** change `add-limits` и `rework-export` оба содержат MODIFIED «Выгрузка данных» для `data-export`
- **THEN** у обеих карточек есть отметка пересечения, а в панели деталей `add-limits` видно «Выгрузка данных — также rework-export (MODIFIED)»

#### Scenario: Разные требования одной capability

- **WHEN** два change добавляют в `data-export` требования с разными именами
- **THEN** пересечения нет

### Requirement: Устаревшие дельты

IDE ДОЛЖНА (SHALL) для требований MODIFIED, REMOVED и RENAMED активного change
сравнивать текст требования в основном спеке на момент первого коммита файла
дельты с текущим текстом. Если текст изменился, дельта ДОЛЖНА считаться
устаревшей: предупреждение на строке заголовка требования, отметка на карточке
и в панели деталей с изменёнными сценариями и changes, архивированными после
этого и менявшими требование. В VS Code ДОЛЖНО быть действие, открывающее
сравнение текста требования «тогда ↔ сейчас». Без git IDE ДОЛЖНА помечать
требование «возможно устарела», если после даты создания change (включая сам
день) архивирован change, менявший то же требование. Незакоммиченная дельта
устаревшей не считается.

#### Scenario: Основной спек изменился после начала change

- **WHEN** дельта с MODIFIED «Выгрузка данных» закоммичена, а затем в основном спеке изменился сценарий «Успешная выгрузка»
- **THEN** требование помечено как устаревшее с изменённым сценарием «Успешная выгрузка»

#### Scenario: Сравнение тогда и сейчас

- **WHEN** пользователь выбирает «Что изменилось в основном спеке» на устаревшем требовании
- **THEN** открывается редактор сравнения: слева требование на момент начала change, справа — текущее

#### Scenario: Без git

- **WHEN** проект не в git, change создан 2026-09-20, а 2026-09-25 архивирован change, изменявший то же требование
- **THEN** требование помечено «возможно устарела» с именем архивного change

### Requirement: Забытые changes

IDE ДОЛЖНА (SHALL) помечать change, который находится в фазе «Готово к
архивации» и не имеет активности три дня и дольше, отметкой «ждёт архивации
N дн.» на карточке доски. Активность ДОЛЖНА определяться по последнему
коммиту каталога change, по незакоммиченным правкам в нём (активность —
сейчас), а без git — по времени изменения файлов.

#### Scenario: Готовый change без активности

- **WHEN** все пункты плана change выполнены, а последний коммит его каталога был 5 дней назад
- **THEN** на карточке видно «ждёт архивации 5 дн.»

#### Scenario: Правки не закоммичены

- **WHEN** в каталоге готового change есть незакоммиченные правки
- **THEN** отметки «ждёт архивации» нет

### Requirement: Пакетная архивация

Расширение ДОЛЖНО (SHALL) предоставлять команду «OpenSpec: Архивировать
готовые changes…»: выбор нескольких changes из фазы «Готово к архивации»,
одно подтверждение со списком в порядке архивации (по дате создания, changes
без даты — последними по имени), затем архивация по одному, где каждой
предшествует предпросмотр. Change, архивацию которого CLI отклонит, ДОЛЖЕН
пропускаться с причиной, а остальные — архивироваться. Итог ДОЛЖЕН
показываться одним сообщением: архивированные и пропущенные с причинами.

#### Scenario: Один из пакета отклонён

- **WHEN** пользователь архивирует пакетом три change, и предпросмотр второго сообщает отказ CLI
- **THEN** первый и третий архивированы, второй остаётся активным, итог называет его и причину

#### Scenario: Нет готовых changes

- **WHEN** ни один change не находится в фазе «Готово к архивации»
- **THEN** команда сообщает, что архивировать нечего
