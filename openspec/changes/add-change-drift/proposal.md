# Change: пересечения, устаревшие дельты и забытые changes

## Why

Несколько активных changes живут параллельно, и методология ломается на их
стыках, а IDE этого не показывает:

- **Пересечения.** Два change изменяют одно и то же требование. Архивируется
  первый, и дельта второго начинает перетирать его правки или вовсе не
  применяется. Сейчас раздел «Дельты» предупреждает только о том, что
  capability меняется ещё где-то, — не о том, какое требование и кто.
- **Устаревшие дельты.** Change был начат, потом другой change изменил
  основной спек, и MODIFIED первого описывает уже не существующую версию
  требования. При архивации MODIFIED молча заменит свежий текст старым.
- **Забытые changes.** Всё сделано, а change не архивирован — требования не
  попали в основные спеки. В этом репозитории таких четыре одновременно.

## What Changes

Новая возможность `change-drift`:

- **Пересечения по требованиям**: одно требование capability (по имени, как
  сравнивает OpenSpec) затрагивают два и более активных change — MODIFIED,
  REMOVED, RENAMED или одинаковое ADDED. Видно на карточке доски, в панели
  деталей change (с кем и по какому требованию, переход к строке) и в панели
  «Проблемы» VS Code на строках заголовков.
- **Устаревшие дельты**: для MODIFIED, REMOVED и RENAMED берётся текст
  требования основного спека на момент, когда дельта появилась в git (первый
  коммит файла дельты), и сравнивается с текущим. Изменился — дельта
  устарела: предупреждение с перечнем изменённых сценариев и заархивированных
  после этого changes, менявших требование. Действие «Что изменилось в
  основном спеке» открывает сравнение «тогда ↔ сейчас» в VS Code. Без git
  проверка опирается на архив: changes, архивированные в день создания change
  или позже и менявшие то же требование, дают отметку «возможно устарела».
- **Забытые changes**: change в фазе «Готово к архивации», у которого нет
  активности 3 дня и дольше (последний коммит каталога change, а без git —
  время изменения файлов), помечается «ждёт архивации N дн.».
- **Пакетная архивация** — команда «OpenSpec: Архивировать готовые changes…»:
  выбор из changes «Готово к архивации», архивация по одному в порядке
  создания (раньше созданный — первым), каждому предшествует предпросмотр;
  change, который CLI отклонит, пропускается; итог — одним сообщением.
- Маршрут `GET /api/drift`; ревизия API — 8.

Не входит: автоматическое обновление устаревшей дельты (трёхстороннее
слияние), архивация пакетом из панели в браузере.

## Capabilities

### New Capabilities

- `change-drift` — пересечения активных changes, устаревшие дельты, забытые
  changes и пакетная архивация.

### Modified Capabilities

Нет.

## Impact

- **Код**: `packages/core/src/drift.ts` — пересечения, сравнение базовой и
  текущей версии требования, забытые changes, порядок архивации;
  `packages/server/src/drift.ts` — git (базовая версия, дата активности),
  архив, маршрут; `packages/web` — отметки на карточке, раздел в панели
  деталей; `packages/vscode` — диагностики, сравнение, команда пакетной
  архивации.
- **Тесты**: модульные тесты `core`, тест сервиса на временном git-репозитории,
  e2e: отметка пересечения на доске фикстуры `delta-ops`, дымовой тест
  пакетной архивации.
