# Change: запуск GigaCode CLI через собственные обёртки .cmd на Windows

## Why

GigaCode CLI, установленный в `C:\Program Files\GigaCLI\`, запускается
обёрткой `gigacode.cmd`, устроенной не так, как обёртки npm. IDE не смогла
извлечь из неё запускаемый скрипт и заблокировала агента сообщением «укажите
путь к .exe или к .js-файлу», хотя `gigacode` в терминале работает. Разбор
понимал только обёртки npm, а запасного способа запуска не было.

## What Changes

- Разбор обёрток `.cmd` понимает обёртки установщиков: `%~dp0` с косой чертой и
  без, переменные из `SET` (в том числе `SET "имя=значение"`), пути в кавычках и
  без, `call`, собственный `node.exe` рядом с обёрткой, флаги Node и аргументы
  перед `%*`, обёртки, вызывающие `.exe`.
- Обёртка, которую разобрать не удалось, больше не блокирует агента: она
  запускается через `cmd.exe` с закавыченными аргументами, а многострочный
  промпт уходит на стандартный ввод; в аргументе остаётся однострочная отсылка
  к нему. Проверка подключения показывает пометку со строкой запуска из
  обёртки. Аргумент, который `cmd.exe` исказил бы (перевод строки, кавычка,
  `%`), не передаётся, а даёт понятную ошибку.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `agent-bridge` — запуск CLI через обёртки `.cmd` на Windows.

## Impact

- **Код**: `packages/server/src/process/platform.ts` (разбор обёрток, план
  запуска через `cmd.exe`, стандартный ввод), `agent/probe.ts`,
  `agent/runner.ts`, `openspec/exec.ts`.
- **CLI OpenSpec и GigaCode**: не затрагиваются.
