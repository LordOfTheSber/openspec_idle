# Spec Delta: spec-authoring

## ADDED Requirements

### Requirement: Документы OpenSpec в редакторе

Расширение ДОЛЖНО (SHALL) предоставлять языковые функции для трёх видов
markdown-документов: основной спек `openspec/specs/<capability>/spec.md`,
файл дельты активного change и отслеживаемый артефакт (план) активного
change, как их определяет схема change. Другие файлы не ДОЛЖНЫ получать этих
функций. Все функции ДОЛЖНЫ работать по текущему тексту редактора, включая
несохранённые правки; остальные документы берутся с диска и обновляются при
их изменении.

#### Scenario: Несохранённая правка

- **WHEN** пользователь добавил в дельту требование и ещё не сохранил файл
- **THEN** структура документа и проверки ссылок уже учитывают это требование

#### Scenario: Предложение change

- **WHEN** пользователь открывает `proposal.md` change
- **THEN** расширение не предлагает для него дополнений и подсказок над строками

### Requirement: Структура документа и поиск символов

Расширение ДОЛЖНО (SHALL) отдавать структуру документа: для спека —
требования с вложенными сценариями, для дельты — операции с вложенными
требованиями и сценариями, для плана — группы с вложенными пунктами. Поиск
символов по рабочей области ДОЛЖЕН находить требования и сценарии основных
спеков и дельт активных changes с указанием capability и change.

#### Scenario: Структура дельты

- **WHEN** пользователь открывает дельту с секциями ADDED и MODIFIED
- **THEN** в Outline видны узлы «ADDED», «MODIFIED», под ними требования, под требованиями сценарии

#### Scenario: Поиск требования по проекту

- **WHEN** пользователь ищет символ «Выгрузка»
- **THEN** в результатах есть требование «Выгрузка данных» основного спека `data-export` и его версия в дельте change

### Requirement: Дополнение в дельте

Расширение ДОЛЖНО (SHALL) предлагать в файле дельты: заголовки секций
`## ADDED Requirements`, `## MODIFIED Requirements`, `## REMOVED
Requirements`, `## RENAMED Requirements` в начале строки `##`; после
`### Requirement:` в секциях MODIFIED и REMOVED и после `FROM:` в секции
RENAMED — имена требований основного спека этой capability, которые ещё не
упомянуты в этой секции дельты; шаблоны «требование со сценарием» и
«сценарий» с шагами WHEN/THEN. В секции ADDED имена основного спека
предлагаться не ДОЛЖНЫ.

#### Scenario: Имя для MODIFIED

- **WHEN** пользователь набирает `### Requirement: ` в секции MODIFIED дельты `data-export`
- **THEN** предлагаются имена требований основного спека `data-export`

#### Scenario: Уже изменённое требование

- **WHEN** требование «Выгрузка данных» уже есть в секции MODIFIED этой дельты
- **THEN** оно не предлагается повторно в этой секции

#### Scenario: Нет основного спека

- **WHEN** capability дельты ещё нет в `openspec/specs/`
- **THEN** имена не предлагаются, заголовки секций и шаблоны — предлагаются

### Requirement: Проверка ссылок дельты на основной спек

Расширение ДОЛЖНО (SHALL) показывать в панели «Проблемы» на строке заголовка
требования дельты: ошибку, если требование MODIFIED или REMOVED либо прежнее
имя RENAMED не найдено в основном спеке capability (сравнение без учёта
регистра и лишних пробелов, как в OpenSpec), с похожими именами в тексте;
ошибку, если требование ADDED уже есть в основном спеке; ошибку, если
MODIFIED не содержит сценариев, которые есть у этого требования в основном
спеке, с их перечнем. Замечания ДОЛЖНЫ обновляться при наборе текста.

#### Scenario: Опечатка в имени MODIFIED

- **WHEN** дельта изменяет требование «Выгрузка даных», а в основном спеке есть «Выгрузка данных»
- **THEN** на строке заголовка показана ошибка «требования нет в основном спеке», в тексте названо «Выгрузка данных»

#### Scenario: ADDED уже существующего требования

- **WHEN** дельта добавляет требование «Кодировка файла», которое уже есть в основном спеке
- **THEN** на строке заголовка показана ошибка о том, что архивация откажет

#### Scenario: MODIFIED теряет сценарий

- **WHEN** в MODIFIED нет сценария «Пустой набор данных», который есть у требования в основном спеке
- **THEN** показана ошибка с именем потерянного сценария

### Requirement: Быстрые исправления в дельте

Расширение ДОЛЖНО (SHALL) предлагать для требования MODIFIED, найденного в
основном спеке, действие «Скопировать требование из основного спека»,
которое заменяет тело блока (от строки после заголовка до следующего
требования или секции) телом требования основного спека, не меняя заголовок
и остальной файл. Для требования, не найденного в основном спеке, ДОЛЖНЫ
предлагаться замены имени на похожие имена основного спека.

#### Scenario: Копирование требования

- **WHEN** пользователь применяет «Скопировать требование из основного спека» к MODIFIED «Выгрузка данных»
- **THEN** блок содержит описание и все сценарии требования основного спека, а строки вне блока не изменились

#### Scenario: Замена имени

- **WHEN** пользователь применяет «Заменить на „Выгрузка данных“» к заголовку «Выгрузка даных»
- **THEN** заголовок становится `### Requirement: Выгрузка данных`, и ошибка исчезает

### Requirement: Ссылки плана на сценарии

Расширение ДОЛЖНО (SHALL) в плане change: после `↳ ` или `-> ` в строке под
пунктом предлагать ссылки `<capability> / <сценарий>` и `<capability> /
<требование>` на сценарии и требования ADDED и MODIFIED дельт этого change;
при наведении на строку ссылки показывать требование и шаги найденных
сценариев; по переходу к определению открывать сценарий или требование в
файле дельты; показывать предупреждение на строке ссылки, которая не находит
ни сценария, ни требования.

#### Scenario: Дополнение ссылки

- **WHEN** пользователь набирает `  ↳ ` под пунктом плана
- **THEN** предлагаются ссылки на сценарии дельт change, например `data-export / Превышен объём`

#### Scenario: Переход к сценарию

- **WHEN** пользователь нажимает F12 на строке `↳ data-export / Превышен объём`
- **THEN** открывается дельта `data-export` change на строке `#### Scenario: Превышен объём`

#### Scenario: Висячая ссылка

- **WHEN** ссылка называет сценарий, которого нет в дельтах change
- **THEN** на строке ссылки показано предупреждение

### Requirement: Подсказки над строками

Расширение ДОЛЖНО (SHALL) показывать над заголовком требования ADDED и
MODIFIED в дельте число пунктов плана, которые на него ссылаются явно или
предположительно, либо «Не покрыт планом — добавить пункт», которое
дописывает пункт со ссылкой в план; над требованием MODIFIED, REMOVED и
RENAMED, найденным в основном спеке, — переход «Основной спек»; над пунктом
плана со ссылками — число сценариев, которые он покрывает.

#### Scenario: Требование не покрыто

- **WHEN** на требование ADDED не ссылается ни один пункт плана
- **THEN** над заголовком видно «Не покрыт планом — добавить пункт», и выбор дописывает пункт со ссылкой в конец последней группы плана

#### Scenario: Переход к основному спеку

- **WHEN** пользователь выбирает «Основной спек» над MODIFIED «Выгрузка данных»
- **THEN** открывается основной спек на строке `### Requirement: Выгрузка данных`
