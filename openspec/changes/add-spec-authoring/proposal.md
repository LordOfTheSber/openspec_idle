# Change: помощь при написании спеков и плана в редакторе

## Why

Спеки, дельты и план люди и агенты пишут в редакторе VS Code, а расширение
помогает там только диагностикой валидации. Самые частые ошибки OpenSpec
делаются именно при наборе текста и всплывают поздно — при валидации или
при архивации:

- `MODIFIED`/`REMOVED` с именем требования, которого нет в основном спеке
  (опечатка, лишний пробел, другое слово) — архивация отказывает, а
  `validate --strict` сообщает это лишь как INFO без строки;
- `MODIFIED` без части сценариев основного спека: блок заменяет требование
  целиком, и сценарии теряются. Текст приходится копировать из основного
  спека вручную;
- ссылка `↳ capability / сценарий` в плане с опечаткой — трассировка молча
  считает сценарий непокрытым;
- навигация по требованиям — только поиском по тексту.

## What Changes

Новая возможность `spec-authoring` — языковые функции для markdown-файлов
OpenSpec в VS Code (основные спеки, дельты changes, отслеживаемый артефакт —
план):

- **Структура документа**: требования и сценарии (в дельте — под операцией),
  группы и пункты плана — в Outline, хлебных крошках и `Ctrl+Shift+O`;
  **поиск символов по проекту** (`Ctrl+T`) — по требованиям и сценариям
  основных спеков и дельт активных changes.
- **Дополнение в дельте**: заголовки `## ADDED/MODIFIED/REMOVED/RENAMED
  Requirements`; после `### Requirement:` в секциях MODIFIED и REMOVED и после
  `FROM:` в RENAMED — имена требований основного спека этой capability, ещё не
  упомянутые в дельте; шаблоны «требование со сценарием» и «сценарий».
- **Быстрые исправления в дельте**: «Скопировать требование из основного
  спека» для MODIFIED — блок получает текст и все сценарии основного спека;
  «Заменить на „…“» — похожие имена для требования, которого нет в основном
  спеке.
- **Проверка ссылок дельты** (панель «Проблемы», сразу при наборе): MODIFIED,
  REMOVED или RENAMED FROM на требование, которого нет в основном спеке;
  ADDED требования, которое там уже есть; MODIFIED, который теряет сценарии
  основного спека.
- **Ссылки плана на сценарии**: дополнение после `↳ ` (capability / сценарий
  или требование из дельт change), текст сценария при наведении, переход к
  сценарию по F12, предупреждение о ссылке, которая ничего не находит.
- **Подсказки над строками (CodeLens)**: над требованием дельты — «Основной
  спек» (переход) и покрытие планом («Пунктов плана: 2» или «Не покрыт планом —
  добавить пункт»); над пунктом плана — сколько сценариев он покрывает.
- Всё работает по несохранённому тексту редактора.
- Маршрут `GET /api/authoring` — тексты основных спеков, дельт и планов
  активных changes; ревизия API — 7.

Не входит: переименование требования с правкой всех ссылок (refactoring),
автодополнение в `design.md` и `proposal.md`.

## Capabilities

### New Capabilities

- `spec-authoring` — языковые функции для спеков, дельт и плана в редакторе.

### Modified Capabilities

Нет.

## Impact

- **Код**: `packages/core/src/authoring.ts` — чистая модель: разбор
  документов, символы, дополнения, исправления, проверки ссылок, подсказки;
  `packages/server/src/authoring.ts` — сбор источников, маршрут;
  `packages/vscode/src/authoring.ts` — провайдеры VS Code.
- **Тесты**: модульные тесты `core` на каждый сценарий спеки, тест маршрута,
  дымовой тест регистрации провайдеров и диагностики ссылок.
