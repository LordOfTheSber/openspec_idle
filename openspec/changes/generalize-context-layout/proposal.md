# Change: произвольная раскладка контекста

## Why

Карта контекста знает одну раскладку: `openspec/context/modules/<папка>/` с
`index.md` и `context.md`. Проекты же раскладывают контекст по-своему.
Команда, перешедшая на формат AIPDLC, делит контекст модуля на нумерованные
части (`00-start-here.md`, `01-product-context.md` … `05-testing-and-quality.md`),
кладёт модули в группы по структуре репозитория (`modules/back/cm/`) и
собирается завести рядом с `modules/` раздел `functions/`. Для IDE всё это —
ошибки «нет `index.md`» и «файл вне наборов», а агент получает набор без
архитектуры, стандартов и тестирования модуля.

## What Changes

- Модуль — любая папка в `openspec/context/` (кроме `adr/`) на любой глубине с
  файлом метаданных `00-start-here.md` или `index.md`. Его файлы — все `.md`
  папки и её подпапок, которые сами не модули; набор частей определяет модуль
  (у конфигурации может не быть `05-testing-and-quality.md`).
- Файл метаданных входит в набор, только если в нём есть текст кроме
  frontmatter и заголовков: маршрут `00-start-here.md` агент читает первым, а
  прежний `index.md` из одного frontmatter в набор не попадает.
- Папка без файла метаданных, под которой есть модули, — группа: её `.md` —
  общий контекст модулей под ней, в наборе — перед файлами модуля.
- Раздел (`modules`, `functions`…) — первая папка пути модуля; идентификатор
  без поля `module` — последняя папка пути.
- Части модуля в наборе — по имени с числами по значению (`2-…` раньше `10-…`).
- Контроль: пустота — по каждой части; свежесть — по последнему коммиту любой
  части модуля; привязка и свежесть — у всех файлов модуля; повторы и пути —
  ещё и в группах.
- «Создать модуль…» принимает имя с группой (`back/router`) и заводит модуль в
  раскладке проекта: `index.md` и `context.md`, если все модули на прежней,
  иначе `00-start-here.md` и `01-product-context.md`.
- Сверка спеков с кодом модулей (`quality`) находит модули по тем же правилам.
- Раздел «Контекст»: в карточке модуля — папка и все его файлы, объём и
  полезность по всем файлам модуля; в виде «Контроль» — вид файла «группа».
- Навык `context-fill`: раскладка проекта, что класть в каждую часть, промпт
  перевода модуля с `index.md` и `context.md` на нумерованные части.
- Фикстура `tests/fixtures/context-layered` с нумерованными частями, группой
  `modules/back/` и `structure.yaml` под неё.

Не входит: ADR внутри модулей (`modules/x/adr/` — части модуля, а не ADR),
наследование контекста от модуля-родителя вложенному модулю (только от групп),
настройка имён файла метаданных.

### Modified Capabilities

- `context-map` — произвольная раскладка `openspec/context/`: модули на любой
  глубине и в любых разделах, части модуля, группы, создание модуля в
  раскладке проекта.

## Impact

- **Код**: `packages/core/src/contextMap.ts` — `ModuleSource` с файлом
  метаданных и списком файлов, `ContextModule.files`, `groupFiles`, `section`,
  группы на карте, вид файла `group`; `packages/server/src/contextMap.ts` —
  обход `scanContext`, создание модуля; `packages/server/src/quality.ts`,
  `packages/server/src/git.ts` (несколько путей в `lastCommit` и
  `hasChanges`); `packages/web` — карточка модуля, пустое состояние, вид
  «Контроль».
- **API**: `ContextModule.contextPath` заменён на `files` и `groupFiles`;
  ревизия API — 13.
- **Файлы проекта**: прежняя раскладка работает без изменений; `.md` рядом с
  `index.md` (например, `notes.md`) теперь входят в набор модуля, а не
  отмечаются как файлы вне наборов.
