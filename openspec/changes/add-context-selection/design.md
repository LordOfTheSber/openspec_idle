# Design: набор контекста из нескольких узлов

## Context

Мотивация — в `proposal.md`, требования — в дельте `specs/context-map`.
Набор строится в панели по уже загруженной карте, бэкенд не участвует.

## Decisions

### 1. Режим набора и щелчок с модификатором

**Решение.** Кнопка «Набор контекста» переключает смысл щелчка: в режиме
щелчок добавляет узел в набор или убирает его, вне режима — открывает карточку,
как раньше. Ctrl/⌘/Shift+щелчок добавляет узел в любом режиме и включает
режим. Панель набора занимает место карточки.

**Альтернатива — только модификатор.** Не меняет привычный щелчок, но
невидима: без подсказки её не найти, а на тачпаде и в webview модификатор
неудобен. Режим виден на панели инструментов, модификатор остаётся ускорением.

### 2. Что добавляется к выбранному

**Решение.** Для модулей по умолчанию, как и в наборе одного модуля,
берутся транзитивные зависимости по `depends_on` и спеки их доменов; оба
добавления отключаются флажками. Выбранный домен добавляет свою спеку и ADR,
ссылающиеся на него; выбранный ADR добавляет только себя. Выбор домена не
тянет модули домена: иначе выбор общего домена втащил бы половину системы.

**Альтернатива — брать только явно выбранное.** Предсказуемо, но для типичной
задачи «модуль и всё, что ему нужно» пришлось бы щёлкать каждую зависимость.

### 3. Порядок и хранение

Порядок файлов прежний: общий контекст, `context.md` модулей в порядке обхода
от выбранных, спеки (домены модулей, затем выбранные), ADR. Выбор хранится
ключами узлов `вид:идентификатор` в `localStorage` окна; узлы, пропавшие с
карты после правки файлов, из набора уходят.

**Альтернатива — хранить набор в файле проекта.** Набор — рабочее состояние
одного человека под текущую задачу; в репозитории он создавал бы шум.

## Risks / Trade-offs

- Флажок «спеки доменов модулей» действует на все модули набора сразу; тонкая
  настройка по модулю — только выбором доменов вручную с выключенным флажком.
