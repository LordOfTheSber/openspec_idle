# Spec Delta: spec-quality

## ADDED Requirements

### Requirement: Проверка качества спеков

Система ДОЛЖНА (SHALL) проверять содержание требований основных спеков и
дельт активных changes детерминированными правилами — регулярными
выражениями и разбором markdown, без LLM, — и выдавать замечание со строкой,
уровнем и именем правила. Требования под `## REMOVED Requirements` и
`## RENAMED Requirements` проверяться НЕ ДОЛЖНЫ. Замечания ДОЛЖНЫ попадать в
панель «Проблемы» VS Code с источником `openspec-quality` и кодом — именем
правила — и пересчитываться по несохранённому тексту редактора.

#### Scenario: Замечание при наборе

- **WHEN** пользователь дописывает в требование дельты слово «валидном» и не сохраняет файл
- **THEN** в панели «Проблемы» на строке этого предложения появляется предупреждение с источником `openspec-quality` и кодом `vague-wording`

#### Scenario: Удалённое требование не проверяется

- **WHEN** дельта содержит под `## REMOVED Requirements` требование с причиной «устарело и т. д.»
- **THEN** замечаний качества у этой дельты нет

### Requirement: Трассируемость кодов ошибок

Система ДОЛЖНА (SHALL) сверять коды ошибок текста требования и шагов THEN
его сценариев: код из THEN, которого нет в тексте, и код из текста, которого
нет ни в одном THEN, дают предупреждение `error-code-trace`. Кодом ДОЛЖНО
считаться слово из заглавных латинских букв и цифр хотя бы с одним `_` (или
по шаблону настроек); в тексте — только в предложении со словом об ошибке
или коде либо из реестра кодов. Код, который сценарий подаёт на вход в WHEN,
кодом ошибки НЕ ДОЛЖЕН считаться.

#### Scenario: Код из текста без сценария

- **WHEN** текст требования говорит «кластер ДОЛЖЕН вернуть ошибку `SESSION_CREATION_WITHOUT_EXTERNAL_SESSION_ID`», а ни один THEN этот код не содержит
- **THEN** на строке предложения есть предупреждение `error-code-trace` с этим кодом

#### Scenario: Имя переменной — не код ошибки

- **WHEN** текст требования говорит «брать путь из переменной `OPENSPEC_CLI`»
- **THEN** предупреждения `error-code-trace` нет

### Requirement: Покрытие условий и перечислений сценариями

Система ДОЛЖНА (SHALL) находить в тексте требования условия («если», «когда»,
«при» и английские if, when, unless) и перечисления значений в `` `коде` ``
(«`A`, `B` и `C`», «как `X`, так и `Y`», список пунктов с `` `кодом` ``). Условие,
ключевые слова которого не находятся в WHEN или имени ни одного сценария,
ДОЛЖНО давать сведение `branch-coverage`; значение перечисления, которого нет
ни в одном сценарии, — предупреждение `enumeration-coverage`. Пути, файлы и
фразы с пробелами значениями перечисления НЕ ДОЛЖНЫ считаться.

#### Scenario: Непокрытое условие

- **WHEN** текст говорит «Если клиент заблокирован, кластер ДОЛЖЕН отказать», а сценарии описывают только истёкшую сессию
- **THEN** на строке условия есть сведение `branch-coverage` с текстом «клиент заблокирован»

#### Scenario: Значение перечисления без сценария

- **WHEN** текст говорит «как `sliding`, так и `entire`», а сценарий есть только на режим `sliding`
- **THEN** есть предупреждение `enumeration-coverage`, называющее `entire`

### Requirement: Граничные значения

Система ДОЛЖНА (SHALL) находить в тексте требования интервалы (`[a, b]`,
«от a до b», `between a and b`) и пороги («не более N», «больше N», «не менее
N», `at most N`), где граница — число или параметр. Для интервала ДОЛЖНЫ
быть сценарии со значением на каждой границе, ниже нижней и выше верхней,
для порога — на границе и за ней; недостающие точки ДОЛЖНЫ давать
предупреждение `boundary-values`. Присваивание `` `minTtl` = 60 `` в шаге
ДОЛЖНО задавать значение границы, а не считаться сценарием на равенство.

#### Scenario: Нет сценариев на границах интервала

- **WHEN** текст говорит «приводить TTL к интервалу [`minTtl`, `maxTtl`]», а сценарии подают TTL 10 и 7200 при `minTtl` = 60 и `maxTtl` = 3600
- **THEN** есть предупреждение `boundary-values` о значениях «= minTtl, = maxTtl»

#### Scenario: Размер, равный лимиту

- **WHEN** текст говорит «хранить не более `maxCacheSize` сессий», и есть сценарии «число сессий равно `maxCacheSize`» и «число сессий больше `maxCacheSize`»
- **THEN** предупреждения `boundary-values` нет

### Requirement: Арифметика приведения к интервалу

Система ДОЛЖНА (SHALL) для требования, которое приводит значение к интервалу
(«приводить», «ограничивать», `clamp`), сверять каждый сценарий с одним
входным числом в WHEN и одним числом в THEN с правилом clamp(x, min, max).
Границы ДОЛЖНЫ браться из чисел текста, параметров настроек или присваиваний
шагов сценария. Расхождение ДОЛЖНО давать предупреждение `clamp-arithmetic`
на строке THEN.

#### Scenario: Ожидание противоречит правилу

- **WHEN** текст говорит «приводить TTL к интервалу [60, 3600]», а сценарий ожидает для TTL 7200 значение 7200
- **THEN** на строке THEN есть предупреждение `clamp-arithmetic` «должно стать 3600, а THEN ожидает 7200»

### Requirement: Наблюдаемость сценариев

Система ДОЛЖНА (SHALL) давать предупреждение `implementation-leak` на шаг
WHEN или THEN с вызовом метода или с внутренним именем вида
`объектКласса.поле`, которого нет в реестре терминов, и предупреждение
`observable-then` на шаг THEN, который говорит о внутреннем
состоянии (кэш, память, база данных, внутренняя переменная) и не называет
ответ, код ошибки, статус, сообщение или другое наблюдаемое снаружи.
Окончание множественного числа вида `scenario(s)` и текст в «кавычках»
вызовом метода НЕ ДОЛЖНЫ считаться.

#### Scenario: Вызов метода в THEN

- **WHEN** шаг THEN проверяемого спека говорит «sessionCache.getCacheSize() возвращает 1»
- **THEN** на строке шага есть предупреждение `implementation-leak` с вызовом «sessionCache.getCacheSize()»

#### Scenario: THEN о кэше

- **WHEN** шаг AND после THEN говорит «сессия в кэш не создаётся»
- **THEN** на строке шага есть предупреждение `observable-then` с «кэш»

### Requirement: Реестр терминов и словарь акторов

Система ДОЛЖНА (SHALL) собирать реестр терминов спека из разделов
`## Glossary`, `## Configuration`, «Глоссарий», «Параметры», «Конфигурация»
(для дельты — и из основного спека capability) и из `glossary` и
`parameters` настроек. При непустом реестре каждый camelCase-идентификатор
текста и шагов, которого в реестре нет, ДОЛЖЕН давать предупреждение
`parameter-registry`; поле `SessionDto.expirationInfo` из реестра ДОЛЖНО
находиться и по имени `expirationInfo`. При заданном в настройках словаре
`actors` подлежащее при ДОЛЖЕН/SHALL не из словаря ДОЛЖНО давать
предупреждение `actor-dictionary`. Без реестра и без словаря эти правила
замечаний НЕ ДОЛЖНЫ давать.

#### Scenario: Параметр вне раздела Configuration

- **WHEN** раздел `## Configuration` объявляет только `minTtl`, а текст требования упоминает `maxTtl`
- **THEN** есть предупреждение `parameter-registry` о «maxTtl»

#### Scenario: Непустой реестр из настроек

- **WHEN** раздела `## Configuration` нет, а настройки содержат `glossary: [SessionDto.expirationInfo]` и `parameters: { maxTtl: 3600 }`
- **THEN** упоминания `maxTtl` и `expirationInfo` предупреждений `parameter-registry` не дают

#### Scenario: Реестр пуст

- **WHEN** у спека нет разделов-реестров, а в настройках нет `glossary` и `parameters`
- **THEN** замечаний `parameter-registry` нет

#### Scenario: Подлежащее не из словаря

- **WHEN** в настройках задан словарь `actors: [кластер, КМ]`, а требование говорит «Master ДОЛЖЕН подтверждать приём»
- **THEN** на строке предложения есть предупреждение `actor-dictionary` с «Master»

### Requirement: Расплывчатые формулировки

Система ДОЛЖНА (SHALL) давать предупреждение `vague-wording` на каждую строку
текста или шага, где есть слово словаря расплывчатых формулировок
(«валидный», «корректный», «и т. д.», «например», «при необходимости», их
формы и английские аналоги), и считать их плотность на 100 слов. Слова в `` `коде` `` и в кавычках, а также «в основном спеке»
расплывчатыми НЕ ДОЛЖНЫ считаться. Настройка `vagueWords` ДОЛЖНА пополнять
словарь (`add`) и убирать из него слова (`ignore`).

#### Scenario: Валидный запрос

- **WHEN** текст требования говорит «создавать сессию по валидным NewSessionRq»
- **THEN** на этой строке есть предупреждение `vague-wording` с «валидным»

#### Scenario: Сообщение в кавычках

- **WHEN** шаг THEN говорит «ответ содержит «Некорректный путь»»
- **THEN** предупреждения `vague-wording` на этой строке нет

### Requirement: Негативные и позитивные сценарии

Система ДОЛЖНА (SHALL) для требования, текст которого говорит об отказе,
отклонении, возврате ошибки или называет код ошибки, проверять наличие и
сценария с ошибкой в THEN (слово об ошибке, код ошибки или статус 4xx/5xx), и
сценария без неё. Недостающий вид ДОЛЖЕН давать предупреждение
`negative-scenarios` на строке требования.

#### Scenario: Только сценарий с ошибкой

- **WHEN** требование «отклонять запрос без заголовка `SDS-CM-CLIENT-IP`» имеет один сценарий с THEN «ответ — ошибка 400»
- **THEN** есть предупреждение `negative-scenarios` «нет сценария, где запрос проходит»

#### Scenario: Только успешный сценарий

- **WHEN** у того же требования единственный сценарий с THEN «сессия создаётся»
- **THEN** есть предупреждение `negative-scenarios`: ни один сценарий не проверяет ошибку

### Requirement: Атомарность требования

Система ДОЛЖНА (SHALL) давать сведение `atomicity` на требование, нормативные
предложения которого (с ДОЛЖЕН/SHALL/MUST) делятся на группы без общих
содержательных слов: такое требование описывает несколько предметов.

#### Scenario: Операция и заголовки в одном требовании

- **WHEN** текст требования говорит «Кластер ДОЛЖЕН создавать сессию клиента. Каждый ответ ДОЛЖЕН нести заголовки трассировки.»
- **THEN** на строке требования есть сведение `atomicity`

### Requirement: Согласованность с Purpose

Система ДОЛЖНА (SHALL) извлекать из раздела Purpose основного спека
перечисленные сущности — пункты списка и короткие части перечисления через
запятую или «и» — и давать сведение `purpose-coverage` на сущность, слова
которой не находятся ни в имени, ни в тексте ни одного требования.

#### Scenario: Обещанный healthcheck

- **WHEN** Purpose говорит «Кластер управляет сессиями: создание сессии, healthcheck и синхронизация узлов», а требование есть только о создании сессии
- **THEN** на строке Purpose есть сведение `purpose-coverage` с «healthcheck» и «синхронизация узлов»

### Requirement: Реестр кодов ошибок

Система ДОЛЖНА (SHALL), если в настройках задан реестр кодов ошибок —
файлы проекта (`errorCodes.registry`), — давать предупреждение
`error-code-registry` на код спеки, которого нет в реестре, и сведение на
строке файла реестра на код, который не упоминается ни в одной спеке.
Ненайденный файл реестра ДОЛЖЕН давать ошибку настроек.

#### Scenario: Код без спецификации

- **WHEN** реестр `src/ErrorCode.java` содержит `CACHE_LIMIT_EXCEEDED`, а ни одна спека его не упоминает
- **THEN** на строке кода в `src/ErrorCode.java` есть сведение `error-code-registry`

#### Scenario: Код вне реестра

- **WHEN** сценарий проверяемого спека ожидает код ошибки, которого нет в реестре
- **THEN** на строке шага есть предупреждение `error-code-registry` с этим кодом

### Requirement: Настройки проверки качества

Система ДОЛЖНА (SHALL) читать настройки из необязательного файла
`openspec/quality.yaml`: область проверки `scope` (все спеки или только
дельты активных changes), уровни правил `rules` (от ошибки до выключенного
правила), а также словари, реестры и пороги из требований выше. Без файла
ДОЛЖНЫ действовать умолчания. Неизвестный ключ, правило, уровень или
метрика и регулярное выражение, которое не разбирается, ДОЛЖНЫ давать
ошибку на строке ключа, а остальные настройки — продолжать действовать.

#### Scenario: Правило выключено

- **WHEN** `openspec/quality.yaml` содержит `rules: { vague-wording: off }`
- **THEN** замечаний `vague-wording` нет, остальные правила дают замечания

#### Scenario: Уровень правила повышен

- **WHEN** `openspec/quality.yaml` содержит `rules: { vague-wording: error }`
- **THEN** замечания `vague-wording` имеют уровень `error`

#### Scenario: Только дельты

- **WHEN** `openspec/quality.yaml` содержит `scope: changes`
- **THEN** замечания есть только у файлов в `openspec/changes/`

#### Scenario: Неизвестное правило

- **WHEN** `openspec/quality.yaml` содержит в `rules` ключ `nope` на строке 3
- **THEN** есть ошибка на `openspec/quality.yaml:3` «неизвестное правило «nope»»

### Requirement: Метрики качества и пороги

Система ДОЛЖНА (SHALL) считать по проверенным спекам метрики:
`errorCodeTraceability` — доля кодов, которые есть и в тексте, и в THEN;
`branchCoverage` — доля покрытых условий; `boundaryCoverage` — доля
покрытых точек границ; `ambiguityDensity` — расплывчатых слов на 100 слов.
Метрика, которую считать не по чему, ДОЛЖНА быть пустой. Порог из
`thresholds` (для долей — не ниже, для плотности — не выше) ДОЛЖЕН давать
ошибку `metric-threshold` на строке порога в `openspec/quality.yaml`.

#### Scenario: Трассируемость ниже порога

- **WHEN** в настройках `thresholds: { errorCodeTraceability: 1 }`, а один код из двух есть только в тексте требования
- **THEN** есть ошибка `metric-threshold` на строке порога «ниже порога 100 %»

### Requirement: Проверка качества в CI

Команда `openspec-ide-check` ДОЛЖНА (SHALL) выполнять проверку `quality` с
теми же правилами и настройками, что и редактор: замечание — с файлом,
строкой и именем правила в скобках, итог проверки — с метриками строкой в
формате `text` и полем `metrics` в формате `json`. Без замечаний уровня
`error` проверка ДОЛЖНА проходить с кодом 0.

#### Scenario: Отчёт с метриками

- **WHEN** выполняется `openspec-ide-check --only quality` в проекте, где спеки дают только предупреждения и сведения
- **THEN** код завершения 0, в итоге под строкой `quality` — «трассируемость кодов ошибок …, покрытие ветвлений …, покрытие границ …, расплывчатых слов на 100 …»

#### Scenario: Замечание с правилом

- **WHEN** спека содержит «валидном формате CSV»
- **THEN** отчёт содержит строку `путь:строка: предупреждение: … (vague-wording) [quality]`
