# Change: кэш контроля контекста

## Why

С появлением вида «Контроль» раздел «Контекст» открывается заметно дольше.
Карта строится одним запросом `GET /api/context-map`, и почти всё его время
уходит на свежесть контекста по git: на каждый модуль с `context.md` и
существующими путями кода — четыре процесса git (`status`, два `log`,
`rev-list --count`), все разом. На синтетическом репозитории (20 000 коммитов,
40 модулей) сборка карты занимает 650–900 мс, без git — 30–45 мс. На Windows и
на больших репозиториях счёт идёт на секунды.

Результат при этом почти никогда не меняется: свежесть зависит только от
текущего коммита, индекса git и текста `context.md`. А пересчитывается она:

- при каждом открытии раздела: компонент раздела при переключении
  размонтируется, и карта запрашивается заново, а до ответа раздел пуст;
- при каждом изменении в `openspec/` (ревизия рабочего пространства);
- в VS Code — ещё и на каждое создание или удаление любого файла рабочего
  пространства (наблюдатель `**/*` пересчитывает замечания для панели
  «Проблемы»). Во время сборки проекта это непрерывные волны процессов git,
  с которыми конкурирует запрос раздела.

## What Changes

- **Кэш свежести на сервере.** `ContextMapService` запоминает свежесть модуля
  по ключу «состояние git + путь `context.md` + его текст + префиксы путей
  кода». Состояние git — коммит `HEAD` и время изменения и размер файла
  индекса — снимается одним вызовом git на сборку карты. Пока ключ тот же,
  свежесть берётся из кэша без процессов git. Новый коммит, переключение ветки,
  `git add`, правка `context.md` или его путей кода меняют ключ, и свежесть
  считается заново.
- **Один расчёт на одновременные запросы.** Запросы карты, пришедшие, пока
  свежесть модуля ещё считается (раздел и панель «Проблемы» после одного
  изменения файлов), ждут тот же расчёт, а не запускают git повторно.
- **Последняя карта на клиенте.** Раздел «Контекст» при повторном открытии
  сразу показывает последнюю полученную карту и обновляет её, когда придёт
  ответ; устаревший ответ не перезаписывает более новый.
- Что карта показывает, не меняется: значения свежести, замечания и формат
  ответа API прежние.

Не входит: сохранение кэша на диск между перезапусками бэкенда, ограничение
числа одновременных процессов git при холодной сборке, кэш остальных частей
карты (чтение файлов и проверка путей укладываются в десятки миллисекунд).

### New Capabilities

### Modified Capabilities

- `context-map` — свежесть контекста по git не пересчитывается, пока не
  изменились коммит, индекс git или `context.md`; раздел при повторном
  открытии сразу показывает последнюю карту.

## Impact

- **Код**: `packages/server/src/git.ts` — снимок состояния git (коммит `HEAD`
  и путь индекса одним вызовом); `packages/server/src/contextMap.ts` — кэш
  свежести с общими незавершёнными расчётами; `packages/web/src/components/ContextMap.tsx`
  — последняя карта при монтировании и защита от устаревшего ответа.
- **API**: без изменений, ревизия API прежняя.
- **Поведение**: повторное открытие раздела «Контекст» и пересчёт замечаний
  без изменений в git не запускают процессов git, кроме одного снимка
  состояния; первая сборка после запуска бэкенда — как раньше.
