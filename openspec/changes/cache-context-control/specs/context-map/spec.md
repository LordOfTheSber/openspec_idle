# Spec Delta: context-map

## ADDED Requirements

### Requirement: Повторное использование свежести контекста

Система ДОЛЖНА (SHALL) переиспользовать рассчитанную свежесть `context.md`
модуля, пока не изменились текущий коммит репозитория, индекс git, текст
`context.md` и пути кода модуля. Повторная сборка карты контекста при тех же
условиях НЕ ДОЛЖНА запускать запросы истории git для модуля, кроме одного
снимка состояния репозитория на всю сборку. Изменение любого из условий
ДОЛЖНО приводить к пересчёту свежести этого модуля при следующей сборке
карты. Запросы карты, пришедшие, пока свежесть модуля ещё считается, ДОЛЖНЫ
получать результат того же расчёта. Значения свежести и замечания карты
ДОЛЖНЫ совпадать с теми, что дал бы расчёт без повторного использования.

#### Scenario: Повторное открытие без изменений

- **WHEN** карта контекста построена, и после этого не было ни коммитов, ни изменений индекса git, ни правок `context.md`
- **THEN** следующая сборка карты не запускает запросов истории git для модулей
- **AND** свежесть модулей и замечания об отставании те же

#### Scenario: Новый коммит в коде модуля

- **WHEN** после сборки карты в путях кода модуля сделан коммит
- **THEN** следующая сборка карты показывает отставание контекста этого модуля на один коммит больше

#### Scenario: Правка контекста без коммита

- **WHEN** после сборки карты в `context.md` модуля внесена незакоммиченная правка
- **THEN** следующая сборка карты считает контекст этого модуля свежим

#### Scenario: Одновременные запросы

- **WHEN** раздел «Контекст» и панель «Проблемы» запрашивают карту одновременно после изменения файлов
- **THEN** свежесть каждого модуля считается по git один раз

### Requirement: Повторное использование анализа текста контекста

Система ДОЛЖНА (SHALL) переиспользовать результаты анализа текста файла
контекста для вида «Контроль» — оценку токенов, найденные ссылки на пути,
признак пустого файла, повторы, коэффициент полезности и антипаттерны, —
пока текст файла и параметры расчёта не изменились. Правка одного файла
ДОЛЖНА приводить к повторному анализу только этого файла и расчётов, которые
сравнивают файлы между собой. Результаты ДОЛЖНЫ совпадать с теми, что дал бы
анализ без повторного использования. Объём запомненного ДОЛЖЕН быть
ограничен.

#### Scenario: Повторная сборка без правок

- **WHEN** карта контекста построена, и после этого ни один файл контекста не менялся
- **THEN** следующая сборка карты не анализирует тексты файлов заново
- **AND** объём, повторы, полезность и антипаттерны в виде «Контроль» те же

#### Scenario: Правка одного файла

- **WHEN** после сборки карты изменён `context.md` одного модуля
- **THEN** следующая сборка анализирует заново только этот файл
- **AND** замечания по этому файлу отражают новый текст

### Requirement: Последняя карта при повторном открытии раздела

Раздел «Контекст» ДОЛЖЕН (SHALL) при повторном открытии в том же окне сразу
показывать последнюю полученную карту — граф, матрицу и вид «Контроль» — и
заменять её новой, когда придёт ответ сервера. Ответ на более ранний запрос
НЕ ДОЛЖЕН заменять карту из ответа на более поздний.

#### Scenario: Возврат в раздел

- **WHEN** пользователь открыл вид «Контроль», перешёл в другой раздел и вернулся
- **THEN** вид «Контроль» с прежними данными виден сразу, без ожидания ответа сервера
- **AND** после ответа сервера показаны свежие данные

#### Scenario: Ответы пришли не по порядку

- **WHEN** файлы изменились дважды подряд, и ответ на первый запрос карты пришёл после ответа на второй
- **THEN** раздел показывает карту из ответа на второй запрос
