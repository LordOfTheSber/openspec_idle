# ide-runtime Specification

## Purpose
Определяет, как OpenSpec IDE запускается на машине разработчика, как находит
каталог OpenSpec и действующую схему процесса, как страница общается с локальным
сервером и какие гарантии безопасности и конфигурации при этом действуют.

## Requirements

### Requirement: Разрешение корня OpenSpec

Система ДОЛЖНА (SHALL) определять корень OpenSpec тем же способом, что и CLI: поиском
ближайшего каталога `openspec/` вверх по дереву от рабочего каталога. Результат
разрешения ДОЛЖЕН быть показан в интерфейсе.

#### Scenario: Запуск из подкаталога проекта

- **WHEN** IDE запущена из вложенного каталога, а `openspec/` находится выше по дереву
- **THEN** рабочим пространством становится каталог, содержащий `openspec/`
- **AND** интерфейс показывает абсолютный путь разрешённого корня

#### Scenario: OpenSpec не инициализирован

- **WHEN** ни в рабочем каталоге, ни выше по дереву нет каталога `openspec/`
- **THEN** интерфейс открывается в состоянии «проект не инициализирован»
- **AND** показывается подсказка с командой `openspec init`
- **AND** разделы навигации, редактора и доски недоступны

#### Scenario: Отсутствует CLI OpenSpec

- **WHEN** исполняемый файл `openspec` не найден ни в проекте, ни в PATH
- **THEN** интерфейс показывает блокирующее уведомление с названием недостающего инструмента
- **AND** предлагается команда установки

### Requirement: Разрешение схемы процесса

Система ДОЛЖНА (SHALL) определять действующую схему для каждого change по данным
`openspec status --change <name> --json` и показывать её имя и источник разрешения.
Ни состав артефактов, ни их порядок, ни имя отслеживаемого артефакта не ДОЛЖНЫ
задаваться в коде IDE.

#### Scenario: Change на схеме по умолчанию

- **WHEN** change заведён без явного указания схемы
- **THEN** действующей считается схема, заданная в настройках проекта
- **AND** её имя показано в интерфейсе change

#### Scenario: Change на собственной схеме

- **WHEN** change заведён по схеме из `openspec/schemas/`
- **THEN** артефакты, их порядок и отслеживаемый артефакт берутся из этой схемы
- **AND** источник разрешения схемы показан как проектный

#### Scenario: Схема change недоступна

- **WHEN** схема, на которую ссылается change, не разрешается
- **THEN** change показывается в состоянии ошибки с именем недостающей схемы
- **AND** остальные changes остаются доступны

### Requirement: Единая обёртка над CLI OpenSpec

Система ДОЛЖНА (SHALL) обращаться к OpenSpec исключительно через один серверный модуль,
запускающий CLI как процесс и разбирающий его JSON-вывод. Ответ обёртки ДОЛЖЕН
включать код возврата, разобранные данные и исходный текст вывода при ошибке
разбора.

#### Scenario: Успешный вызов команды

- **WHEN** серверу требуется список changes
- **THEN** обёртка выполняет `openspec list --json` в корне рабочего пространства
- **AND** возвращает разобранный объект вызывающему коду

#### Scenario: CLI завершился с ошибкой

- **WHEN** вызванная команда CLI возвращает ненулевой код
- **THEN** обёртка возвращает ошибку, содержащую код возврата и текст stderr
- **AND** интерфейс показывает этот текст пользователю без искажения

#### Scenario: Вывод CLI не разбирается как JSON

- **WHEN** команда завершилась успешно, но её вывод не является валидным JSON
- **THEN** обёртка возвращает ошибку разбора с сохранённым исходным выводом
- **AND** не выдаёт частично разобранные данные за результат

### Requirement: Доступ только с локальной машины

Система ДОЛЖНА (SHALL) принимать соединения исключительно с loopback-интерфейса и
ДОЛЖНА отклонять запросы, не подтверждённые токеном сессии, который выдаётся при
запуске. Токен ДОЛЖЕН меняться при каждом запуске сервера.

#### Scenario: Запрос с внешнего интерфейса

- **WHEN** на сервер приходит запрос с адреса, не принадлежащего loopback
- **THEN** соединение отклоняется
- **AND** попытка фиксируется в журнале сервера

#### Scenario: Запрос без токена сессии

- **WHEN** к API приходит запрос без корректного токена сессии
- **THEN** сервер отвечает кодом 401
- **AND** данные рабочего пространства не раскрываются

### Requirement: Операции над файлами ограничены рабочим пространством

Система ДОЛЖНА (SHALL) отклонять любое чтение или запись файла, чей канонический путь
находится вне разрешённого корня рабочего пространства, включая пути, полученные
через символические ссылки и относительные переходы.

#### Scenario: Попытка выйти за пределы корня

- **WHEN** клиент запрашивает файл по пути, содержащему переход выше корня
- **THEN** сервер отвечает ошибкой доступа
- **AND** файл не читается и не изменяется

#### Scenario: Символическая ссылка наружу

- **WHEN** запрошенный путь внутри рабочего пространства является ссылкой на файл вне корня
- **THEN** операция отклоняется после разрешения ссылки

### Requirement: Конфигурация IDE

Система ДОЛЖНА (SHALL) читать настройки из файла `.openspec-ide/config.json` в корне
рабочего пространства, применяя значения по умолчанию для отсутствующих полей.
Секреты ДОЛЖНЫ задаваться только через переменные окружения или поле со ссылкой
на переменную окружения, но не значением в файле.

#### Scenario: Конфигурация отсутствует

- **WHEN** файл конфигурации не существует
- **THEN** IDE запускается на значениях по умолчанию
- **AND** файл создаётся при первом сохранении настроек из интерфейса

#### Scenario: Конфигурация содержит нераспознанные поля

- **WHEN** в файле конфигурации есть поля, неизвестные текущей версии
- **THEN** они сохраняются без изменений при перезаписи файла
- **AND** интерфейс показывает предупреждение со списком таких полей

#### Scenario: Попытка сохранить секрет в файл

- **WHEN** интерфейс отправляет на сохранение настройку, помеченную как секрет, с непустым значением
- **THEN** сервер отклоняет запись
- **AND** сообщает, что значение задаётся переменной окружения
