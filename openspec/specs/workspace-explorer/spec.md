# workspace-explorer Specification

## Purpose
Даёт разработчику навигацию по рабочему пространству OpenSpec: дерево активных
changes, основных спеков, схем процесса и архива, статусы артефактов, поиск по
требованиям и сценариям и автоматическую синхронизацию с изменениями файлов на
диске.

## Requirements

### Requirement: Дерево рабочего пространства

Система ДОЛЖНА (SHALL) показывать дерево из четырёх разделов — активные changes,
основные спеки, схемы процесса и архив — построенное по данным
`openspec list --json`, `openspec list --specs --json`, `openspec schemas --json`
и содержимому каталога архива. У каждого change ДОЛЖНЫ быть видны его артефакты,
у каждого спека — путь capability, у каждой схемы — источник её разрешения.

#### Scenario: Открытие IDE в проекте с changes и спеками

- **WHEN** пользователь открывает IDE в инициализированном проекте
- **THEN** дерево показывает разделы «Изменения», «Спеки», «Процессы» и «Архив»
- **AND** каждый change раскрывается в список артефактов своей схемы
- **AND** каждый спек показан своим путём capability относительно `openspec/specs/`

#### Scenario: Change на собственной схеме

- **WHEN** change заведён по схеме с составом артефактов, отличным от встроенной
- **THEN** в дереве раскрываются именно артефакты этой схемы
- **AND** список артефактов берётся из `openspec status --json`, а не из фиксированного перечня

#### Scenario: Проект без активных changes

- **WHEN** в проекте нет ни одного активного change
- **THEN** раздел «Изменения» показывает пустое состояние
- **AND** предлагается действие создания нового change

#### Scenario: Вложенные capability

- **WHEN** спек расположен по вложенному пути, например `identity/user-auth`
- **THEN** дерево отражает вложенность сегментов пути
- **AND** не схлопывает разные capability с совпадающим последним сегментом

### Requirement: Индикаторы состояния артефактов

Система ДОЛЖНА (SHALL) показывать для каждого артефакта change одно из состояний:
отсутствует, черновик, заполнен, не проходит валидацию. Для артефакта, объявленного
схемой отслеживаемым, ДОЛЖЕН дополнительно отображаться прогресс в виде числа
выполненных пунктов из общего числа.

#### Scenario: Артефакт ещё не создан

- **WHEN** у change отсутствует файл артефакта, предписанный схемой workflow
- **THEN** артефакт показан в состоянии «отсутствует»
- **AND** доступно действие создания артефакта из шаблона

#### Scenario: Артефакт не проходит валидацию

- **WHEN** валидация change сообщает об ошибке, привязанной к файлу артефакта
- **THEN** артефакт помечен состоянием «не проходит валидацию»
- **AND** число ошибок показано рядом с артефактом

#### Scenario: Прогресс по отслеживаемому артефакту

- **WHEN** в отслеживаемом артефакте change отмечено 4 пункта из 11
- **THEN** рядом с этим артефактом отображается «4/11»
- **AND** отмеченной считается задача, у которой в скобках стоит символ `x` в любом регистре и с любыми пробелами

### Requirement: Поиск по рабочему пространству

Система ДОЛЖНА (SHALL) предоставлять поиск по названиям changes, capability и схем,
текстам требований и сценариев. Результат ДОЛЖЕН содержать тип найденного элемента, его
владельца и переход к месту в файле.

#### Scenario: Поиск по тексту требования

- **WHEN** пользователь вводит фрагмент текста требования
- **THEN** выдача содержит все требования, где встречается фрагмент
- **AND** каждый результат показывает, какому спеку или change он принадлежит
- **AND** выбор результата открывает соответствующий файл на нужной строке

#### Scenario: Поиск не дал совпадений

- **WHEN** запрос не совпадает ни с одним элементом
- **THEN** показывается пустое состояние с текстом запроса
- **AND** предлагается снять активные фильтры, если они заданы

#### Scenario: Фильтр по типу элемента

- **WHEN** пользователь ограничивает поиск только сценариями
- **THEN** выдача содержит только сценарии
- **AND** счётчик результатов отражает применённый фильтр

### Requirement: Синхронизация с файловой системой

Система ДОЛЖНА (SHALL) следить за изменениями файлов в каталоге OpenSpec, включая
каталог схем, и обновлять дерево, статусы и открытые представления без ручной
перезагрузки страницы.
Множественные изменения за короткий промежуток ДОЛЖНЫ объединяться в одно
обновление.

#### Scenario: Файл изменён внешним инструментом

- **WHEN** агент или редактор изменяет `proposal.md` открытого change
- **THEN** дерево и статусы обновляются в течение двух секунд
- **AND** представление, показывающее этот файл, отмечает наличие новой версии на диске

#### Scenario: Change создан извне

- **WHEN** в `openspec/changes/` появляется новый каталог change
- **THEN** он появляется в дереве без перезагрузки страницы

#### Scenario: Пакетное изменение множества файлов

- **WHEN** за одну секунду изменяются десятки файлов, например при архивации
- **THEN** интерфейс выполняет одно объединённое обновление
- **AND** не выдаёт отдельное уведомление на каждый файл

#### Scenario: Потеря соединения с сервером

- **WHEN** соединение потока обновлений разрывается
- **THEN** интерфейс показывает признак отключения
- **AND** восстанавливает соединение с нарастающей паузой между попытками
- **AND** после восстановления перечитывает состояние рабочего пространства целиком
