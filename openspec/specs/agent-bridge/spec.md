# agent-bridge Specification

## Purpose
Подключает к IDE языковую модель через GigaCode CLI — единственный разрешённый в
MVP канал к LLM — и делает запуск агента управляемой операцией: с проверяемой
конфигурацией, собранным из инструкций OpenSpec промптом, потоковым выводом,
ограничением бюджета и привязкой результата к пункту плана.

## Requirements

### Requirement: Настройка подключения к GigaCode CLI

Система ДОЛЖНА (SHALL) предоставлять раздел настроек, где задаются путь к исполняемому
файлу GigaCode CLI, модель, режим подтверждения действий, бюджет по времени и по
числу вызовов инструментов, а также имена переменных окружения с учётными
данными. Значения секретов ДОЛЖНЫ передаваться только через переменные
окружения; IDE не сохраняет их в файлы конфигурации и не показывает в интерфейсе.

#### Scenario: Сохранение настроек подключения

- **WHEN** пользователь задаёт путь к исполняемому файлу и модель и сохраняет настройки
- **THEN** значения записываются в конфигурацию рабочего пространства
- **AND** имена переменных окружения сохраняются без их значений

#### Scenario: Учётные данные отсутствуют

- **WHEN** переменная окружения, указанная в настройках, не задана в среде сервера
- **THEN** раздел настроек показывает это как незавершённую настройку
- **AND** запуск агента блокируется с объяснением, какая переменная не задана

#### Scenario: Попытка ввести значение секрета в интерфейсе

- **WHEN** пользователь вводит значение учётных данных в поле настроек
- **THEN** сохранение отклоняется
- **AND** показывается инструкция по заданию переменной окружения

### Requirement: Проверка доступности агента

Система ДОЛЖНА (SHALL) проверять доступность GigaCode CLI перед первым запуском и по
запросу пользователя, определяя наличие исполняемого файла, его версию и
поддержку требуемых режимов вывода. Результат проверки ДОЛЖЕН быть показан в
настройках.

#### Scenario: Успешная проверка

- **WHEN** пользователь запускает проверку подключения при корректных настройках
- **THEN** показываются версия CLI и подтверждение поддержки потокового вывода
- **AND** запуск агента становится доступен

#### Scenario: Исполняемый файл не найден

- **WHEN** по указанному пути нет исполняемого файла и он отсутствует в PATH
- **THEN** проверка завершается неуспешно с указанием проверенных путей
- **AND** запуск агента остаётся заблокированным

#### Scenario: Установленная версия не поддерживает потоковый вывод

- **WHEN** проверка показывает, что CLI не принимает запрошенный формат потокового вывода
- **THEN** IDE переключается на одноразовый формат вывода
- **AND** пользователю сообщается, что вывод будет показан по завершении, а не в реальном времени

### Requirement: Сборка промпта из инструкций OpenSpec

Система ДОЛЖНА (SHALL) формировать промпт запуска из вывода
`openspec instructions <artifact> --change <name> --json` для любого артефакта
схемы этого change, дополняя его контекстом выбранного пункта плана, если запуск
связан с задачей. Перечень артефактов, для которых доступен запуск, ДОЛЖЕН
браться из схемы change, а не из фиксированного списка. Собранный
промпт ДОЛЖЕН быть показан пользователю до запуска и доступен для правки.

#### Scenario: Запуск по артефакту

- **WHEN** пользователь запускает агента для артефакта proposal выбранного change
- **THEN** промпт содержит инструкции схемы для этого артефакта
- **AND** содержит путь, по которому артефакт должен быть создан

#### Scenario: Запуск по артефакту собственной схемы

- **WHEN** пользователь запускает агента для артефакта, объявленного только собственной схемой
- **THEN** промпт содержит инструкцию этого артефакта из схемы
- **AND** запуск не требует изменений в коде IDE

#### Scenario: Артефакт схемы без инструкции

- **WHEN** у артефакта в схеме не заполнена инструкция
- **THEN** запуск для него не предлагается
- **AND** сообщается, что процесс не описал, что делать с этим артефактом

#### Scenario: Запуск по пункту плана

- **WHEN** пользователь запускает агента для конкретной задачи из отслеживаемого артефакта
- **THEN** промпт содержит текст задачи и её критерий приёмки
- **AND** содержит ссылки на артефакты change как контекст

#### Scenario: Правка промпта перед запуском

- **WHEN** пользователь изменяет текст промпта в окне подтверждения
- **THEN** агент запускается с изменённым текстом
- **AND** запущенный текст сохраняется в записи о запуске

#### Scenario: Команда инструкций недоступна

- **WHEN** `openspec instructions` возвращает ошибку
- **THEN** запуск не выполняется
- **AND** пользователю показывается вывод команды

### Requirement: Запуск агента и потоковый вывод

Система ДОЛЖНА (SHALL) запускать GigaCode CLI как отдельный процесс в корне рабочего
пространства в неинтерактивном режиме с потоковым структурированным выводом и
отображать поступающие события в панели агента по мере их получения.
Одновременно ДОЛЖЕН выполняться не более одного запуска на change.

#### Scenario: Отображение хода работы

- **WHEN** агент запущен и присылает события
- **THEN** панель агента показывает сообщения модели и вызовы инструментов по мере поступления
- **AND** видны текущая длительность запуска и израсходованный бюджет

#### Scenario: Успешное завершение

- **WHEN** процесс завершается с нулевым кодом возврата
- **THEN** запуск помечается успешным
- **AND** показываются итоговое сообщение, расход токенов и список затронутых файлов
- **AND** дерево и статусы рабочего пространства обновляются

#### Scenario: Завершение с ошибкой

- **WHEN** процесс завершается ненулевым кодом возврата
- **THEN** запуск помечается неуспешным с этим кодом
- **AND** вывод процесса сохраняется в записи о запуске и доступен пользователю

#### Scenario: Прерывание пользователем

- **WHEN** пользователь останавливает выполняющийся запуск
- **THEN** процессу посылается сигнал завершения
- **AND** если процесс не завершился за отведённое время, он снимается принудительно
- **AND** запуск помечается прерванным, а собранные к этому моменту показатели сохраняются

#### Scenario: Попытка параллельного запуска по тому же change

- **WHEN** пользователь запускает агента по change, где запуск уже выполняется
- **THEN** новый запуск не стартует
- **AND** показывается ссылка на выполняющийся запуск

#### Scenario: Нераспознанное событие в потоке

- **WHEN** в потоке приходит событие неизвестного типа
- **THEN** оно сохраняется в необработанном виде в записи о запуске
- **AND** обработка последующих событий продолжается

### Requirement: Бюджеты запуска

Система ДОЛЖНА (SHALL) ограничивать каждый запуск агента предельным временем работы и
предельным числом вызовов инструментов, передавая эти пределы CLI. Превышение
предела ДОЛЖНО завершать запуск и отмечаться отдельным исходом.

#### Scenario: Превышен предел времени

- **WHEN** запуск работает дольше заданного предела времени
- **THEN** запуск завершается
- **AND** его исход помечается как превышение бюджета времени
- **AND** израсходованные к этому моменту показатели сохраняются

#### Scenario: Превышен предел вызовов инструментов

- **WHEN** число вызовов инструментов достигает заданного предела
- **THEN** запуск завершается с исходом превышения бюджета вызовов

#### Scenario: Пределы не заданы

- **WHEN** в настройках не заданы пределы запуска
- **THEN** применяются значения по умолчанию
- **AND** действующие значения показаны в окне подтверждения запуска

### Requirement: Режим подтверждения действий агента

Система ДОЛЖНА (SHALL) передавать CLI выбранный режим подтверждения действий и по
умолчанию запускать агента в режиме, не разрешающем автоматическое изменение
файлов. Режим с автоматическим подтверждением всех действий ДОЛЖЕН требовать
явного согласия пользователя с предупреждением.

#### Scenario: Режим по умолчанию

- **WHEN** пользователь запускает агента, не меняя режим
- **THEN** используется режим, требующий подтверждения изменений файлов
- **AND** действующий режим показан в окне подтверждения запуска

#### Scenario: Включение полного автоподтверждения

- **WHEN** пользователь выбирает режим автоматического подтверждения всех действий
- **THEN** показывается предупреждение о неконтролируемом изменении файлов
- **AND** режим применяется только после явного согласия

#### Scenario: Режим анализа без изменений

- **WHEN** пользователь выбирает режим анализа
- **THEN** агенту запрещается изменять файлы и запускать команды
- **AND** результат запуска содержит только предложенный план

### Requirement: Журнал запусков и связь с метриками

Система ДОЛЖНА (SHALL) сохранять запись о каждом запуске агента: change, связанный пункт
плана или артефакт, промпт, момент начала и завершения, исход, код возврата,
расход токенов, число вызовов инструментов и список затронутых файлов. Записи
ДОЛЖНЫ быть источником показателей расхода в метриках задач.

#### Scenario: Запуск связан с задачей

- **WHEN** запуск был начат по конкретной задаче и завершился
- **THEN** его показатели учитываются в метриках этой задачи
- **AND** запись доступна из карточки задачи

#### Scenario: Запуск без привязки к задаче

- **WHEN** запуск был начат по артефакту, а не по задаче
- **THEN** его показатели учитываются в сводке change
- **AND** не приписываются ни одной задаче

#### Scenario: Просмотр истории запусков

- **WHEN** пользователь открывает историю запусков change
- **THEN** запуски показаны от новых к старым с исходом и расходом каждого
- **AND** выбор записи открывает сохранённый вывод запуска

#### Scenario: Промпт содержит значения секретов

- **WHEN** в сохраняемой записи о запуске встречается значение переменной окружения, помеченной как секрет
- **THEN** оно заменяется меткой сокрытия перед записью на диск
